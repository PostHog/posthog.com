# AI Observability pocket-guide figures

An opening conversation animation and twelve interactive figures built from the approved Learn-platform Figma **Pocket guide figures** page for the six-chapter guide. `figures.tsx` owns local interactions and inspectors; `fixtures.ts` owns the fictional requests and evidence. Twig UI comes from `@posthog/twig-components/compact-ai-chat`, and PostHog status/code/choice UI reuses package playground primitives.

All state is in memory. No LLM calls, evaluation uploads, bookings, routing to Twig, or real visitor records. The capacity figure recalculates `evaluateCapacity` when the sample changes. The shared evidence toggle chooses between 2 guests, 4 guests, and missing capacity, and a single table row shows requested guests, recorded capacity, and Passed/Failed/N/A immediately; it does not reproduce PostHog’s Test on sample UI or execute arbitrary Hog code. Usage, timing, and event values are illustrative.

The host retains responsibility for Shadow DOM isolation, content placement, reset, and resource links. Container queries control side-by-side/stacked layout; wide figures pair Twig with its inspector. Reset restores the initial prepared state of each figure. The review example keeps human decisions separate from automatic scores.

Preview all six chapters and exercise Send, each request/case selection, both prompt versions, all three capacity samples, operation durations, opening/saving, funnel steps, and Reset. Inspect the completed human review alongside the answer.

Trace inspectors use one operation tree and Messages/Raw tabs. Earlier messages and captured system context are displayed directly, without caret disclosures. The requested group size stays in the visitor message; catalog capacity stays in captured system content. Search spans expose their own input/output separately from generation messages. Other inspectors retain their evaluation, usage, or activity tables with a single contextual title.

The opening `AioConversationPreview` uses the exact three-message flow checked on Twig. Pending replies show Twig’s existing “Twig is typing…” status. Each reply includes the current stay card, replacing the previous recommendation as Twig does. Its single autoplay pass starts when 75% of the chat is visible. Each turn types the visitor’s request into the existing composer, holds the completed draft briefly, sends it into the history, shows Twig’s typing state, and reveals the reply. Replies remain visible for five seconds before composing the next request. It uses the standard figure Reset button. Reduced-motion preferences show the full transcript immediately. The chat fills the figure width with a 320px viewport, persistent composer, and scrollable history. Playback composers are read-only, and Send is non-interactive; the host controls the sequence.

`AioSupportConversationPreview` introduces online evaluations with the existing heating complaint and incorrect refund refusal from Twig’s support scenario. It reuses the opening playback, typing state, visibility gate, reduced-motion behavior, and Reset. Support figures use the actual package `SupportAgent` in compact mode, with its own content-sized layout and support composer, rather than retitling the trip-planner mockup. No evaluation results or extra controls appear in this opening exchange.

The online evaluation table starts collapsed. Each full row toggles its evidence; selecting another row closes the previous one. Code exposes the exact Hog rule and evaluated response, sentiment exposes the evaluated visitor message, and the policy judge exposes its criterion, captured request/policy, and answer. Each evaluation row has one disclosure level: its evidence is displayed directly when expanded. Keep teaching explanations in chapter prose; inspector disclosures contain the underlying rule, configuration, and captured content. The table reuses the lab’s plus/minus disclosures and result colors, with column headings available to assistive technology without repeating the visible title. Reset clears the conversation and expanded result.

Online evaluations and saved-case results share the same `InspectionResults` table: one contextual title, no visible repeated column label, and one plus/minus disclosure per row. Saved cases reveal their request, expected answer, and actual answer directly. Opening a saved case also selects that conversation in the adjacent support chat; collapsing it retains the selected conversation. Offline prompt comparisons reuse the same saved-case inspector.

The Prompts chapter has two local examples. `AioPromptVersionFigure` starts with the application pinned to v1; selecting v2 resets the prepared conversation, and Send reveals the corresponding answer, captured prompt metadata, and system instructions. `AioPromptTemplateFigure` substitutes one or two days into the same cancellation template. Both use existing Twig, evidence-choice, and code-block components and the standard Reset. They do not fetch or publish managed prompts. These concepts are preview-first and have not been added to Figma.

The cost and outcome figures follow the same minimal inspector pattern. Request choices update both the chat and usage; catalog context is displayed directly. Timeline bars are static, with no selection, hover treatment, or click behavior. Timing and usage disclaimers appear as small, italic notes aligned to the bottom right. Opening and saving in Twig drives the activity log directly; event rows reuse `InspectionResults` to reveal identifiers only on demand. The illustrative seven-day funnel shows 120 visitors opening a recommendation and 48 saving it within 30 minutes (40% conversion). Selecting a step reveals one matching example event, explicitly distinguished from the aggregate count. Evidence rows use white by default and the same yellow highlight for selected or emphasized data; hover does not introduce another background state. Human review shows a completed engineer assessment and a concrete improvement note, rather than asking the reader to fill out a form. It distinguishes avoiding an undersized recommendation from helping the visitor find an alternative. These refinements are preview-first.

All guide evidence toggles reuse `EvidenceTabs` with the same request-selector treatment, including Messages/Raw inside generation panels. Do not add generation-specific type, padding, or border variants.

Evaluation evidence labels identify who produced the content: **Evaluated message** is the visitor’s message; **Evaluated response** is the AI feature’s reply. Use these labels consistently across figures rather than calling an AI response an evaluated message or answer.

Prompt comparison figures show their prompt instructions directly, without a System disclosure. The offline comparison keeps the selected instructions visible before sending and above the resulting scores, so the changed prompt is distinct from an application-code fix.

**Default for guide figures: show captured evidence directly.** Do not hide messages, context, inputs, outputs, or instructions behind caret disclosures. Only add a disclosure when Sarah explicitly requests that specific interaction. Evaluation and saved-case row expansions were explicitly requested; never nest another disclosure inside them.
