What better way to document MDX than with MDX?

## Rationale

There were a few moving parts involved with setting up MDX so it might make sense to have them written down.

## What's MDX?

Not in scope here - but it's essentially React in Markdown.

## How do we make it work?

### Page creation

Website pages are automatically created for all MDX files. Astro content collections load the files in `contents/` (the collections are in `src/content.config.ts`, and their folders and schemas are in `src/content/schemas.ts`). For each content type, a route file in `src/pages/` uses `getStaticPaths` to create a page for each entry. Slugs are automatically generated based on the file path, and the design template for each page is determined based on the folder the file resides in.

### Design templates

The main templates (in `src/templates/`) are:

-   **Handbook / Docs** - Files located in `contents/handbook` and `contents/docs`
-   **Blog post** - Files located in `contents/blog`, `contents/customers`, and the other post folders
-   **Blog category** - Automatically created based on categories used in blog posts
-   **Plain** - All other files located in `contents`

Each route builds the props for its template from the collection entry, with a builder in `src/lib/content/` (for example, `docs.ts` and `handbook.ts`).

The props contain everything we need, from frontmatter to the content key of the body, and we use the component
`MDXRenderer` (`src/components/MDXRenderer`) to render the body, and `MDXProvider` to pass some context that is available to all MDX pages.

In this case, we pass references to components that can then be used without imports directly on MDX pages, like this hedgehog:

<BasicHedgehogImage />
<br />

Because of the components passed to `MDXProvider`, I can include this hedgehog by just adding `<BasicHedgehogImage />` in my
MDX file - no import needed.

However, if I want to include something from a module, I can also do so. Here's how one would insert a Transition component from Headless UI:

```mdx
import { Transition } from '@headlessui/react'

## Some Markdown

<Transition>{/* ... */}</Transition>
```

> Currently, the components in `src/mdxGlobalComponents.js` are available automatically. If you need a reference for which components you should be using in your MDX, check out our [MDX components handbook page](/handbook/engineering/posthog-com/markdown).

### Global components

`src/mdxGlobalComponents.js` exports `shortcodes`, the components that every MDX page can use without an import. The templates pass these components to `MDXProvider`, making them available everywhere. To make a component global, import it in this file and add it to `shortcodes`.

Doing globally available imports this way was important for 3 main reasons:

-   Relative imports in MDX can be annoying
-   Keeping MDX files clean
-   Making MDX a nice experience even for less technical people that update our website
