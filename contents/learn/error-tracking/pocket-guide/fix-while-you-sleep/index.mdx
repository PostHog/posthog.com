# Check whether the fix held

This creates a <Term name="scout" />, which is a scheduled agent that queries your PostHog events and files a <Term name="report" /> in your <Term name="inbox" /> when it finds something.

This one checks each fix once it has had time to reach users, and reports the fixes that didn't hold. An <Term name="issue" /> can keep firing after a fix while some clients still run the old code, so the scout waits and compares rates before it reports.

## What the scout looks at

Yesterday at `10:30` you merged a fix for a checkout `TypeError`. Today the issue still fires at about the rate it did before the merge, so the scout reports it <SeeFig n={1} />. When the rate fell hard and keeps falling, the fix is still rolling out, and the scout checks again later.

## The report in your inbox

A fix that didn't hold becomes a new <Term name="report" /> in your <Term name="inbox" />, linked to the original so you can see what was already tried <SeeFig n={2} />. Click **Ask AI** on the report to ask who else is affected, whether the problem is new, or what to do next. See [reports](/docs/self-driving/reports#ask-ai-about-a-report).

## The scout itself

PostHog maintains this scout, listed as **Inbox validation** in your scouts, and you can read [its skill file on GitHub](https://github.com/PostHog/posthog/blob/master/products/signals/skills/signals-scout-inbox-validation/SKILL.md). It waits 24 hours after the merge for a server fix, and 72 hours or more for web and mobile. Then it compares the issue's exceptions and affected users with the same window before the merge. It also checks your overall traffic, so a quiet weekend doesn't pass for a fix. For a fix no report links to, the [PR follow-up](/learn/error-tracking/pocket-guide/what-changed) scout runs the same check.

## The schedule it runs on

The scout runs every 24 hours by default, but stays quiet unless something needs your attention. You can change the schedule in its **Settings**.

## Add this to your scout troop

PostHog ships this scout turned on, and you can turn it off for each project. It checks a fix once exceptions reach PostHog and the fix's report resolves, either when its linked pull request merges or when you resolve it yourself.
