## Unresolved stack traces

A <Term name="stack trace" /> shows the exact line of code that caused the exception. Without a <Term name="source map" />, PostHog can't map the frames back to your code, so they show up as **unresolved** <SeeFig n={1} />.

## Source map uploads

Give PostHog a source map and a trace like this points back to your source code <SeeFig n={2} />. PostHog can get your maps three ways:

| Option | Trade-off |
| --- | --- |
| Upload in CI | The default. Your source stays private, and each build uploads its own maps. |
| Host them publicly | No upload step, but anyone can read your source. |
| Embed them in the bundle | No upload, but your users download larger files and can read your source. |

Link each upload to a [release](/docs/error-tracking/releases). PostHog then shows the version and commit on every trace. With a [GitHub or GitLab integration](/docs/error-tracking/integrations), it also links each frame to the file and line in your repository.

The Wizard's Error Tracking setup already adds uploads where your platform needs them. To add them to an existing setup:

<Setup subcommand="upload-source-maps" />

To set it up yourself, follow [Upload source maps](/docs/error-tracking/upload-source-maps) for your framework.

## Breadcrumbs

Breadcrumbs, which PostHog calls exception steps, hold context that only matters if something breaks. Call `addExceptionStep` at checkpoints like a retry or a fallback path. The SDK attaches the steps to the next exception, and they show up in the issue's **Timeline** tab <SeeFig n={3} />.

If no exception happens, the SDK discards the steps, so successful runs cost nothing.

Pick where context goes by when you'll need it:

| Record it as | When |
| --- | --- |
| An exception step | It only matters if this run fails |
| A log | You want it kept for every run, failed or not |
| A property on the exception | You want to filter, group, assign, or count issues by it |
| An event | You want to count the action on its own |

Steps work in the web, React Native, iOS, Android, and Flutter SDKs.

## Symbol sets

PostHog lists every source map and symbol file it has as a symbol set, along with uploads that failed. A missing one shows why it failed, and you can upload the file from the same list. The upload only resolves exceptions captured after it.
