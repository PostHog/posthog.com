# Error Tracking 101

Your code throws an exception when something goes wrong, such as a `TypeError`. A stack trace tells you what led up to the exception. Error Tracking captures these exceptions and stack traces as queryable PostHog events.

These exception events sit alongside your other PostHog events. That lets you answer questions you can't with just a stack trace:

- [Which customers are impacted?](/learn/error-tracking/pocket-guide/measure-impact#a-customers-errors)
- [Does it impact conversion and retention?](/learn/error-tracking/pocket-guide/measure-impact#churn)
- [Can this error be tied to loss in revenue?](/learn/error-tracking/pocket-guide/measure-impact#revenue-at-risk)
- [Were they part of any feature flag or experiment rollouts?](/learn/error-tracking/pocket-guide/measure-impact#experiments)
- [What's shown on the user's page before and after the exception is thrown?](/learn/error-tracking/pocket-guide/measure-impact#session-replays)

## Exceptions and issues

Like other PostHog tools, each instance of an <Term name="exception" /> is captured as a `$exception` <Term name="event" />. Similar exceptions are aggregated into <Term name="issue">issues</Term> <SeeFig n={1} />. Those issues are the base unit of work: you diagnose, triage, assign, and fix them, not individual exceptions.

## By the end of this pocket guide

Most production apps have more exceptions than your team can fix. And not all of them matter. That one mysterious React error has been firing for months and no-one notices anyway. Error Tracking helps you find the highest-impact issues, report them, and automate the fixes. We'll introduce each step throughout this guide:

- **Capture** – Group exceptions into issues. Make stack traces readable. Keep noise out.
- **Query** – Query exceptions as events with HogQL and MCP. Join them with revenue, funnels, and experiments to measure impact.
- **Automate** – Route each issue to the team that owns it. Alert on spikes and regressions.
- **Self-drive** – Scouts watch for failure patterns and measure their impact. They send reports to your inbox. Agents open pull requests to fix them.

The end result is a report like this one, with a pull request ready to review <SeeFig n={2} />.

## Install and turn it on

Run the Error Tracking Wizard. It installs PostHog if your app doesn't have it, turns on exception capture, and sets up source map uploads where your platform needs them. Or [install it yourself](/docs/error-tracking/installation).

<Setup />

To capture uncaught exceptions automatically, switch on [exception autocapture](https://app.posthog.com/error_tracking/configuration#selectedSetting=error-tracking-exception-autocapture) in your project settings. An autocapture setting in your SDK config overrides the project switch, and exceptions you send yourself with `captureException` don't need it. [The next page](/learn/error-tracking/pocket-guide/group-exceptions) covers how PostHog groups exceptions into issues.
