# Exceptions as events

Exceptions are events, so you can analyze them like any other event in PostHog. You can find the errors that make people leave, compare error rates between flag variants, or see which paying accounts hit an error.

For example, this chart finds the new errors that put the most MRR at risk <SeeFig n={1} />.

<Callout title="Prerequisites">

- Group analytics to relate users to the company they belong to. [Configure group analytics](/docs/product-analytics/group-analytics#set-up-group-analytics)
- An `mrr` property from a warehouse connection with [Stripe](/docs/data-pipelines/sources/stripe). [Connect your payment data](/docs/data-warehouse/warehouse-properties#set-up-a-warehouse-property)

</Callout>

This chart joins exceptions to accounts on `$groups` in [HogQL](/docs/data-warehouse/sql):

| Source | What it adds |
| --- | --- |
| `$exception` | The accounts each issue hit |
| `groups` | What each account pays, from its `mrr` property |

To build a version of this for your organization, give your agent the skill <SeeFig n={2} />. For more examples, see [Measure impact with your other data](/learn/error-tracking/pocket-guide/measure-impact).

## What an exception looks like

Everything in PostHog is an event, and exceptions are no different. An exception carries the same properties as your other events, like the person, session, and account, as well as additional properties that describe the error <SeeFig n={3} />.

PostHog keeps your events in one [context warehouse](/docs/self-driving/context) with persons, groups, sessions, and the tables you [sync](/docs/data-pipelines/sources) from tools like [Stripe](/docs/data-pipelines/sources/stripe) or [Zendesk](/docs/data-pipelines/sources/zendesk). [HogQL](/docs/data-warehouse/sql) queries all of it together, so anything you put in PostHog can be joined to your exceptions.

## Joining exceptions to other PostHog events

Filter, break down, or join exceptions on these properties:

| To answer | Use | Set up |
| --- | --- | --- |
| Which error is it? | The message in `$exception_list`, or the issue in `$exception_issue_id` | The message is set automatically by every SDK. PostHog assigns the issue |
| Which page did it happen on? | `$current_url` or `$pathname` | Set automatically by the web SDK |
| Is it a crash? | `$exception_level` set to `fatal` | Set automatically for crashes by the Android, iOS, and React Native SDKs |
| Which SDK or app sent it? | `$lib` or `$app_namespace` | `$lib` is set automatically by every SDK, and `$app_namespace` by the mobile SDKs |
| Who hit it? | `distinct_id` and person properties, like email | [Identify your users](/docs/getting-started/identify-users) |
| Which account hit it, and what does it pay? | `$groups` and the account's group properties | [Set up group analytics](/docs/product-analytics/group-analytics) |
| Which flag variant did they see? | `$feature/<flag-key>` | [Send flags with your events](/docs/feature-flags/adding-feature-flag-code), on the server too |
| Which session was it in, and what's in its replay? | `$session_id` | Set automatically by the web and mobile SDKs. On the server, [pass the session ID](/docs/data/sessions#server-sdks-and-sessions) |
| Which LLM trace was it in? | `$ai_trace_id` | [Link exceptions to traces](/docs/ai-observability/link-error-tracking) |
| Which part of your product threw it? | Your own properties | [Add them at capture](/docs/error-tracking/capture#customizing-exception-properties) |
| What do your other tools say, like support tickets or billing? | Any property above, joined to a synced table | [Sync a source](/docs/data-pipelines/sources) |

[Issues and exceptions](/docs/error-tracking/issues-and-exceptions) lists every property PostHog sets.

## PostHog MCP

The [PostHog MCP](/docs/model-context-protocol) lets your agents write queries for you. Add the MCP with one command:

<Setup subcommand="mcp add" />

To set it up by hand, follow the guide for [Claude Code](/docs/model-context-protocol/claude-code), [Cursor](/docs/model-context-protocol/cursor), or [Codex](/docs/model-context-protocol/codex).

You can query exceptions using these MCP tools:

| Tool | What your agent uses it for |
| --- | --- |
| `query-error-tracking-issues-list` | Listing, filtering, and sorting issues |
| `query-error-tracking-issue` | One issue's details and impact, including the pages and browsers it happens on |
| `query-error-tracking-issue-events` | Sample exceptions, with stack traces and session IDs |
| `query-session-recordings-list` | The session replays for those session IDs |
| `execute-sql` | Joining exceptions to people, accounts, sessions, and synced sources |
| `read-data-schema` | Checking which events and properties exist before it queries |
| `metric-list` | Finding governed metrics, like MRR, in your [semantic layer](/docs/semantic-layer) |
