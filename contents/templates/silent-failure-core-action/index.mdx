showTitle: true
badge: beta
filters:
  type:
    - self-driving
  maintainer: official
premise: >-
  Every product has one action that matters more than the rest: checkout, publish, send, or deploy. When
  it fails loudly, you hear about it. This scout watches for the failure you never hear about – the one where nobody saw an error or filed a ticket.
discriminator:
  writesToInbox: >-
    Fewer of the people who start your core action are finishing it than usual.
  writesNothing: >-
    Fewer people started it too, so the same share still finish. That's just normal traffic.
  why: >-
    A drop in finishes might just mean fewer people showed up. A drop in the share can't be
    explained that way, which is what lets the scout decide on its own.
watches:
  - name: Your product events
    detail: How many people start your core action and how many finish, compared with the last two weeks.
  - name: Error Tracking
    detail: The failures that show up as errors – including the ones your code catches, so the user never sees them.
  - name: Session Replay
    detail: The failures that never become errors – recordings of people who started, got stuck, and gave up.
  - name: Your codebase
    detail: Your deploys, so a drop can be matched to the change that caused it instead of just a time of day.
requires:
  - label: >-
      A core action with a start and finish event, named explicitly when you add the scout –
      it can't guess which flow is the whole point of your product
    level: required
  - label: Error Tracking instrumented, including the paths where exceptions are caught
    level: required
  - label: Your codebase connected via GitHub, to correlate a break against deploys
    level: recommended
  - label: Session Replay, for failures that never reach your server at all
    level: recommended
  - label: >-
      Intermediate events inside the flow, if you have them – they're what turns "it broke" into
      "it broke at the payment step"
    level: optional
category: Product Analytics
schedule: Daily
report:
  title: Publish completion rate down 31 points while attempts hold steady
  source: Scout · core action funnel
  receivedAgo: 2h
  affected: ~1,240 publishes/day failing silently
  body: >-
    Since the 14:02 deploy, publish attempts are flat at ~4,000/day but the completion rate
    fell from 92% to 61%. The drop is uniform across source, device, and geo, so it isn't a
    traffic-mix change, and the `publish_completed` event is still firing normally elsewhere.


    Error Tracking shows a new handled timeout on the publish path, caught by the retry wrapper
    and never rethrown – so no error page rendered and no alert fired. Session Replay matches: users
    click Publish, watch the spinner, and leave after ~8 seconds.
  suggestedAction: >-
    Surface the failure to the user instead of retrying silently. The timeout itself is the
    root cause and a separate follow-up – this PR is about making it visible.
  actionNote: An agent opens the pull request – you review and merge.
