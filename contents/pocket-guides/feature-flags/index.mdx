# Feature Flags

A <Term name="feature flag">feature flag</Term> separates deploying code from releasing it. You merge the change turned off, then decide from PostHog who gets it: your team first, then 5% of users, then everyone. If errors climb at 5%, you flip the flag off, and nobody waits on a revert.

## Where to start

Jump to the page for the job in front of you:

- Letting a few people try a change first: [Rollouts](/pocket-guides/feature-flags/roll-out-gradually)
- Something broke and has to go dark now: [The off switch](/pocket-guides/feature-flags/off-switch)
- Checking a flag on the server and in the browser: [Server and client](/pocket-guides/feature-flags/server-and-client)
- Changing copy or limits without a deploy: [Payloads](/pocket-guides/feature-flags/payloads)
- Testing whether a change is better: [Experiments](/pocket-guides/feature-flags/flag-to-experiment)
- Deleting flags that finished their job: [Cleaning up](/pocket-guides/feature-flags/cleanup)

New to flags? Start with [Feature Flags 101](/pocket-guides/feature-flags/101).
