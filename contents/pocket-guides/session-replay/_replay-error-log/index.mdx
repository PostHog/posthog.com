# Replay, error, log

## Why the replay isn't enough on its own

Session Replay → Error Tracking: Seeing something break visually isn't enough. They want structured, queryable errors tied to users and releases, surfaced on the ticket. Error Tracking makes debugging systematic instead of ad hoc.

## Where the server side shows up

Inspect structured backend logs connected to the same user session. When replay and error tracking show what happened on the frontend, logs show what happened on the server, and a log line [links straight back to the replay](/docs/logs/link-session-replay) it came from.

## The chain, end to end

Click from an NPS score to a session replay to an error to a log line to the conversation.
