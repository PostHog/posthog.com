# WHAT TO WRITE
#
# ## What a signal is
#   A signal is a finding with its evidence attached, not a notification. Related signals group
#   into one report in the inbox, so one problem arrives once rather than three times.
#   Contrast with the alerts page before it: an alert tells you a threshold moved and stops.
#   Source: /docs/self-driving/signals, /docs/self-driving/reports.
#
# ## Turning error tracking on as a source
#   It is a toggle, not a build. Once on, every new exception, reopened issue, and volume spike
#   is processed continuously as it happens. Nothing is skipped because something weighed it.
#   Source: /docs/self-driving/inbox/sources line 37 and line 132.
#
# ## Exhaustive, not selective
#   The trade this page exists to explain, quoting the docs' own table: a source is exhaustive
#   and continuous with predictable behaviour; a scout is selective, scheduled, and uses
#   judgement. "Neither is the upgrade from the other, and most projects run both."
#   Say plainly what a source will NOT do: rank, cluster, weigh, or stay quiet on a busy day.
#   Source: /docs/self-driving/signals lines 41-55.
#
# ## What lands in the inbox
#   Signals from several sources describing one problem are deduplicated and grouped into a
#   single report. Worth showing the report card here – reuse AnatomyFigure with an inline
#   report rather than inventing a new figure.
#   Source: /docs/self-driving/reports.
#
