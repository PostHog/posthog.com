# Find the change that caused it

The deploy that shipped the bug is on the same event as the bug. A <Term name="release" /> narrows it to a build. A <Term name="feature flag" /> variant narrows it to a code path. Neither needs a second tool.

## Line it up against a release

Every exception carries the release it was thrown in. The release is recorded when you upload <Term name="source map">source maps</Term>, so the one upload that makes a <Term name="stack trace" /> readable also makes it attributable.

Compare an issue across releases and "started at 14:02" becomes "started in 1.4.2" <SeeFig n={1} />. With a GitHub or GitLab integration, each frame links to the file and commit that produced it.

<Prompt>
Take my top error tracking issue from the last 7 days and break its exceptions down by release. Tell me which release it first appeared in and whether it exists in the one before.
</Prompt>

## Split it by feature flag variant

The flags a person had are ordinary properties on the exception, so an issue breaks down by variant like it breaks down by browser.

A bug that only exists in the test variant is a flag you can turn off now. That is faster than any fix, and it holds the line while the fix is written.

<Prompt>
Break my top error tracking issue down by feature flag variant and tell me if it concentrates in one variant.
</Prompt>

## New, regressed, or always there

These are three different findings, and the issue list marks them differently.

- **New** arrived with a release. The release comparison above tells you which.
- **Regressed** was resolved and came back. PostHog reopens a resolved issue on its own when the error recurs, and that deserves more attention than new, because someone already believed it was done.
- **Always there** is the background you have stopped seeing. It is not urgent, and it is the noise the next page teaches you to keep out of your alerts.

<Prompt>
List my error tracking issues from the last 7 days in three groups: new since the latest release, reopened after being resolved, and older than 30 days.
</Prompt>
