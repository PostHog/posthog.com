# Query exceptions with MCP

The [PostHog MCP server](/docs/model-context-protocol) connects your coding agent to your PostHog project. Your agent can query exceptions alongside your events, people, accounts, sessions, replays, and logs. It can also join them to the [sources](/docs/data-warehouse/sources) you sync into the data warehouse, like Stripe or Postgres.

Ask about an error in plain language, and your agent writes and runs queries like the ones in [Exceptions as events](/pocket-guides/error-tracking/exceptions-as-events) for you.

## Install the MCP server

The wizard adds the PostHog MCP server to your agent:

<Setup subcommand="mcp add" />

To set it up by hand, follow the guide for [Claude Code](/docs/model-context-protocol/claude-code), [Cursor](/docs/model-context-protocol/cursor), or [Codex](/docs/model-context-protocol/codex).

## Know the tools

Your agent chooses from these tools when you ask about exceptions. The first three belong to Error Tracking, and the rest reach your other PostHog data:

| Tool | What your agent uses it for |
| --- | --- |
| `query-error-tracking-issues-list` | Listing, filtering, and sorting issues |
| `query-error-tracking-issue` | One issue's details and impact, including the pages and browsers it happens on |
| `query-error-tracking-issue-events` | Sample exceptions, with stack traces and session IDs |
| `query-session-recordings-list` | The session replays for those session IDs |
| `execute-sql` | Joining exceptions to people, accounts, sessions, and synced sources |
| `read-data-schema` | Checking which events and properties exist before it queries |
| `metric-list` | Finding governed metrics, like MRR, in your [semantic layer](/docs/semantic-layer) |

For revenue and other business numbers, your agent looks for an approved metric first. When none fits, it writes its own query and labels the answer noncanonical.
