# WHAT TO WRITE
#
# ## What a scout adds that a source cannot
#   The trade, stated once and not repeated from the previous page: a source is exhaustive and
#   continuous, a scout is selective and scheduled. A scout can rank, cluster, weigh, and stay
#   quiet on a busy day – a source processes everything and holds no opinion.
#   Source: /docs/self-driving/signals lines 41-55.
#
# ## The scouts that already watch errors
#   Do not invent. These ship: error-tracking (spikes, stuck loops, fingerprint clusters,
#   triaged by how many users they hit), apm (new errors per service), logs (new error message
#   patterns), csp-violations. Name them and say what each holds.
#   Source: /docs/self-driving/scout-examples lines 30-49.
#
# ## Writing one for your own question
#   The canonical error scout stops at people. Point at the errors-by-account-value scout in
#   vol. 1 as the worked example of extending it, rather than teaching scout authoring here.
#   Source: /pocket-guides/self-driving/errors-your-best-accounts-hit.
#
# ## From report to pull request
#   An agent gets the report and its evidence as context, opens the PR, and you review it like
#   any other. Nothing merges without you. Reports are free, pull requests are $15 each with
#   the first three a month free. Source: /docs/self-driving/anatomy-of-a-pr, /docs/self-driving/pricing.
#
