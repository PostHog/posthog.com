# WHAT TO WRITE
#
# ## Three things worth alerting on
#   Trigger events are issue created, issue reopened, and a volume spike. Alerting on every new
#   issue trains people to ignore the channel; the other two are the ones that earn a page.
#   Source: /docs/error-tracking/alerts.
#
# ## Spikes against a baseline
#   A threshold on a raw count fires whenever traffic moves. Spike detection compares against
#   the issue's own recent volume, so it fires when the shape changes rather than when Monday
#   happens. Source: /docs/error-tracking/spikes.
#
# ## Assignment rules
#   Route on the way in rather than triaging later. Rules run during ingestion, so they can
#   match on the unminified stack trace – which is what lets you route by source file to the
#   team that owns it. Test before saving, same as grouping rules.
#   Source: /docs/error-tracking/assigning-issues line 38 onward.
#
# ## Out to your tracker
#   GitHub, GitLab, Linear, Jira. The issue carries a link back, so whoever picks it up sees
#   the exception rather than your description of it. Source: /docs/error-tracking/integrations.
