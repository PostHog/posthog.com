To build LLM-powered apps, developers need to know how users are using their app. 

LLM observability tools help them do this by capturing LLM provider requests and generations, then visualizing and aggregating them. This helps developers monitor, debug, and improve their apps. 

To help you pick the best of these tools, we put together this list. All of the following products:

1. Integrate with popular LLM providers like OpenAI, Anthropic, and Vercel AI SDK to capture generations.
2. Let you view individual generations and traces from your app.
3. Calculate and display an aggregated metrics dashboard with cost, latency, and more.
4. Are open source and self-hostable.
5. Have a free hosted version (minus one of them…)

**PostHog** is the pick if you want LLM traces tied to the rest of your product data. **Langfuse** is the most complete dedicated platform. **Opik** suits teams that train models as well as build on them. **OpenLLMetry** is instrumentation rather than a full platform, and fits best if you already run OpenTelemetry. **Phoenix** is free to self-host with no feature gates, though its license is source-available.

- **Who it's for:** teams that want [LLM traces](/docs/ai-observability/traces) tied to the same users as their [product analytics](/docs/product-analytics), [session replays](/docs/session-replay), [experiments](/docs/experiments), [errors](/docs/error-tracking), and more, and want their agents to be able to [query all of it](/docs/model-context-protocol).
- **Who it isn't for:** teams that need a built-in LLM gateway or proxy, or want to self-host at scale.
- **License:** MIT
- [PostHog on GitHub](https://github.com/PostHog/posthog)

[PostHog](/) is your product's context layer. It combines [AI observability](/ai-observability) with [product](/product-analytics) and [web analytics](/web-analytics), [session replay](/session-replay), [feature flags](/feature-flags), [experiments](/experiments), [error tracking](/error-tracking), [logs](/logs), and [surveys](/surveys), and a [data warehouse](/warehouse) and [CDP](/cdp) connect it all to the business data you keep elsewhere.

Its LLM observability product, [AI observability](/ai-observability), captures details of generations, provides an aggregated metrics dashboard, and more. It has [integrations](/docs/ai-observability/installation) for more than 40 providers, frameworks, and gateways, including OpenAI, Anthropic, LangChain, and the Vercel AI SDK, plus OpenTelemetry, and it rolls everything up into an aggregated metrics dashboard.

#### What does PostHog AI observability include?
 
- **Tracing and costs:** Captures every [generation](/docs/ai-observability/generations) and [trace](/docs/ai-observability/traces) with its tokens, cost, latency, and errors, and rolls them up in a [dashboard](/docs/ai-observability/dashboard).
- **Product context:** LLM data sits alongside your product and business data, so you can query it with [SQL](/docs/data-warehouse/sql), watch [session replays](/docs/session-replay) of AI interactions, and [A/B test prompts](/tutorials/llm-ab-tests).
- **[Prompt management](/docs/prompt-management):** Create and version prompts directly in PostHog. Prompts are fetched at runtime via the SDK with caching and fallback support, so you can update them without code deploys. Non-engineers can iterate on prompts from the UI, and every change creates an immutable version you can compare, restore, or link to traces to see which prompt versions drive which outputs.
- **[Evaluations](/docs/ai-evals):** Score production generations with LLM-as-a-judge, code-based checks, or sentiment analysis, and queue traces for [human review](/docs/ai-observability/trace-reviews). This tracks quality over time – not just whether API calls succeed, but [whether they're actually good](/blog/stop-ai-slop).
- **Agent access:** The [MCP server](/docs/ai-observability/surfaces/mcp) lets Claude Code, Cursor, or Codex check costs, errors, and traces from your editor, and you can ask the same questions from [Slack](/slack) or the [CLI](/docs/cli).

#### How much does PostHog AI observability cost?
 
PostHog Cloud is free to start: 100k AI observability events every month, with unlimited seats and 30-day retention. Beyond this, pricing is usage-based and [totally transparent](/pricing). 

You can also [self-host PostHog](/docs/self-host) for free under the MIT license, though we recommend Cloud.

## 2. Langfuse

- **Who it's for:** teams that want the a complete and dedicated LLM engineering platform, self-hosted or managed.
- **Who it isn't for:** teams that want product analytics, session replay, or experiments in the same tool, or more than two users on the free cloud plan.
- **License:** MIT (enterprise features are licensed separately)
- [Langfuse on GitHub](https://github.com/langfuse/langfuse)

![Langfuse dashboard](https://res.cloudinary.com/dmukukwp6/image/upload/langfuse_6db7c2d9e7.png)

[Langfuse](/docs/ai-observability/integrations/langfuse-posthog) (recently acquired by ClickHouse) is an open source LLM engineering platform. It provides LLM call tracking and tracing, prompt management, evaluation, datasets, and more. These give LLM app developers tools they need for their entire workflow.

ClickHouse acquired Langfuse in January 2026. Both companies say the core stays MIT-licensed and Langfuse Cloud keeps running as a standalone service. We compare it with PostHog in detail in [PostHog vs Langfuse](/compare/posthog-vs-langfuse).

#### What does Langfuse include?
 
- **Tracing:** LLM call tracking and tracing with session tracking, native SDKs for Python and JavaScript, and integrations with most LLM providers and agent frameworks.
- **OpenTelemetry:** Can act as an OpenTelemetry backend, so any OTel-instrumented app can send it traces.
- **Evaluation:** Scores, datasets, and annotation queues for human review, plus prompt management and a playground.
- **Breadth:** Langfuse lists more than 80 features, from session tracking to batch exports to SOC 2 reports.
- **AI and agent tools:** An MCP server with read and write tools, an in-app assistant called Halo, and an AI gateway in public beta.

#### How much does Langfuse cost?
 
Langfuse can be self-hosted for free, though a few features, like audit logs and project-level roles, need an enterprise license key. 

If you prefer a managed service, Langfuse Cloud is free to use up to 50k units per month and 2 users, but this only includes 30 days of data access. 

Pricing beyond this starts at $29/month for 100k units, unlimited users, and 90 days of data access. Additional usage starts at $8 per 100k units and decreases with volume, down to $6 per 100k units above 50M units.

## 3. Opik

- **Who it's for:** teams that train or fine-tune their own models as well as build LLM apps, and want a platform that's Apache 2.0 throughout.
- **Who it isn't for:** teams with high trace volume that want to stay on a free cloud plan, which is capped at 25k spans a month.
- **License:** Apache 2.0
- [Opik on GitHub](https://github.com/comet-ml/opik)

![Opik dashboard](https://res.cloudinary.com/dmukukwp6/image/upload/opik_7fcc9b0840.png)

**Opik** is an open source platform for evaluating, testing, and monitoring LLM apps. It provides tracing, annotations, a prompt and model playground, evaluation, and more. It's built by Comet, an end-to-end model evaluation platform for developers.

In 2026, Opik 2.0 shifted its focus toward agents, adding test suites and an agent playground, and Comet later added cost tracking for coding agents like Claude Code and Codex.

#### What does Opik include?
 
- **Tracing:** Traces LLM calls and agent workflows, with annotations for reviewing them.
- **Evaluation:** Automated evaluations, online evaluation rules, and a prompt and model playground.
- **Monitoring:** Dashboards and alerts for production traffic.
- **Agent tools:** An agent optimizer, guardrails, and its own MCP server.
- **Comet platform:** Comet's experiment tracking and model registry make it ideal for teams training and hosting models of their own, not just using the LLM providers.

#### How much does Opik cost?
 
Opik's free hosted plan provides 25k spans per month with up to 10 team members and 60-day data retention. 

Beyond this, its Pro plan is $19 per month for 100k spans per month and up to 50 team members, with every extra 100k spans costing $5. Self-hosting is free, and the whole platform is Apache 2.0, with no separately licensed enterprise code.

## 4. OpenLLMetry

- **Who it's for:** teams already running OpenTelemetry that want LLM instrumentation feeding the observability stack they have.
- **Who it isn't for:** teams that want a full platform with prompt management built in, or more than 24 hours of retention on Traceloop's free plan.
- **License:** Apache 2.0
- [OpenLLMetry on GitHub](https://github.com/traceloop/openllmetry)

![OpenLLMetry dashboard](https://res.cloudinary.com/dmukukwp6/image/upload/openllmetry_aa916c3921.png)

**OpenLLMetry** is an open-source observability product for LLM applications based on OpenTelemetry. It was built by Traceloop and recommends using its SDK to capture data.
 
ServiceNow announced it was acquiring Traceloop in March 2026, and has since made its platform part of ServiceNow’s AI Control Tower. OpenLLMetry itself remains open source and is still shipping releases.

#### What does OpenLLMetry include?
 
- **Instrumentation:** Captures data from more than a dozen LLM providers, plus vector DBs and LLM frameworks, through OpenTelemetry.
- **Destinations:** Sends that data to more than 20 supported destinations, from Traceloop to [Datadog](/compare/best-datadog-alternatives) to Honeycomb, so it's very likely to work with the observability tools you already use.
- **Full-stack traces:** As part of the broader OpenTelemetry ecosystem, it can instrument things like your database and API calls too.
- **Standards:** Its semantic conventions for LLMs were the starting point for OpenTelemetry's own GenAI conventions.
- **MCP:** Instruments MCP calls so they show up in your traces.

#### How much does OpenLLMetry cost?
 
OpenLLMetry itself is free. Traceloop, the hosted platform, is free up to 50k spans per month and 5 seats, but this only provides 24-hour data retention. 

For more, you'll need to talk to sales, which now means ServiceNow.

## 5. Phoenix

- **Who it's for:** teams that want to self-host with no feature gates on an OpenTelemetry-based setup, or expect to move to Arize AX later.
- **Who it isn't for:** teams that need an OSI-approved license, or a free hosted version of Phoenix itself.
- **License:** Elastic License 2.0 (source-available)
- [Phoenix on GitHub](https://github.com/Arize-ai/phoenix)

![Phoenix](https://res.cloudinary.com/dmukukwp6/image/upload/phoenix_fb7498c189.png)

Phoenix is an open source AI observability platform. It provides tracing, evaluation, datasets and experiments, a playground, prompt management, and more. It works out-of-the-box with frameworks like LlamaIndex and LangChain as well as LLM providers like OpenAI, Bedrock, and more. 

It's built by Arize AI, a unified AI observability and evaluation platform that Dynatrace acquired in October 2026.

One caveat on "open source": Phoenix uses the Elastic License 2.0. You can self-host it for free with no feature gates, but it isn't an OSI-approved license, and you can't offer Phoenix to others as a managed service. 

#### What does Phoenix include?
 
- **Tracing:** Built on OpenTelemetry and OpenInference, a set of conventions and plugins that are complementary to OpenTelemetry, so it fits into your existing telemetry stack.
- **Evaluation and experiments:** Evaluations, datasets and experiments, a playground, and prompt management.
- **Agent tools:** A built-in AI engineering agent called PXI and a remote MCP server, both added in 2026.
- **Arize AX:** Connected to a broader platform that also monitors traditional ML and computer vision models, which helps teams running more than LLMs.

#### How much does Phoenix cost?
 
Phoenix is free to self-host. Arize no longer advertises a free hosted Phoenix, although existing Phoenix Cloud users can still log in. For a managed option, it points you to Arize AX, its separate SaaS platform: AX Free includes 25k spans per month with 15-day retention, and AX Pro costs $50 per month for 50k spans with 30-day retention. Both include unlimited users.
 
Dynatrace says Phoenix and AX will both continue, with Arize’s capabilities integrated into Dynatrace over time.

## Other open source LLMO tools worth knowing
 
These didn't make the list, either because they miss one of the criteria above or because they're newer and smaller:
 
- **MLflow** – One of the largest open source ML projects, with an Apache 2.0 license and a home at the Linux Foundation. Its tracing supports 50+ frameworks and providers. There's no free hosted version from the project itself; managed MLflow runs on Databricks and AWS.
- **LangWatch** – Open core (Apache 2.0, with separately licensed enterprise code) and known for agent simulation testing. Its free cloud plan covers 50k events a month for 2 users, with 14-day retention.
- **Laminar** – Fully Apache 2.0, with tracing and dashboards for cost, tokens, and latency. The free cloud plan is small: 1 GB of data, 7-day retention, and one seat.
- **Lunary** – An observability and prompt management platform built for LLM chatbots; its repository is no longer public, self-hosting now needs an enterprise license, and there's no free plan, so we removed it.

LangSmith and Braintrust come up a lot too, but neither is open source. We cover them in [the best AI observability tools](/compare/best-ai-observability-tools).

## Frequently asked questions

<details>
<summary>What does it mean for PostHog to be your product's context layer?</summary>

It means your LLM traces sit next to everything else you know about the user. [AI observability](/ai-observability), [product analytics](/product-analytics), [session replay](/session-replay), [error tracking](/error-tracking), [feature flags](/feature-flags), and [logs](/logs) all share one model of users and sessions. For any generation, you can see who the user was, what they did next, whether an error fired, and which experiment they were in, etc.
 
The [data warehouse](/warehouse) and [data pipelines](/data-pipelines) extend it to the business data that lives elsewhere, like Stripe, HubSpot, and Postgres. So an agent working from [Slack](/slack), the [CLI](/docs/cli), or your editor via [the MCP](/mcp) can answer questions about your product data without stitching a bunch of tools together.
 
</details>

<details>
<summary>PostHog says it makes your product "self-driving" – what does that mean?</summary>

It means PostHog digs through your product data, finds what's worth fixing, and has agents do the work.

It starts with context. A full suite of developer tools – [AI observability](/ai-observability), [product analytics](/product-analytics), [session replay](/session-replay), [feature flags](/feature-flags), [experiments](/experiments), [error tracking](/error-tracking), [logs](/logs), and more – captures everything happening in your product, and a [data warehouse](/warehouse) unifies it into one source agents can read across.

From there, [Scouts](/blog/what-is-a-scout) read across all of it and sort what's worth knowing from what's just noise. What clears the bar becomes a report in your inbox: an agent picks it up, roots out the cause, and opens a PR. You review and merge.

<details>
<summary>What is LLM observability?</summary>

LLM observability (also called AI observability) is the practice of monitoring and understanding how your LLM-powered application behaves in production. It typically includes capturing individual LLM calls (inputs, outputs, latency, token usage), aggregating metrics across requests, and providing tools to debug issues and improve model performance.

It's similar to traditional application observability, but focused on the unique characteristics of LLM systems – non-deterministic outputs, high token costs, prompt sensitivity, and the challenge of evaluating quality.

</details>

<details>
<summary>What features do you need in an LLM observability tool?</summary>

A good LLM observability tool gives you visibility into how your AI-powered app is performing in production. Most solid tools include:

- **Tracing and logging** to capture individual LLM calls, inputs, outputs, and latency
- **Cost tracking** to monitor token usage and spend across providers and models
- **Aggregated dashboards** for monitoring performance trends over time
- **Self-hosting options** so you keep full control of your data and model inputs

More advanced tools go further with:

- **Prompt management** for versioning, testing, and deploying prompts
- **Evaluation and evals** to score model outputs automatically or with human review
- **Datasets** for curating examples and running regression tests
- **Integration with product analytics** so you can connect LLM performance to user behavior
- **OpenTelemetry compatibility** for teams with existing observability infrastructure

</details>

<details>
<summary>When should you consider an LLM observability tool?</summary>

If you're building an LLM-powered app and have shipped to real users, you need one. Common signals that you're ready:

- You're not sure which prompts or models are causing user drop-off
- You're spending more on tokens than expected and don't know where the cost is going
- You have no visibility into latency spikes or failure rates
- You want to [run evals or compare model versions systematically](/blog/testing-ai-agents)

Most tools on this list are free to start, so there's no reason to wait.

</details>

<details>
<summary>Which open source LLM observability tools have an MCP server?</summary>

PostHog, Langfuse, Opik, and Phoenix all have one, so a coding agent like Claude Code or Cursor can query your traces and costs directly:
 
- **PostHog** – The [MCP server](/docs/ai-observability/surfaces/mcp) covers AI observability along with the rest of the platform, so an agent can go from a trace to the session replay or error behind it.
- **Langfuse** – A native MCP server with read and write tools for prompts, observations, scores, and datasets.
- **Opik** and **Phoenix** – Each ships its own MCP server.

OpenLLMetry takes a different angle: it instruments MCP calls so they show up in your traces.
 
</details>

No. PostHog's [LLM observability](/docs/ai-observability) product is built into the platform, so if you're already using PostHog for product analytics or session replay, you can add LLM observability without any additional setup or contract. You get 100k LLM events free per month.

[Getting started](/docs/ai-observability/start-here) is easy; once you install the SDK, it will handle all the heavy lifting. Use your LLM provider as normal and we'll capture everything automatically.

</details>

<details>
<summary>What's the difference between LLM observability and traditional application monitoring?</summary>

**Traditional application monitoring** focuses on things like error rates, latency, and uptime – binary metrics where something either works or doesn't. 

**LLM observability** adds a quality dimension: you need to evaluate whether model outputs are actually good, not just whether the API call succeeded. This is why tools like Langfuse and Opik invest heavily in evals, human review, and prompt management – capabilities that don't exist in [traditional APM tools](/compare/best-apm-tools-for-developers).

</details>
 
<details>
<summary>Are these tools compatible with all LLM providers?</summary>

Most tools on this list support the major providers – OpenAI, Anthropic, Google Gemini, and AWS Bedrock – as well as popular frameworks like LangChain, LlamaIndex, and Vercel AI SDK. Coverage varies by tool. **Langfuse** and **PostHog** have the broadest integration coverage.

For specific provider support, check each tool's documentation.

</details>
