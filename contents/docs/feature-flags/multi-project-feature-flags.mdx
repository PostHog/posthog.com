Sometimes, you may want to use the same feature flag keys across different PostHog [projects](/docs/settings/projects). For example, when you're testing a new feature in staging before releasing to production. In this case, PostHog makes it easy to copy and sync feature flags across projects.

This eliminates the need for manual replication, which is error-prone.

## Bulk copying flags to other projects

You can copy multiple feature flags to other projects at once using bulk copy. This is useful when you need to replicate several flags across environments (like dev, staging, and production).

To bulk copy flags:

1. Go to the [Feature Flags tab](https://app.posthog.com/feature_flags) in PostHog.
2. Use the checkboxes to select the flags you want to copy.
3. Click **Copy to projects** in the toolbar that appears.
4. Select the destination projects in the modal.
5. **Optional:** Check **Copy as disabled** to copy the flags in a disabled state.
6. **Optional:** Check **Copy pending scheduled changes** to include any pending [scheduled changes](/docs/feature-flags/scheduled-flag-changes).
7. Click **Copy** to start the copy operation.

The results view shows a summary of the operation, including:

- **Successful copies** – Flags that were created or updated in the target projects.
- **Pending approval** – Flags where a [change request](/docs/settings/approvals) was created because the target project requires approval for flag changes.
- **Failures** – Flags that couldn't be copied (for example, due to missing access to the target project).

Each flag × project combination succeeds or fails independently, so inaccessible targets don't block other copies.

<CalloutBox icon="IconInfo" title="Bulk copy limits" type="fyi">

You can copy up to 100 flags to up to 50 destination projects at a time.

</CalloutBox>

### Bulk copy from the Projects grid

You can also bulk copy from the **Projects** tab on the Feature Flags page. This tab shows a grid view of all flags across all projects in your organization.

1. Go to the [Feature Flags tab](https://app.posthog.com/feature_flags) and select the **Projects** tab.
2. Use the row checkboxes to select the flag keys you want to copy.
3. Click **Copy to projects** in the toolbar.
4. Select the **source project** (the project to copy flags from).
5. Select the **destination projects**.
6. Configure options and click **Copy**.

## Copying a single flag to other projects

> **Note:** If you copy a flag linked to a [dynamic cohort](/docs/data/cohorts#dynamic-cohorts) and a cohort with the same name does not exist in the target project, the entire cohort will be copied over.
>
> For [static cohorts](/docs/data/cohorts#static-cohorts), the cohort will be copied but it will be empty. This is because the associated persons might not exist in the target project.

Follow these steps to copy or update the flag in another project:

1. Navigate to the feature flag you want to copy.
2. Select the **Projects** tab.
3. Select the project you want to copy the flag to.
4. **Optional:** Check **Copy schedules** to include pending [scheduled changes](/docs/feature-flags/scheduled-flag-changes). This checkbox shows the count of pending schedules (e.g., "3 pending") and is only enabled when the source flag has pending scheduled changes.
5. Click **Copy** or **Update** - this depends on whether the flag already exists in the target project.
6. View the table at the bottom to see the newly created or updated flag.

<CalloutBox icon="IconInfo" title="Note" type="fyi">

When copying schedules, only unexecuted (pending) scheduled changes are copied. All schedule properties are preserved, including timing, recurrence, payload, and end dates.

</CalloutBox>
