## What's included in a profile

Customer profiles pull together data from across PostHog and connected sources:

| Data type         | Source                                                  | Requirements                             |
| ----------------- | ------------------------------------------------------- | ---------------------------------------- |
| Events            | [Product analytics](/docs/product-analytics)            | Automatic                                |
| Errors            | [Error tracking](/docs/error-tracking)                  | Error tracking enabled                   |
| LLM traces        | [LLM observability](/docs/ai-engineering/observability) | LLM observability enabled                |
| Support tickets   | [Zendesk](/docs/data-pipelines/sources/zendesk)         | Zendesk data warehouse source connected  |
| Customer journeys | [Customer journeys](#customer-journeys)                 | Journeys configured with funnel insights |

## Viewing a customer profile

You can access customer profiles in two main ways:

1. **From the dashboard**: Click on any customer in the [customer analytics dashboard](https://app.posthog.com/customer_analytics)
2. **From customer lists**: Click any [person](https://app.posthog.com/persons) or [group](https://app.posthog.com/groups/0) from the lists to open their profile

Accessing customers from insights and other producs will also land in their profile page.

## Persons vs groups

Customer profiles work for both individual [persons](/docs/data/persons) and [groups](/docs/product-analytics/group-analytics).

- **Person profiles** show activity for a single user
- **Group profiles** show aggregated activity for an organization, company, or any other group type you've defined

This is useful for B2B products where you care about company-level activity, not just individual users.

## Pinned account properties

The account sidebar displays pinned properties for quick access to the information that matters most. You can customize which properties appear by clicking the gear icon next to **Properties** in the sidebar.

When viewing an account, a chip next to the **Properties** heading shows where the current pinned properties come from – for example, **Project default** or a role name.

### How pinned properties are resolved

PostHog resolves which properties to display using the following priority:

1. **Personal pins** – If you've saved your own pinned properties, those are used.
2. **Role defaults** – If you haven't set personal pins and your [roles](/docs/settings/access-control) have default pins configured, PostHog merges the defaults from all your roles.
3. **Project defaults** – If neither personal pins nor role defaults exist, the project-wide defaults are used.

### Reset to default

To follow a default configuration instead of your personal pins, open the pin configurator by clicking the gear icon and click **Reset to default**. If multiple defaults are available (project and role), choose which one to follow.

When you follow a default, your pinned properties stay in sync with that default. If an admin updates the default later, your sidebar reflects the change automatically.

### Configure default pinned properties

Admins can set default pinned properties in [**Settings** > **Customer analytics** > **Accounts**](https://app.posthog.com/settings/environment-customer-analytics#customer-analytics-accounts). Use the **Applies to** dropdown to configure defaults for:

- **Everyone in the project** – The fallback default for all team members.
- **A specific role** – Members of that role see these defaults instead of the project defaults, as long as they haven't saved personal pins.

## Customer journeys

Customer profiles include a **Customer journey** node that shows where a person or group is within your defined journeys. Journeys are based on funnel insights you configure, letting you see a customer's progress through key conversion steps.

The journey node displays:

- Which funnel steps the customer has completed
- Which steps are incomplete
- Which steps are optional

You can switch between different journeys using the dropdown selector in the node. If no journeys are configured, click **Configure journeys** to set them up.

For details on creating and managing journeys, see [Create customer journeys](/docs/customer-analytics/create-customer-journeys).

## Connecting support tickets

To see support tickets in customer profiles, connect Zendesk as a [data warehouse source](/docs/data-pipelines/sources/zendesk).

Once connected, support tickets appear in the profile alongside events and errors. This helps you understand the full context of a customer's experience: what they did, what went wrong, and what they asked for help with.

### How tickets are matched to customers

For people, the email associated with the person is used to get their Zendesk tickets. The ticket needs to have been created from the same email for it to show up.

For groups, all tickets from a given Zendesk organization are fetched. To correlate a PostHog group to a Zendesk organization, you need to set the organization `external_id` with the value of the `groupKey` used to create the group (ideally the ID of the group in your application's database).
For more information about setting up groups, see [groups docs](/docs/product-analytics/group-analytics).
