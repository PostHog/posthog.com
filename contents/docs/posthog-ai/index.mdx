PostHog AI is an AI product analyst that lives inside PostHog. Ask it a question in plain English and it queries your data, builds the insight, writes the SQL, or finds the session replay – then explains what it found. Because it runs on your project's own events, persons, and schema, its answers are about your product, not a generic dataset.

It also does the work, not just the analysis. PostHog AI creates dashboards, surveys, alerts, and feature flags, edits filters in the UI alongside you, and remembers what it learns about your product between conversations. When a change belongs in code, it hands the job to a coding agent and reports back on it – see [how that works](#how-posthog-ai-works-with-self-driving) below.

## How PostHog AI works with Self-driving

Most tools feed [Self-driving](/docs/self-driving) as a signal source. PostHog AI's relationship to the loop is different: it's how *you* start and follow coding work, rather than a stage the autonomous loop passes through.

Ask PostHog AI to make a change and it creates a coding task, points it at a connected repository, and runs it. The code is written by a coding agent working in a sandbox, which pushes a branch and opens a draft pull request. PostHog AI is the thing you talk to and the thing that reports back – it isn't the agent editing your files.

The autonomous path runs the same way at the end – a report becomes a coding task and a draft pull request – but it starts from a [signal report](/docs/self-driving/reports) rather than from a conversation, so PostHog AI isn't involved in picking it up. Either way you can follow every run from the task tracker in the [web app](/docs/posthog-ai/surfaces/web-app). See the [Self-driving docs](/docs/self-driving) for the full picture.
