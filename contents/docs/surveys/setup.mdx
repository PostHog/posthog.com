---
title: Initial setup
---

You can set up surveys as a pre-built in-app popover or with your own custom UI (`type: "api"`).

## Option 1: Pre-built survey

1. Turn on **Enable surveys** in [project survey settings](https://app.posthog.com/settings/project-surveys) (sets `surveys_opt_in: true` on the project).
2. Initialize `posthog-js` (or add the [JavaScript snippet](/docs/getting-started/install)) without `disable_surveys: true`:

```js-web
posthog.init("<ph_project_token>", {
    api_host: "<ph_client_api_host>",
    // Optional: set opt_out_useragent_filter: true in headless browser tests (Playwright/Puppeteer)
})
```

3. Create and launch a survey in [Surveys](https://app.posthog.com/surveys).

## Option 2: Custom UI (`type: "api"`)

1. Enable `surveys_opt_in` in project settings and initialize `posthog-js >= 1.232.7` for `onSurveysLoaded` (`>= 1.249.2` for automatic seen-state tracking, `>= 1.435.0` for `onActiveMatchingSurveysChanged`). Set `opt_out_useragent_filter: true` in automated headless browsers so bot filtering doesn't drop events.
2. Wait for surveys and feature flags before reading matches. Do **not** call `getActiveMatchingSurveys()` directly inside `posthog.init`'s `loaded` callback (the surveys module finishes initializing after `loaded`). Subscribe with `onActiveMatchingSurveysChanged` (`posthog-js` 1.435.0+), or on older SDKs combine `onFeatureFlags` and `onSurveysLoaded` (`posthog-js` 1.232.7+) while cleaning up both unsubscribe functions, and filter for `survey.type === 'api'`:

```js-web
// posthog-js 1.435.0+
const unsubscribe = posthog.onActiveMatchingSurveysChanged((surveys) => {
    const apiSurveys = surveys.filter((survey) => survey.type === 'api')
    handleSurveys(apiSurveys)
})

// posthog-js 1.232.7 - 1.434.x (unsubscribe inner listener before re-subscribing and on cleanup)
let unsubscribeSurveys
const unsubscribeFlags = posthog.onFeatureFlags(() => {
    unsubscribeSurveys?.()
    unsubscribeSurveys = posthog.onSurveysLoaded(() => {
        posthog.getActiveMatchingSurveys((surveys) => {
            const apiSurveys = surveys.filter((survey) => survey.type === 'api')
            handleSurveys(apiSurveys)
        })
    })
})
```

> **Note:** On `posthog-js >= 1.249.2`, capturing `survey sent` or `survey dismissed` automatically marks the survey as seen in `localStorage` and sets the response/dismissal person properties (include `$survey_iteration` for recurring surveys). See [mark a survey as seen](/docs/surveys/implementing-custom-surveys#mark-a-survey-as-seen) for backend capture.

3. Capture lifecycle events (`survey shown`, `survey sent`, `survey dismissed`) using ID-keyed response properties (`$survey_response_<question.id>`):

```js-web
posthog.capture("survey shown", {
    $survey_id: survey.id,
    $survey_iteration: survey.current_iteration,
})

posthog.capture("survey sent", {
    $survey_id: survey.id, // required
    $survey_iteration: survey.current_iteration,
    $survey_submission_id: crypto.randomUUID(),
    $survey_completed: true,
    $survey_questions: survey.questions.map(({ id, question }) => ({ id, question })),
    [`$survey_response_${survey.questions[0].id}`]: surveyResponse,
    $survey_name: survey.name, // optional
})
```

See [implementing custom surveys](/docs/surveys/implementing-custom-surveys#response-formats) for rating, choice, branching, and inline rendering details.
