The [PostHog MCP server](/docs/model-context-protocol) exposes Surveys API operations as tool calls for MCP clients (Cursor, Claude Code, Windsurf, VS Code).

## Prerequisites

1. Enable **Surveys** (`surveys_opt_in`) in [project survey settings](https://app.posthog.com/settings/project-surveys) and [install a PostHog SDK](/docs/surveys/installation).
2. Install the PostHog MCP server:

```bash
npx @posthog/wizard mcp add
```

You can also [configure it manually](/docs/model-context-protocol#get-started-in-30-seconds).

## Available tools and scopes

| Tool | Required scopes | Behavior & key inputs |
| --- | --- | --- |
| `survey-create` | `survey:write` (`feature_flag:write` when setting targeting) | Creates a survey as a **draft** by default (requires `name` and `type`). Supports `type` (`popover`, `widget`, `external_survey`, `api`), `questions` (each entry requires `type` and `question`), `appearance`, `conditions`, `schedule`, `repeat_until_stopped`, `responses_limit`, `base_language` (BCP-47, default `"en"`), and `translations`. |
| `survey-update` | `survey:write` (`feature_flag:write` when setting targeting) | Updates questions, appearance, conditions, targeting, schedule, `responses_limit`, `archived`, or `base_language`/`translations`. Setting `start_date` via `survey-update` also activates targeting flags when launching a draft. |
| `survey-launch` | `survey:write` | Launches a draft survey by setting `start_date` to the current UTC time. Does not toggle `internal_targeting_flag` or `targeting_flag`, so for a default draft from `survey-create`, set `start_date` via `survey-update` (or activate the targeting flags first) so SDK eligibility checks pass. |
| `survey-stop` | `survey:write` | Stops an active survey by setting `end_date` to the current UTC time while keeping collected responses. |
| `survey-delete` | `survey:write` | Soft-deletes a survey by setting `archived: true` via `PATCH` (reversible via `survey-update`). |
| `survey-get` | `survey:read` | Returns one survey's full configuration, question UUIDs, and feature flag keys. |
| `surveys-get-all` | `survey:read` | Lists project surveys with optional search filter. |
| `surveys-global-stats` | `survey:read` | Returns project-wide `survey shown`, `survey dismissed`, and `survey sent` counts and conversion rates across an optional date window (ISO 8601 or relative `-7d`; naive values use the project timezone). |
| `survey-stats` | `survey:read` | Returns single-survey engagement counts, conversion rates, and optional per-question answer distributions when `include_per_question_stats: true` is passed. |
| `surveys-responses-list` | `survey:read`, `query:read` | Lists individual responses with resolved question text, score filters, and `exclude_archived` filtering. |
| `surveys-summarize-responses-create` | `survey:read` | Generates an LLM theme summary for one question (`question_id` or `question_index`, PostHog Cloud only), or a survey-wide headline summary when omitted. |

## Example prompts

- `Create a draft NPS survey with base_language "en" for users who visited /pricing in the last week.`
- `Launch the checkout feedback survey.`
- `Pull per-question stats and raw responses for the onboarding survey.`
- `Stop the PMF survey now that we hit our response target.`
