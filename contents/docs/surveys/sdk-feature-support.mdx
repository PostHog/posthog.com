Check minimum SDK versions and feature limits across PostHog Surveys client SDKs.

## Platform requirements

| SDK | Package | Minimum OS / runtime | Built-in UI | Custom UI |
| --- | --- | --- | --- | --- |
| Web | `posthog-js` | `>= 1.81.3` (`1.67.1` for API-only) | Automatic popover, inline (`displaySurvey`), feedback button | `getActiveMatchingSurveys` + `capture` |
| React Native | `posthog-react-native` | `PostHogSurveyProvider` required (`react-native-svg` optional) | Built-in modal | Custom rendering via SDK survey methods |
| iOS | `posthog-ios` | iOS `15.0+` | Built-in SwiftUI sheet | Custom `PostHogSurveysDelegate` |
| Android | `posthog-android` | API `23+` (`posthog-android-surveys-compose` for UI) | `PostHogSurveysComposeDelegate` (auto-discovered in `3.49.0+`, otherwise log-only default) | Custom `PostHogSurveysDelegate` |
| Flutter | `posthog_flutter` | `>= 5.8.0` (`5.14.0+` recommended), Android API `23+`, iOS `15.0+`, `PosthogObserver` required | Built-in bottom sheet (Web delegates to `posthog-js`) | Not built-in |

## Cross-SDK constraints

- Event property filters with `gte` or `lte` operators in `conditions.events` or `conditions.cancelEvents` aren't supported on any SDK.
- Enable **Surveys** (`surveys_opt_in`) in [project survey settings](https://app.posthog.com/settings/project-surveys) before any client SDK receives active surveys.
- On Android, HTML descriptions on intro screens, questions, and thank-you screens are omitted. Use plain text descriptions for Android compatibility.
- On Flutter Web, survey fetching and rendering delegate to `posthog-js`, so web feature support applies instead of Flutter mobile limits.
