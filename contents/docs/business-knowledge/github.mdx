GitHub repositories let Business Knowledge read repositories you select as context when it answers a question. It searches file names and the README, then reads a file. It doesn't index the code, and it doesn't search inside file contents.

Connect a repository in [Business Knowledge settings](https://app.posthog.com/business-knowledge/settings). The setting is shown when GitHub repositories are enabled for your project.

The list belongs to the environment where you save it. An environment is a separate data space in a project, such as production or development. Each environment keeps its own repository list.

## How repositories are referenced

Document search runs first. If that search returns nothing, Business Knowledge searches the file names and README text of the repositories you saved.

It matches file names and identifiers, not a full sentence. Each result includes the GitHub description. When that description says the repository holds a handbook or docs, Business Knowledge searches that repository for those words, then reads the file.

The read returns the file text and a permalink. The Playground shows this as **Searched repositories** and **Read file**.

## Connect

1. [Install the PostHog GitHub App](https://app.posthog.com/settings/project-integrations) if it isn't installed yet.
2. Open [**Business Knowledge** settings](https://app.posthog.com/business-knowledge/settings).
3. Under **GitHub repositories**, connect the installation.
4. Add repositories and choose **Save repositories**.

You can select up to 100 repositories.

## Disconnect

**Disconnect** stops Business Knowledge from reading those repositories. The GitHub App stays installed.

## Libraries

Repositories can belong to [libraries](/docs/business-knowledge/sources#libraries). Open a library and add repositories in the library dialog. Pass `library_id` to repository search or file read to search only the repositories in that library. A repository link is removed only when no environment in the project still allows that repository.
