Flushing is best-effort and asynchronous – it starts sending queued events in the background but doesn't wait for the request to finish, so it isn't a delivery guarantee. You don't need to flush before your app goes to the background (the SDK flushes automatically) or before `reset()` on logout (queued events keep the `distinct_id` they were captured with). Anything not sent is persisted to the device's file storage on capture and retried automatically the next time the app opens, so events aren't lost.
