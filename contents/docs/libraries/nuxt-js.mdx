PostHog makes it easy to get data about usage of your [Nuxt.js](https://nuxt.com/) app. Integrating PostHog into your app enables analytics about user behavior, custom events capture, session replays, feature flags, and more.

This guide covers Nuxt v4.x and v3.7+. For these versions, we recommend using `@posthog/nuxt` module for client-side capture.

The `@posthog/nuxt` module provides:

- Automatic client-side PostHog initialization
- Auto-imported composables for PostHog and feature flags
- Automatic exception capture for error tracking
- Source map configuration and upload for error tracking

For server-side event capture, reuse the module's Node client as shown below.

> **Using an older version?** See our docs for [Nuxt 3.0-3.6](/docs/libraries/nuxt-js-3-6) or [Nuxt 2.x](/docs/libraries/nuxt-js-2).

## Configuration

Store your PostHog keys in environment variables rather than hard-coding them. Add them to a `.env` file (and to your hosting provider). You can find these values in [your project settings](https://us.posthog.com/settings/project).

```shell file=.env
NUXT_PUBLIC_POSTHOG_KEY=<ph_project_token>
NUXT_PUBLIC_POSTHOG_HOST=<ph_client_api_host>
```

Then reference them when you add the module to your `nuxt.config.ts` file:

```typescript file=nuxt.config.ts
export default defineNuxtConfig({
  modules: ['@posthog/nuxt'],
  posthogConfig: {
    publicKey: process.env.NUXT_PUBLIC_POSTHOG_KEY, // Find it in project settings https://app.posthog.com/settings/project
    host: process.env.NUXT_PUBLIC_POSTHOG_HOST, // Optional: defaults to https://us.i.posthog.com. Use https://eu.i.posthog.com for EU region
    clientConfig: {
      // Optional: PostHog client configuration options
    },
  },
})
```

## Usage on the client side

The module provides the `usePostHog()` composable which is auto-imported and available in all your Vue components:

```vue file=app/pages/index.vue
<script setup>
const posthog = usePostHog()

// Capture a custom event
posthog?.capture('button_clicked', { button_name: 'signup' })
</script>
```

> **Note:** `usePostHog()` returns `undefined` on the server side during SSR, so use optional chaining `?.` when calling methods.

## Usage on the server side

Reuse the server client initialized by the module. The Node-only `@posthog/nuxt/server` accessor returns that client after its Nitro plugin starts and returns `undefined` before startup or after shutdown:

```typescript file=server/utils/posthog.ts
import type { PostHog } from 'posthog-node'
import { getPostHogServerClient } from '@posthog/nuxt/server'

export function useServerPostHog(): PostHog {
  const client = getPostHogServerClient()
  if (!client) throw new Error('PostHog server client is not initialized')
  return client
}
```

Then use it in your server routes:

```typescript file=server/api/example.ts
export default defineEventHandler((event) => {
  const posthog = useServerPostHog()

  posthog.capture({
    distinctId: 'user_123',
    event: 'server_event',
  })

  return { success: true }
})
```

### Request and span context

This setup requires the Nuxt module release with `requestContext` and `getPostHogServerClient()`, plus the Node SDK release with the shared context bridge and signal support. Add the opt-in to your existing Nuxt configuration:

```typescript file=nuxt.config.ts
export default defineNuxtConfig({
  posthogConfig: {
    serverConfig: { requestContext: true },
  },
})
```

The module reads `X-PostHog-Distinct-ID` and `X-PostHog-Session-ID` as fallback analytics context. It preserves application identity, removes control characters, trims values, limits IDs to 1,000 characters, and omits missing IDs. These headers must not authorize access. Analytics context works without OpenTelemetry.

For application-owned OpenTelemetry spans, add a processor using the same client inside your existing tracing plugin:

```typescript file=server/utils/posthog-tracing.ts
import { PostHogContextSpanProcessor } from 'posthog-node/otel'
import { useServerPostHog } from './posthog'

export function createPostHogSpanProcessor() {
  return new PostHogContextSpanProcessor(useServerPostHog())
}
```

Call `createPostHogSpanProcessor()` from your existing tracing plugin after the PostHog module's Nitro plugin starts and before requests begin. Add it to your existing provider's processors. Keep the provider, exporters, sampler, and other processors. See the [Node.js tracing guide](/docs/distributed-tracing/installation/nodejs#with-opentelemetry) for setup. The module does not create spans or install OpenTelemetry.

The handler scope fills missing `posthogDistinctId` and `sessionId` attributes on an existing recording span. The processor handles new child spans and verified recording server ancestors. Explicit attributes stay unchanged. If a sampler drops an intermediate span, the earlier server ancestor stays unchanged.

The Node setup covers Nitro 2's H3 handler and Nitro 3's fetch handler. Context ends when the handler returns or throws. Later stream-body work and detached tasks have no request IDs. The existing error hook uses the saved two-ID request snapshot; background errors keep anonymous identity. Give separate jobs explicit context and their own lifetime. The module owns client shutdown; do not close it after each request.

## Feature flags

The module provides auto-imported composables for feature flags. All composables return reactive refs that automatically update when flags are loaded or changed.

```vue
<script setup>
const isEnabled = useFeatureFlagEnabled('new-feature')
// returns true, false, or undefined
</script>

<template>
  <div v-if="isEnabled">Feature is enabled!</div>
</template>
```

```vue
<script setup>
const variant = useFeatureFlagVariantKey('experiment')
// returns the variant string, true/false, or undefined
</script>

<template>
  <div v-if="variant === 'control'">Control group</div>
  <div v-else-if="variant === 'test'">Test group</div>
</template>
```

```vue
<script setup>
const payload = useFeatureFlagPayload('config-flag')
// returns any JSON value or undefined
</script>

<template>
  <div v-if="payload">Config: {{ payload.value }}</div>
</template>
```

## Troubleshooting

**TypeScript errors in posthog config:** Remove the `.nuxt` directory and rebuild your project to regenerate config types.

**PostHog not capturing events:** Ensure you're using optional chaining (`posthog?.capture()`) since `usePostHog()` returns `undefined` during server-side rendering.
