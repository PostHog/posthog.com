<Step title="Add the PostHogProvider to your app" badge="required">

In data mode, you'll need to wrap your `RouterProvider` with the `PostHogProvider` context. This passes an initialized PostHog client to your app.

```tsx file=app/index.tsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import { createBrowserRouter, RouterProvider } from "react-router";
import Root, { RootErrorBoundary } from "./app/root";

import posthog from 'posthog-js'; // +
import { PostHogProvider } from '@posthog/react' // +

posthog.init(import.meta.env.VITE_POSTHOG_PROJECT_TOKEN, { // +
  api_host: import.meta.env.VITE_POSTHOG_HOST,
  defaults: '<ph_posthog_js_defaults>', // +
}); // +

const router = createBrowserRouter([...]);

createRoot(document.getElementById("root")!).render(
  <StrictMode>
    {/* Pass PostHog client through PostHogProvider */}
    <PostHogProvider client={posthog}> // +
      <RouterProvider router={router} />
    </PostHogProvider>, // +
  );
});
```

This initializes PostHog and passes it to your app through the `PostHogProvider` context.

<Step title="Capture router errors" badge="recommended">

React Router catches every error thrown while rendering a route or running a loader, action or fetcher, and shows your `ErrorBoundary`, so these errors never reach PostHog's exception autocapture. Turn on `capture_exceptions: true` and pass an `onError` handler to `<RouterProvider>`. Skip responses you throw on purpose, such as 404s.

```tsx
import { isRouteErrorResponse, type ClientOnErrorFunction } from 'react-router';

const onError: ClientOnErrorFunction = (error) => {
  if (isRouteErrorResponse(error)) return;
  posthog.captureException(error);
};

// ...
<RouterProvider router={router} onError={onError} />
```

`onError` needs React Router 7.11 or later. On 7.8.2 to 7.10, pass the same handler as `unstable_onError` and type it with `unstable_ClientOnErrorFunction`. Do not also call `captureException` in your `ErrorBoundary`, and do not rely on a `PostHogErrorBoundary` around the router: React Router's boundaries catch these errors first. See the [React Router error tracking guide](/docs/error-tracking/installation/react-router).

<Step title="Set up server-side analytics" badge="recommended">

Now that you've set up PostHog for React Router V7 in data mode, you can continue to set up server-side analytics. You can find our other SDKs in the [SDKs page](/docs/libraries).

To help PostHog track your user sessions across the client and server, you'll need to add the `tracing_headers: ['your-backend-hostname1.com', 'your-backend-hostname2.com', ...]` option to your PostHog initialization:

```tsx
posthog.init(import.meta.env.VITE_POSTHOG_PROJECT_TOKEN, {
  api_host: import.meta.env.VITE_POSTHOG_HOST,
  defaults: '<ph_posthog_js_defaults>',
  tracing_headers: [ window.location.hostname, 'localhost' ], // +
});
```

This adds the `X-POSTHOG-DISTINCT-ID` and `X-POSTHOG-SESSION-ID` headers to requests sent to the configured hostnames, which you can later use on the server-side.
