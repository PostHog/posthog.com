[Google Tag Manager](https://marketingplatform.google.com/about/tag-manager/) helps you add code snippets or tracking pixels to your website in a low-code way to send data to services like marketing and analytics tools. 

It is an easy way to integrate PostHog into your website without having to update your codebase.

## Using all the features of PostHog via Google Tag Manager

PostHog works the same via Google Tag Manager as it does via our snippet directly. This means you can use all of the features like session replays, surveys, and more without additional setup. 

Some of these do require calling PostHog, which you can do by checking for the window's `posthog` object and calling any of its methods. For example, you can capture a custom event like this:

```html
<script>
  (function waitForPosthog() {
    if (window.posthog) {
      window.posthog.capture('hello');
    } else {
      setTimeout(waitForPosthog, 100);
    }
  })();
</script>
```

You can find the full list of methods in our [JavaScript Web docs](/docs/libraries/js/usage).

## Tag templates

PostHog maintains two Google Tag Manager templates. Both are in the Community Template Gallery. In your container, go to **Templates > Tag Templates > Search Gallery**, then search for PostHog.

- The web template loads the JavaScript Web SDK and adds tag types for capture, identify, alias, reset, and opt in or opt out. Source: [posthog-gtm-template](https://github.com/PostHog/posthog-gtm-template).
- The server template sends events from a server container to the [capture API](/docs/api/capture). Source: [posthog-gtm-template-server](https://github.com/PostHog/posthog-gtm-template-server).

Use the web template to configure PostHog from Google Tag Manager without a custom HTML tag. The custom HTML method above also continues to work.

The web template loads the SDK from PostHog Cloud only. If you use a [reverse proxy](/docs/advanced/proxy) or you self-host, load the SDK with a custom HTML tag, then set the region of the template to **Custom host**.
