PostHog makes it easy to get data about traffic and usage of your Flask app. Integrating PostHog enables analytics, custom events capture, feature flags, error tracking, and more.

This guide walks you through integrating PostHog into your Flask app using the [Python SDK](/docs/libraries/python/reference).

> **Supported versions:** These docs cover version `8.x.x` of the PostHog Python SDK and Flask 2.2 or later. Version `7.71.0` and later `7.x.x` releases also support everything on this page. Both majors require Python 3.10 or higher. Python 3.9 needs `6.x.x` (`pip install 'posthog<7'`), which has no Flask integration. Upgrading from `7.x.x`? Read the [migration guide](/docs/libraries/python/migration).

## Installation

To start, run `pip install "posthog>=8,<9"` to install PostHog’s Python SDK.

Then, initialize PostHog where you'd like to use it. For example, here's how to capture an event in a simple route:

```python file=app.py
from flask import Flask
from posthog import Posthog

app = Flask(__name__)

posthog = Posthog(
    '<ph_project_token>',
    host='<ph_client_api_host>',
)

@app.route('/api/dashboard', methods=['POST'])
def api_dashboard():
    posthog.capture(
        'dashboard_api_called',
        distinct_id='distinct_id_of_your_user',
    )
    return '', 204
```

You can find your project token and instance address in [your project settings](https://app.posthog.com/project/settings).

## Request contexts

Version `7.66.0` and later of the Python SDK includes a Flask integration that creates a fresh [context](/docs/libraries/python#posthognew_context) for every request. It adds the request URL, method, path, route, IP address, and user agent to events captured during the request.

Register the integration after you create your Flask app and PostHog client:

```python file=app.py
from posthog.integrations.flask import PosthogFlaskIntegration

PosthogFlaskIntegration(
    app,
    client=posthog,
    capture_exceptions=True,
)
```

Setting `capture_exceptions=True` captures unhandled Flask exceptions. Set it to `False` for request enrichment without automatic exception capture. If you omit it, the integration inherits the client's `enable_exception_autocapture` setting.

You can also provide:

- `request_filter` to skip both enrichment and automatic exception capture for selected requests
- `extra_properties` to add application-specific properties to the request context
- `capture_tracing_headers` to stop reading PostHog session and distinct ID headers

If you're using [PostHog JavaScript Web](/docs/libraries/js) on the frontend, configure [`tracing_headers`](/docs/libraries/js/config#tracing-headers) for your Flask backend hostname so browser requests include the session and distinct ID headers.

With SDK `7.71.0` or later, the integration reads these headers by default as analytics context. Clients can set them, so don't use them for authentication or authorization. To stop reading them, set `capture_tracing_headers=False` when you register the integration.

Identify the request context from your route when you have an authenticated user ID:

```python
from flask import session
from posthog import identify_context

@app.route("/api/dashboard", methods=["POST"])
def api_dashboard():
    user_id = session.get("user_id")
    if user_id:
        identify_context(str(user_id))

    posthog.capture("dashboard_api_called")

    return "", 204
```

Events captured without a context or explicit `distinct_id` are sent as [anonymous events](/docs/data/anonymous-vs-identified-events) with an auto-generated `distinct_id`. See the [Python SDK docs](/docs/libraries/python#identify) for more details.
