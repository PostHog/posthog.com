PostHog sends email to your users only from a domain you verified. You add a sender on the [**Channels** tab](https://app.posthog.com/workflows/channels), add the DNS records PostHog shows to your domain, and PostHog checks them. Transactional emails, broadcasts, drip campaigns, and workflow email steps all use the same verified senders. To try email before your domain is verified, use the [sandbox sender](/docs/email/sandbox-sender).

Verification applies to the domain, not to the address. When a domain is verified for one sender in a project, every other sender on that domain in the same project is verified too, and you don't add the DNS records again.

## Add a sender

Only project admins and higher can add a sender. If your access level is member, ask a project admin to add it for you.

1. Go to workflows > [**Channels** tab](https://app.posthog.com/workflows/channels), click **+ New channel**, and select **Email**.
2. Enter the **from name**, such as `PostHog Team`, and the **from email**, such as `team@yourdomain.com`. This is what recipients see in their inbox.
3. PostHog shows the DNS records for the domain. Copy them into your domain host, such as Cloudflare or GoDaddy.

Each sender is a separate channel. Only a sender that exists shows in the **From** dropdown of an email step. To add another sender later, use the **Channels** tab again.

## The DNS records

Copy each value from PostHog, not from this page. The tokens are unique to your domain.

| Record | Type | What it does |
| --- | --- | --- |
| DKIM, `<token>._domainkey.yourdomain.com` | CNAME | Signs your email, so inboxes can check that it came from your domain. |
| SPF, `yourdomain.com` | TXT | `v=spf1 include:amazonses.com ~all`. Lists the servers that can send for your domain. |
| Custom MAIL FROM, usually `feedback.yourdomain.com` | MX and TXT | Routes bounces back to PostHog, and aligns SPF with your domain. |
| DMARC, `_dmarc.yourdomain.com` | TXT | `v=DMARC1; p=none;`. Tells inboxes what to do with email that fails the checks. |

PostHog can also show a `_amazonses.yourdomain.com` TXT record and, if another organization already claimed the domain, a `_posthog-verification.yourdomain.com` TXT record that proves you own it. Add them when PostHog shows them.

DNS changes can take a few minutes to propagate. PostHog checks the records when you open the sender, and checks pending senders again every day. Once the domain is verified, you see a green check mark.

## The default sender

When the first sender in a project is verified, it becomes the project's default sender, unless the project already has one. A [transactional email](/docs/email/transactional-emails) sent from code without a `from` address uses the default sender.

## Before your domain is verified

Until your domain is verified, you can send test emails with the [sandbox sender](/docs/email/sandbox-sender), a PostHog-managed sender that is rolling out to projects. It delivers only to active members of your organization whose PostHog email address is verified, and it has daily caps. To send to anyone else, verify the domain, then select your sender in each email step.

## Troubleshooting

| Issue | Solution |
| --- | --- |
| No address in the **From** dropdown? | The step can only use a sender that exists in the project. Add one on the [**Channels** tab](https://app.posthog.com/workflows/channels), then select it in the step. Only project admins and higher can add a sender. |
| Domain still pending? | Check that each record is on the right host name. Some DNS hosts add your domain to the end of the name, so `feedback.yourdomain.com` becomes `feedback.yourdomain.com.yourdomain.com`. Enter only the part before your domain in those hosts. |
| Emails going to spam? | Check that DKIM and SPF pass, add the DMARC record, and read [sending reputation and allowance](/docs/email/sending-reputation). |
| A send fails with `sender_not_verified`? | The `from` address isn't on a verified domain, or the project has no verified default sender. See [the API errors](/docs/email/transactional-emails/api). |
