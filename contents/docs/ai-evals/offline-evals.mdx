Offline evals test your AI agent against known inputs before you ship a prompt, model, or code change. Run your agent and score its outputs locally or in your CI, using your existing test framework. The PostHog SDK uploads the results so you can compare runs and inspect failures.

[Online evaluations](/docs/ai-evals) help you find failures in production. Add those failures to your offline test set to check that your next change fixes them.

## How offline evals work

Each run follows four steps:

1. **Choose test cases** – Each case has an input and, optionally, an expected output. Keep them in your code, a file, or a PostHog [dataset](/docs/ai-evals/datasets).
2. **Run your agent** – An _experiment_ is one run of your test cases. Each _experiment item_ holds one case's input, actual output, and expected output.
3. **Score the output** – Use code checks, an LLM judge, or your existing evaluation library.
4. **Upload the results** – Send the items and scores to PostHog, then mark the experiment complete.

A _scorer_ defines what a result means: its name, value type, and passing rule. A **reported scorer** records scores calculated by your evaluation code and reported to PostHog, such as whether your agent selected the expected tool. With a [**composite scorer**](#combine-scores-with-a-composite-scorer), PostHog calculates a score from other reported scores for the same item.

## Run your first experiment

This example checks the tool and arguments a support agent selects for six requests. It uses local routing rules, so you don't need a model API key or external tools.

Three deliberate mistakes give you failures to inspect: a wrong tool, a missing order ID, and an incorrect order ID. After trying the demo, replace `run_agent()` / `runAgent()` with your agent and adapt `evaluate_answer()` / `evaluateAnswer()` to your checks.

| ------------------------------------ | ------------------------------------------------------------ |

| `llm_analytics:read`                 | Reading an existing scorer                                   |

### 2. Create two scorers

Save this as `create_scorers.py` or `create_scorers.mts` and run it once to create **Correct tool** and **Correct arguments**. For both scorers, `true` passes and `false` fails.

<MultiLanguage selector="tabs">

```python file=Python
import os
from posthog.ai.evaluations import OfflineEvaluations

with OfflineEvaluations(
    project_id=int(os.environ["POSTHOG_PROJECT_ID"]),
    secret_key=os.environ["POSTHOG_PERSONAL_API_KEY"],
    host=os.environ["POSTHOG_HOST"],
) as evaluations:
    for name in ["Correct tool", "Correct arguments"]:
        scorer = evaluations.scorers.create(
            name=name,
            kind="boolean",
            config={
                "true_is_failure": False,
                "true_label": "Pass",
                "false_label": "Fail",
            },
        )
        print(f"{name}: {scorer.id}")
```

### 3. Run the cases and upload scores

Save this as `support_eval.py` or `support_eval.mts`. It uploads two scores per case, each with an explanation. The argument check compares exact key-value pairs independently of the tool name, so a case can pass one check and fail the other.

```python file=Python
import json
import os
import re
from posthog.ai.evaluations import EvaluationItem, OfflineEvaluations

def run_agent(input: str) -> dict:
    text = input.lower()
    match = re.search(r"#(\d+)", text)
    order_id = match.group(1) if match else ""
    # These three rules contain deliberate mistakes for the demo.
    if "cancel" in text:
        return {"tool": "cancel_order", "arguments": {}}
    if "refund" in text:
        return {"tool": "check_refund_policy", "arguments": {"order_id": "1001"}}
    if "order" in text:
        return {"tool": "check_refund_policy", "arguments": {"order_id": order_id}}
    queue = "billing" if "charged" in text else "account"
    return {"tool": "handoff_to_support", "arguments": {"queue": queue}}

def evaluate_answer(output: dict, expected: dict) -> dict:
    return {
        "tool": {
            "value": output["tool"] == expected["tool"],
            "reasoning": f"Expected {expected['tool']}; selected {output['tool']}.",
        },
        "arguments": {
            "value": output["arguments"] == expected["arguments"],
            "reasoning": (
                f"Expected {json.dumps(expected['arguments'])}; "
                f"received {json.dumps(output['arguments'])}."
            ),
        },
    }

cases = [
    {
        "id": "refund_eligibility",
        "input": "Can I get a refund for order #1001?",
        "expected": {"tool": "check_refund_policy", "arguments": {"order_id": "1001"}},
    },
    {
        "id": "delivery_status",
        "input": "Where is order #1002?",
        "expected": {"tool": "look_up_order", "arguments": {"order_id": "1002"}},
    },
    {
        "id": "cancel_order",
        "input": "Please cancel order #1003.",
        "expected": {"tool": "cancel_order", "arguments": {"order_id": "1003"}},
    },
    {
        "id": "refund_other_order",
        "input": "Can I get a refund for order #1004?",
        "expected": {"tool": "check_refund_policy", "arguments": {"order_id": "1004"}},
    },
    {
        "id": "account_access",
        "input": "I can't sign in to my account.",
        "expected": {"tool": "handoff_to_support", "arguments": {"queue": "account"}},
    },
    {
        "id": "billing_question",
        "input": "Why was I charged twice?",
        "expected": {"tool": "handoff_to_support", "arguments": {"queue": "billing"}},
    },
]

with OfflineEvaluations(
    project_id=int(os.environ["POSTHOG_PROJECT_ID"]),
    secret_key=os.environ["POSTHOG_PERSONAL_API_KEY"],
    host=os.environ["POSTHOG_HOST"],
) as evaluations:
    scorers = {
        "tool": evaluations.scorers.get(os.environ["POSTHOG_TOOL_SCORER_ID"]),
        "arguments": evaluations.scorers.get(os.environ["POSTHOG_ARGUMENTS_SCORER_ID"]),

        name="Support agent baseline",
        suite_key="support-agent",
        run_source="local",

        expected_result_count=len(cases) * len(scorers),
    )

            output = run_agent(case["input"])
            item = EvaluationItem(
                case_key=case["id"],
                input=case["input"],
                output=output,
                expected_output=case["expected"],
            )
            for key, result in evaluate_answer(output, case["expected"]).items():
                experiment.upload_result(
                    item=item,
                    scorer_version_id=scorers[key].current_version_id,
                    **result,
                )
    except Exception:
        experiment.fail()
        raise

    experiment.complete()
    print(f"Completed experiment: {experiment.id}")
```

```typescript file=TypeScript
import { EvaluationItem, OfflineEvaluations } from "@posthog/ai/evaluations"

type ToolCall = { tool: string; arguments: Record<string, string> }

function runAgent(input: string): ToolCall {
    const text = input.toLowerCase()
    const orderId = text.match(/#(\d+)/)?.[1] ?? ""
    // These three rules contain deliberate mistakes for the demo.
    if (text.includes("cancel")) {
        return { tool: "cancel_order", arguments: {} }
    }
    if (text.includes("refund")) {
        return { tool: "check_refund_policy", arguments: { order_id: "1001" } }
    }
    if (text.includes("order")) {
        return { tool: "check_refund_policy", arguments: { order_id: orderId } }
    }
    const queue = text.includes("charged") ? "billing" : "account"
    return { tool: "handoff_to_support", arguments: { queue } }
}

function evaluateAnswer(output: ToolCall, expected: ToolCall) {
    const actualArgs = output.arguments
    const expectedArgs = expected.arguments
    return {
        tool: {
            value: output.tool === expected.tool,
            reasoning: `Expected ${expected.tool}; selected ${output.tool}.`,
        },
        arguments: {
            value:
                Object.keys(actualArgs).length === Object.keys(expectedArgs).length &&
                Object.entries(expectedArgs).every(
                    ([key, value]) => actualArgs[key] === value
                ),
            reasoning: `Expected ${JSON.stringify(
                expectedArgs
            )}; received ${JSON.stringify(actualArgs)}.`,
        },
    }
}

const cases: { id: string; input: string; expected: ToolCall }[] = [
    {
        id: "refund_eligibility",
        input: "Can I get a refund for order #1001?",
        expected: { tool: "check_refund_policy", arguments: { order_id: "1001" } },
    },
    {
        id: "delivery_status",
        input: "Where is order #1002?",
        expected: { tool: "look_up_order", arguments: { order_id: "1002" } },
    },
    {
        id: "cancel_order",
        input: "Please cancel order #1003.",
        expected: { tool: "cancel_order", arguments: { order_id: "1003" } },
    },
    {
        id: "refund_other_order",
        input: "Can I get a refund for order #1004?",
        expected: { tool: "check_refund_policy", arguments: { order_id: "1004" } },
    },
    {
        id: "account_access",
        input: "I can't sign in to my account.",
        expected: { tool: "handoff_to_support", arguments: { queue: "account" } },
    },
    {
        id: "billing_question",
        input: "Why was I charged twice?",
        expected: { tool: "handoff_to_support", arguments: { queue: "billing" } },
    },
]

const evaluations = new OfflineEvaluations({
    projectId: Number(process.env.POSTHOG_PROJECT_ID),
    secretKey: process.env.POSTHOG_PERSONAL_API_KEY!,
    host: process.env.POSTHOG_HOST!,
})

try {
    const scorers = {
        tool: await evaluations.scorers.get(process.env.POSTHOG_TOOL_SCORER_ID!),
        arguments: await evaluations.scorers.get(
            process.env.POSTHOG_ARGUMENTS_SCORER_ID!
        ),
    }
    const experiment = await evaluations.createExperiment({
        name: "Support agent baseline",
        suiteKey: "support-agent",
        runSource: "local",
        expectedItemCount: cases.length,
        expectedResultCount: cases.length * Object.keys(scorers).length,
    })

    try {
        for (const testCase of cases) {
            const output = await runAgent(testCase.input)
            const item = new EvaluationItem({
                caseKey: testCase.id,
                input: testCase.input,
                output,
                expectedOutput: testCase.expected,
            })
            const scores = evaluateAnswer(output, testCase.expected)
            for (const key of ["tool", "arguments"] as const) {
                await experiment.uploadResult({
                    item,
                    scorerVersionId: scorers[key].currentVersionId,
                    ...scores[key],
                })
            }
        }
    } catch (error) {
        await experiment.fail()
        throw error
    }

    await experiment.complete()
    console.log(`Completed experiment: ${experiment.id}`)
} finally {
    evaluations.close()
}
```

### Read scores alongside coverage

Pass rate includes only results with status `ok`. Eight passing results and two evaluator errors produce a 100% pass rate, with only eight scored items.

Expand **Coverage** beside each scorer summary to check errors, skipped checks, and missing results. **Missing** means an uploaded item has no result for that scorer. It can't reveal cases you never uploaded, so compare the received item count with your expected count too. Composite calculations you haven't requested show **Not requested**.

Numeric scorers show their mean. Numeric and categorical scorers need a passing rule to show a pass rate. Repeated trials each count as an item, so keep trial counts consistent when comparing runs.

### Use results in your CI

Use a [project secret API key](/docs/api/project-secret-api-keys) with the `offline_evaluation_ingestion:write` scope for your CI uploads. It can create experiments, upload results, and mark runs complete or failed without depending on a teammate's account.

Project secret keys can't create or read scorers or fetch datasets. Set up scorers and load any PostHog dataset with a personal key first. In your CI script, pass the project key as `secret_key` / `secretKey` and use saved scorer version IDs instead of calling `scorers.get()`.

For a composite, save its version ID and the exact input versions it pins. Send those input results with each calculation request.

In your CI, set `run_source="ci"` in Python or `runSource: "ci"` in TypeScript. Record your agent's commit SHA in `application_version` or `applicationVersion`. You can also record `model_version` and `prompt_version` (`modelVersion` and `promptVersion` in TypeScript).

For runs that use multiple models, set `model_version` / `modelVersion` on each `EvaluationItem` to override the experiment's model. This requires `posthog` 7.76.0+ or `@posthog/ai` 8.17.0+.

Completing an experiment means the run finished, not that every case passed. To block a deployment, check scores against your own threshold in the test script and exit with a failure code.

`from_dataset_item()` / `fromDatasetItem()` copies the test case and its version into the experiment item. Always supply the new run's output. The dataset's `source_output` is an earlier answer.

By default, `snapshot()` selects the latest revision when you call it. To repeat an earlier test set, pass `revision=12` in Python or `{ revision: 12 }` as the second argument in TypeScript. The revision must still be available under the [dataset retention policy](/docs/ai-evals/datasets#data-retention).

## Add more scores

Use a separate scorer for each thing you want to measure, such as correctness, relevance, or whether the agent selected the right tool.

| Scorer type | Result value            | Example                                                 |
| ----------- | ----------------------- | ------------------------------------------------------- |
| Boolean     | `true` or `false`       | Did the agent complete the task correctly?              |
| Numeric     | A number                | How relevant is the answer, from zero to five?          |
| Categorical | A list of category keys | Which failure types occurred, such as `["wrong_tool"]`? |

Create scorers with the SDK or in [**Scorers**](https://app.posthog.com/ai-evals/evaluations/scorers). Each result references a fixed scorer version, so configuration changes don't reinterpret earlier results.

For each additional reported score, call `upload_result()` / `uploadResult()` with the same `EvaluationItem` and the new scorer's version ID. Include all reported and composite results in your expected result count.

Use `reasoning` to explain a score. Set `application_trace_id` / `applicationTraceId` on the item to link it to an [AI Observability trace](/docs/ai-observability/traces).

### Failed checks and evaluator errors

Use `value=False` / `value: false` for a failed check. The default status, `ok`, means the evaluator produced a score, not that the item passed.

If the evaluator can't produce a score, upload `status="error"` / `status: "error"`, omit `value`, and include an `error_message` / `errorMessage`. Use `skipped` for a check you didn't run, or `not_applicable` when a scorer doesn't apply to an item.

## Combine scores with a composite scorer

A composite scorer combines reported scores for one item into a boolean, numeric, or categorical result.

For the support-agent example, **Support task passed** requires both **Correct tool** and **Correct arguments** to pass. Three of the six cases pass both checks, giving a 50% pass rate.

### Create the composite

Use the latest SDK. Save this as `create_composite.py` or `create_composite.mts` and run it once with the quickstart's environment variables and existing scorers.

<MultiLanguage selector="tabs">

```python file=Python
import os
from posthog.ai.evaluations import OfflineEvaluations, ScorerComposition

with OfflineEvaluations(
    project_id=int(os.environ["POSTHOG_PROJECT_ID"]),
    secret_key=os.environ["POSTHOG_PERSONAL_API_KEY"],
    host=os.environ["POSTHOG_HOST"],
) as evaluations:
    tool = evaluations.scorers.get(os.environ["POSTHOG_TOOL_SCORER_ID"])
    arguments = evaluations.scorers.get(os.environ["POSTHOG_ARGUMENTS_SCORER_ID"])
    composition: ScorerComposition = {
        "expression": "tool_correct and arguments_correct",
        "inputs": [
            {"alias": "tool_correct", "scorer_version_id": tool.current_version_id},
            {
                "alias": "arguments_correct",
                "scorer_version_id": arguments.current_version_id,
            },
        ],
    }
    # Optional: check the formula without saving a scorer.
    evaluations.scorers.validate_composition(kind="boolean", composition=composition)
    composite = evaluations.scorers.create(
        name="Support task passed",
        kind="boolean",
        calculation="composite",
        config={"true_is_failure": False},
        composition=composition,
    )
    print(composite.id)
```

```typescript file=TypeScript
const evaluations = new OfflineEvaluations({
    projectId: Number(process.env.POSTHOG_PROJECT_ID),
    secretKey: process.env.POSTHOG_PERSONAL_API_KEY!,
    host: process.env.POSTHOG_HOST!,
})

try {
    const tool = await evaluations.scorers.get(process.env.POSTHOG_TOOL_SCORER_ID!)
    const argumentsScorer = await evaluations.scorers.get(
        process.env.POSTHOG_ARGUMENTS_SCORER_ID!
    )
    const composition = {
        expression: "tool_correct and arguments_correct",
        inputs: [
            { alias: "tool_correct", scorerVersionId: tool.currentVersionId },

    const composite = await evaluations.scorers.create({

        kind: "boolean",
        calculation: "composite",
        config: { trueIsFailure: false },
        composition,
    })

} finally {
    evaluations.close()
```

### Write formulas

These formulas use the two boolean inputs from the support-agent example:

| Output | Formula | Meaning |
| --- | --- | --- |
| Boolean | `tool_correct and arguments_correct` | Pass only when both checks are true. |
| Numeric | `(number(tool_correct) + number(arguments_correct)) / 2` | Return 0, 0.5, or 1 for each item. |
| Categorical | `"pass" if tool_correct and arguments_correct else "fail"` | Return a category key configured on the composite. |

Formulas read raw input values. `number(True)` is 1 and `number(False)` is 0, even if an input scorer treats `true` as a failure. For categorical inputs, test category keys with expressions such as `"helpful" in relevance`.

In the UI, the formula editor suggests a formula from the output type and inputs' passing rules. Manual edits stay unchanged when you edit inputs. Click **Use default formula** to restore the suggestion.

You can use arithmetic (`+`, `-`, `*`, `/`), comparisons, `and`, `or`, `not`, conditional expressions, and the `number`, `min`, `max`, and `abs` functions. Each formula can reference up to 16 reported scorer versions. Every selected input must appear in the formula. Composite scorers can't use other composites as inputs or combine results across different items.

### Handle missing inputs and calculation errors

If a pinned input result is missing, PostHog rejects the entire upload request. Include that input for the same item and version when you retry.

If an input has status `error`, `skipped`, or `not_applicable`, the composite inherits that status without a value. If several statuses apply, the order is `error`, then `skipped`, then `not_applicable`. Input errors use the code `composite_input_error`.

A calculation error, such as division by zero or a value outside the composite's configured bounds, produces an `error` result with code `composite_formula_error`. Valid reported inputs in the same request are still saved. These errors don't enter the composite's mean or pass rate.

## Use MCP

Use the [PostHog MCP server](/docs/model-context-protocol) to create scorers, manage datasets, and upload experiments from your AI agent. For composites, include the pinned inputs and a `calculate: true` request for each item.

## Data retention

PostHog deletes evaluation payloads 30 days after first accepting them:

| Data                                                                                    | Retention             |
| --------------------------------------------------------------------------------------- | --------------------- |
| Item inputs, actual outputs, expected outputs, and payload metadata                     | Deleted after 30 days |
| Result reasoning, error messages, and payload metadata                                  | Deleted after 30 days |
| Experiment, item, and result records, including scores, statuses, summaries, and trends | Kept                  |

Keep your own copy of payloads you need after 30 days. Source datasets have their own [retention policy](/docs/ai-evals/datasets#data-retention).

## Pricing

Each newly accepted reported scorer result for one experiment item counts as one AI Observability event. This includes reported results with status `error`, `skipped`, or `not_applicable`. Retrying the same result doesn't add another event.

Calculated composite results don't add billed events. For example, the six support-agent cases with two reported scorers and one composite produce 18 results and count as 12 events.

Offline evals share the [AI Observability event pricing and free tier](/pricing) with your other AI Observability events. They don't have a separate free allowance.
