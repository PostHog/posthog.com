title: PostHog Desktop skills

Skills give agents a repeatable way to complete specific work. Use one to apply your team's conventions, follow a proven debugging process, or handle a PostHog task without explaining the same steps in every prompt.

PostHog Desktop includes skills for common PostHog work. You can also install community skills, create your own, or share a skill with your team. Under the hood, each skill is a directory with a `SKILL.md` file.

## Get started

Open **Skills** from the left sidebar. Select a skill to read it. Use the **Installed**, **Team**, and **Marketplace** tabs to filter the list.

## Skill sources

| Source | Location |
|---|---|
| **Bundled** | Included with PostHog Desktop. PostHog skills cover instrumentation, Experiments, Data Warehouse, and AI Observability |
| **User** | `~/.claude/skills/` |
| **Repository** | `.claude/skills/` in a repository you add to PostHog Desktop |
| **Team** | Shared through your PostHog project |
| **Marketplace** | The [skills.sh](https://skills.sh) community index, installed in your user directory |

A directory with a valid `SKILL.md` and YAML `frontmatter` appears in Skills and is available to the agent.

Resources under `.pi/` belong to the [Pi harness](/docs/posthog-desktop/use-any-model-and-harness) and require repository trust. PostHog Desktop does not load them until you trust the repository. See [repository trust](/docs/posthog-desktop/mcp-servers#repository-trust-for-pi-servers).

Codex sessions also use bundled PostHog skills. PostHog Desktop mirrors them to `~/.agents/skills/` for the Codex CLI.

## Bundled skills

PostHog Desktop includes skills for common PostHog work:

- `instrument-product-analytics` for adding event capture
- `instrument-error-tracking` for adding error capture and source maps
- `instrument-feature-flags` for adding [Feature Flags](/docs/feature-flags)
- `creating-experiments` for setting up an A/B test
- `diagnosing-failed-warehouse-syncs` for debugging warehouse syncs
- `exploring-llm-traces` for investigating LLM traces

See [PostHog integration](/docs/posthog-desktop/posthog-integration) for the full list.

Bundled skills update separately from PostHog Desktop. You do not need an app update to receive them.

## Create a skill

Create a skill from the Skills view and edit it in PostHog Desktop. The editor includes a file tree and `frontmatter` editor. Save the skill in your user directory for personal use, commit it under `.claude/skills/` for repository use, or publish it to your team.

Keep skills narrow. Describe when to use the skill and list the steps or commands the agent should follow.

## Skill updates

Bundled skills update automatically without an app release. Changes to your own skills appear in the Skills view immediately.

A running task keeps the version it started with. Start a new task to use a skill you added or changed.

## Troubleshooting

### A skill is missing

Check that the skill:

- Is in a directory with `SKILL.md` at its root
- Starts with valid YAML `frontmatter`
- Defines at least `name` and `description`

PostHog Desktop skips skills with missing or invalid `frontmatter`.

### Repository skills do not load

Skills under `.claude/skills/` require the repository to be added to PostHog Desktop. Resources under `.pi/` also require repository trust. Look for the trust control above the composer.

### A changed skill does not affect a task

Start a new task. A task uses the skills available when it started.

### Bundled skills are out of date

Bundled skill updates need network access. When PostHog Desktop cannot check for an update, it keeps using the last version it downloaded.
