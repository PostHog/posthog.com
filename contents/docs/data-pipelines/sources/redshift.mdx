The Redshift connector can link your database tables to PostHog.

To link Redshift:

1. Go to the [Data pipeline page](https://app.posthog.com/data-management/sources) and the sources tab in PostHog
2. Click **New source** and select Redshift
3. Enter your database connection details:
   - **Host:** The hostname or IP of your Redshift cluster like `my-cluster.abc123.us-east-1.redshift.amazonaws.com`.
   - **Port:** The port your Redshift cluster is listening on. The default is `5439`.
   - **Database:** The name of the database you want like `analytics_db`.
   - **User:** The username with the necessary permissions to access the database.
   - **Password:** The password for the user.
   - **Schema:** (Optional) The schema for your database. Leave blank to browse and sync tables from all schemas, or specify one to limit the selection. The default is `public`.
4. Optionally, configure TLS certificate verification:
   - **Verify the server certificate?** Whether to check that your database's TLS certificate comes from a trusted authority and matches the host. Defaults to No.
   - **Certificate authority (optional):** The PEM certificate of the authority that signed your database's certificate. Add it when your database uses a private authority or a self-signed certificate. Adding a certificate authority automatically turns on certificate verification.
5. Click **Next**

The data warehouse then starts syncing your Redshift data. You can see details and progress in the [sources tab](https://app.posthog.com/data-management/sources).

> **Permissions:** The Redshift source only requires read permissions on the schemas and tables you intend to sync.

## TLS certificate verification

Redshift connections use TLS encryption by default (`sslmode=require`). You can optionally enable certificate verification to check that the server's TLS certificate is trusted and matches the host.

To enable certificate verification, set **Verify the server certificate?** to **Yes** in the source configuration. With verification on, PostHog checks:

- The certificate chain — that a trusted authority signed the server's certificate.
- The hostname — that the certificate matches the host you entered.

If you connect through an SSH tunnel, PostHog checks the certificate chain but not the hostname, because the tunnel presents the database on a local address.

### Using a custom certificate authority

If your database uses a private certificate authority or a self-signed certificate, paste the authority's PEM certificate into the **Certificate authority** field. Adding a certificate authority automatically turns on certificate verification, even if the toggle is set to No.

Without a custom authority, verification uses the system's default trusted certificates.

## Selecting columns

By default, PostHog syncs all columns from each table. To sync only specific columns:

1. During source setup, click **Columns** next to any table in the table picker.
2. Uncheck columns you don't want to sync.
3. Primary key columns and the incremental sync field (if configured) are always synced and cannot be disabled.

You can also change column selection after setup:

1. Go to the [sources tab](https://app.posthog.com/data-management/sources) and click your Redshift source.
2. Click **Configure** next to any schema.
3. Under **Columns**, select which columns to sync.

<CalloutBox icon="IconInfo" title="Adding columns to existing syncs" type="fyi">

When you add columns to a schema using incremental or append sync, PostHog prompts you to choose:

- **Sync forward only** - New columns are populated only for future data. Existing rows show `NULL` for the new columns.
- **Full resync** - Triggers a complete resync to backfill the new columns for all rows.
