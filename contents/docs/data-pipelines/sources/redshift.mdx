The Redshift connector can link your database tables to PostHog.

To link Redshift:

1. Go to the [Data pipeline page](https://app.posthog.com/data-management/sources) and the sources tab in PostHog
2. Click **New source** and select Redshift
3. Enter your database connection details:
   - **Host:** The hostname or IP of your Redshift cluster like `my-cluster.abc123.us-east-1.redshift.amazonaws.com`.
   - **Port:** The port your Redshift cluster is listening on. The default is `5439`.
   - **Database:** The name of the database you want like `analytics_db`.
   - **User:** The username with the necessary permissions to access the database.
   - **Password:** The password for the user.
   - **Schema:** (Optional) The schema for your database. Leave blank to browse and sync tables from all schemas, or specify one to limit the selection. The default is `public`.
   - **TLS fields:** (Optional) Verify the server certificate, or add a certificate authority. See [Verify the server certificate](#verify-the-server-certificate).
4. Click **Next**

The data warehouse then starts syncing your Redshift data. You can see details and progress in the [sources tab](https://app.posthog.com/data-management/sources).

> **Permissions:** The Redshift source only requires read permissions on the schemas and tables you intend to sync.

## Direct Redshift connections

Instead of syncing data on a schedule, you can query your Redshift database directly from the [SQL editor](https://app.posthog.com/sql).
Direct connections run queries against your live Redshift cluster in real time. PostHog does not copy any data.

### Creating a direct-only connection

To set up a direct connection:

1. Open the [SQL editor](https://app.posthog.com/sql).
2. Click the connection picker in the toolbar and select **Add direct connection** > **Redshift**.
3. Enter your Redshift credentials (host, port, database, user, password, and optionally a schema). These are the same credentials you use for scheduled syncs.
4. Select the tables you want to make available, then click **Link**.

Once connected, switch to your Redshift connection in the SQL editor's connection picker and write queries against your live data.

### Enabling live queries on a synced source

You can also enable live queries on a synced Redshift source. You then get scheduled syncs and live queries from the same source.

**When creating a new source:** In the source creation wizard, select **Sync and query live**.

**For an existing source:**

1. Go to the [sources tab](https://app.posthog.com/data-management/sources) and click your Redshift source.
2. Open the **Configuration** tab.
3. Turn on the **Enable live queries** toggle.
4. Click **Save changes**.

Once enabled, click **Query directly** on the **Schemas** tab to open the SQL editor with your source preselected.
In the SQL editor's connection picker, synced sources with live queries show a `· synced` label to distinguish them from direct-only connections.

### When to use direct connections vs scheduled syncs

- **Direct connections** are best for ad-hoc exploration, querying data that changes frequently, or when you don't want to duplicate data into PostHog.
- **Scheduled syncs** are better when you need faster query performance, want to join external data with PostHog events in dashboards and insights, or need data available across all PostHog features.

### Limitations

Direct Redshift queries are read-only.
A query that returns more than 1,000,000 rows fails, so add a `LIMIT` clause to large queries.
Some HogQL constructs are not supported and return a clear error if used:

- Arrays and array slices
- Lambdas
- Dicts
- Single-element tuples
- `TRY_CAST`
- `toStartOfISOYear`
- Conditional aggregate functions such as `countIf` and `sumIf`
- `startsWith`
- JSON property access with the `->` and `->>` operators. Use `JSONExtractString()` instead, which runs as Redshift's `json_extract_path_text`.

## Verify the server certificate

By default, PostHog encrypts the connection to your database but does not check its certificate. To make sure PostHog connects to your real database, set these fields when you link the source:

- **Verify the server certificate?** Checks that your database's TLS certificate comes from a trusted authority and matches the host you entered. Off by default.
- **Certificate authority (optional):** The PEM certificate of the authority that signed your database's certificate. Add it when your database uses a private authority or a self-signed certificate. Adding one turns on verification, even when the toggle above is off. Without it, PostHog checks against a standard set of public authorities.

Through an SSH tunnel, PostHog checks that the certificate comes from a trusted authority, but not that it matches the host. The tunnel presents your database on a local address, so the host name can't match.

If you leave all of these fields empty, the connection is encrypted but the certificate is not checked.

### Certificate errors

PostHog stops syncing on these errors, because retrying fails the same way until you change the source:

- "PostHog could not verify your database's TLS certificate. Either an authority PostHog trusts did not sign it, or it does not match the host. Add the authority that signed it, check the host, or turn off certificate verification and remove the certificate authority."
- "Your database's TLS certificate does not match the host you entered. Use the hostname the certificate was issued for, or turn off certificate verification and remove the certificate authority."

After you fix the certificate or the source settings, re-enable the sync.


## Selecting columns

By default, PostHog syncs all columns from each table. To sync only specific columns:

1. During source setup, click **Columns** next to any table in the table picker.
2. Uncheck columns you don't want to sync.
3. Primary key columns and the incremental sync field (if configured) are always synced and cannot be disabled.

You can also change column selection after setup:

1. Go to the [sources tab](https://app.posthog.com/data-management/sources) and click your Redshift source.
2. Click **Configure** next to any schema.
3. Under **Columns**, select which columns to sync.

<CalloutBox icon="IconInfo" title="Adding columns to existing syncs" type="fyi">

When you add columns to a schema using incremental or append sync, PostHog prompts you to choose:

- **Sync forward only** - New columns are populated only for future data. Existing rows show `NULL` for the new columns.
- **Full resync** - Triggers a complete resync to backfill the new columns for all rows.

</CalloutBox>

## Troubleshooting

### No primary key detected

For **Incremental replication**, open the table's sync method settings and select one or more **Primary key** columns. Choose columns whose combined values uniquely identify each row and contain no null values. You also need an incremental field to track new or updated rows.

Redshift [materialized views](https://docs.aws.amazon.com/redshift/latest/dg/materialized-view-create-sql-command.html) cannot declare primary keys. To sync a materialized view incrementally, select the key columns manually in PostHog. This selection does not add a constraint in Redshift.

Redshift [does not enforce primary key constraints](https://docs.aws.amazon.com/redshift/latest/dg/t_Defining_constraints.html), so check that the selected columns are unique even when PostHog detects a declared key.

If no columns uniquely identify each row, choose **Full table replication** (full refresh) instead.
