## Use anonymous events

PostHog captures two types of events: [**anonymous** and **identified**](/docs/data/anonymous-vs-identified-events). Under our current [pricing](/pricing), anonymous events can be up to 4x cheaper than identified ones (due to the cost of processing them), so it's recommended you only capture identified events when needed.

See our docs on [anonymous vs identified events](/docs/data/anonymous-vs-identified-events) for more information on the differences between them and how to capture them.

## Configure autocapture

[Autocapture](/docs/product-analytics/autocapture) is a powerful feature that captures many events automatically. It can also capture more than you need. To reduce which events are captured, you can [set an allow or ignore list](/docs/product-analytics/autocapture#configuring-interaction-autocapture).

Alternatively, you can [disable autocapture](/docs/product-analytics/autocapture#disabling-interaction-autocapture) completely.

## Only call `identify()` once per session

It's only necessary to [identify](/docs/product-analytics/identify) a user once per session. If the user is already identified, calling `identify()` again with the same distinct ID doesn't capture another `$identify` event. If you pass person properties, it captures a `$set` event instead, unless it already sent the same properties since the page loaded.

That check only lasts until the page reloads. On a multi-page site, or in any app that reloads the page, calling `identify()` with person properties on every page load sends a `$set` event on every page load. Each one is billed as an identified event.

To avoid this, call `identify()` without properties on page load, and send person properties only when they change, such as at login or when the user updates their profile. If you can't easily tell when properties change, keep a once-per-session check:

```js-web
const id = String(user.id)
const key = `${id}|${user.plan}`
let sent = false
try { sent = sessionStorage.getItem('ph_person_props') === key } catch (e) {}

if (sent) {
  posthog.identify(id) // already identified with these properties: sends nothing
} else {
  posthog.identify(id, { plan: user.plan })
  // only remember it if the event was actually sent (not before consent)
  if (!posthog.has_opted_out_capturing()) {
    try { sessionStorage.setItem('ph_person_props', key) } catch (e) {}
  }
}
```

To check whether this affects you, compare your `$set` and `$pageview` counts in a [trends insight](/docs/product-analytics/trends/overview). If you have nearly as many `$set` events as pageviews from logged-in users, you're probably resending properties on every page load.

## Only call `group()` once per session

In client-side SDKs, it's only necessary to call [`group()`](/docs/product-analytics/group-analytics) once per session. Prevent calling it multiple times to send fewer events and reduce costs.

    WHERE event = '$groupidentify'
      AND timestamp &gt;= now() - INTERVAL 30 DAY

    HAVING count() &gt; 1
  )
GROUP BY lib
ORDER BY groupidentify_event_count DESC
    GROUP BY $session_id
    HAVING count() > 1
  )
  AND timestamp >= now() - INTERVAL 30 DAY
  AND timestamp < now()
GROUP BY lib
ORDER BY groupidentify_event_count DESC
```

## Disable pageview or pageleave events

PostHog automatically captures pageviews and pageleaves. This is great for analytics, but it may capture more events than you need. An alternative is disabling these events and capturing them manually for the pages you need instead.

To disable automatically capturing these events, set `capture_pageview` and `capture_pageleave` to `false` in the configuration options when initializing PostHog:

```js
  posthog.init('<ph_project_token>', {
    api_host: '<ph_client_api_host>',
    defaults: '<ph_posthog_js_defaults>',
    capture_pageview: false,
    capture_pageleave: false,
  })
```

To manually capture these events, call `posthog.capture('$pageview')` and `posthog.capture('$pageleave')`.

> **Note:** Disabling pageview and pageleave events may prevent other PostHog features from working, like [bounce rate](/docs/data/events#how-events-power-posthog).
