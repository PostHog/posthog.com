The PostHog [MCP server](/docs/model-context-protocol) brings Workflows into Claude Code, Cursor, and other AI tools. It covers the full lifecycle - create a draft, edit its graph, test it, publish it, and read its stats and logs - so you can build and ship a workflow without leaving your editor. The `building-workflows` [agent skill](/docs/email/skills) teaches your agent how to use these tools.

The tools for senders, transactional email, email templates, broadcasts, message categories, opt-outs, suppressions, imports from other tools, and Supabase auth emails are in [Email & Messaging MCP tools](/docs/email/mcp).

## Before you start

1. **Set up Workflows** - Workflows are no-code, so there's nothing to install. [Install a PostHog SDK](/docs/email/installation#trigger-broadcasts-and-automations-from-events) if you want event-based triggers.
2. **Connect the MCP server** - [install it in your AI tool](#set-up) and give it access to your project.

Some tools are still rolling out, so your project might not have every tool below yet.

## Build workflows

- **Create and edit workflows.** `workflows-create` makes a draft, `workflows-patch-graph` and `workflows-update` change it, `workflows-patch-action-email` edits the email in one step, and `workflows-discard-draft` throws the draft away. Drafts can include any step, including [Replay Vision](/docs/workflows/replay-vision) and [AI tasks](/docs/workflows/ai-tasks).
- **Start from a suggestion.** `workflows-data-suggestions-list` suggests up to three workflows from your project's own events, `workflows-data-suggestions-create` builds one as a draft, and `workflows-data-suggestions-get` checks on the suggestions. `workflows-email-drafts-create` builds a draft email workflow for each event you pick.
- **Suggest a change for review.** `workflows-suggest` proposes a change to a workflow for a person to approve, and `workflows-list-proposals` lists the suggested changes.
- **Test and publish.** `workflows-test-run` runs a workflow without sending to real recipients, and `workflows-publish` makes the draft live.
- **Read and list.** `workflows-list` and `workflows-get` pull workflows into your session, and `workflows-update-schedule` changes when a scheduled workflow runs.
- **Organize with tags.** `workflows-create` and `workflows-update` accept a `tags` array to label workflows by team or topic, and `workflows-list` takes a `tags` filter to return only matching workflows.
- **Move between revisions.** `workflows-list-revisions`, `workflows-get-revision`, and `workflows-restore-revision` let you inspect history and roll back.
- **Import from Customer.io.** `workflows-import-customerio` turns Customer.io automations into draft workflows, and `workflows-import-notes` shows what the import changed or left out. See [migrate from Customer.io](/docs/email/migrate-from-customer-io).

## Read results and debug runs

- **Check performance.** `workflows-stats` reports on one workflow and `workflows-global-stats` across all of them. `workflows-list-versions` lists a workflow's published versions, and `workflows-version-stats` reports on one version, so you can compare a change with the version before it.
- **Debug a run.** `workflows-list-invocations`, `workflows-get-invocation`, `workflows-logs`, and `workflows-list-batch-jobs` show what actually happened on a given run.

For the full list of tools and how to scope a session to a subset, see the [MCP tools reference](/docs/model-context-protocol/tools).

## Drafts are the safety net

A workflow created over MCP is a draft. It does not run and nobody receives a message until it's published, so an agent can build the whole thing and hand it to you for review. Test it with `workflows-test-run` first, then publish - from MCP or from the [web app](/docs/workflows/surfaces/web-app).

## Set up

Connect the PostHog MCP server to your AI tool of choice, then grant it access to your project. The [MCP overview](/docs/model-context-protocol) covers install and authentication for each client.
