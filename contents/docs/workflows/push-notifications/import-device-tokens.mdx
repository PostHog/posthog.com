If you're moving to [Workflows](/docs/workflows) push notifications from another push provider, you can import the APNs device tokens and FCM registration tokens you already have. Imported devices can receive pushes right away, so users on older versions of your app don't need to open it again or update before they get notifications.

The mobile SDKs register new devices on their own. Use this import once, for devices that registered with your old provider before you added PostHog.

## Requirements

- A connected **APNs** or **FCM** channel. See [Configure a workflows channel](/docs/workflows/configure-channels?tab=Push). Import APNs tokens into your APNs channel and FCM tokens into your FCM channel.
- A [personal API key](/docs/api/personal-api-keys) with the `integration:write` scope. The key's user must be an admin of the project.
- For each device, the person's `distinct_id` in PostHog and the device token. Use the same `distinct_id` your app identifies the user with, so the imported device lands on the right person.

## Find your channel's ID

List your push channels with the API. Use `kind=apns` for APNs and `kind=firebase` for FCM:

```bash
curl "https://us.posthog.com/api/environments/<project_id>/integrations/?kind=apns" \
  -H "Authorization: Bearer <personal_api_key>"
```

Each result has an `id` and a `config` that shows the channel's bundle ID (APNs) or Firebase project ID (FCM). Pick the channel that matches your app. Use `eu.posthog.com` if your project is in the EU.

## Import tokens

Send up to 1,000 devices per request:

```bash
curl -X POST "https://us.posthog.com/api/environments/<project_id>/integrations/<channel_id>/push_tokens/" \
  -H "Authorization: Bearer <personal_api_key>" \
  -H "Content-Type: application/json" \
  -d '{
    "subscriptions": [
      { "distinct_id": "user_123", "device_token": "f1e2d3c4b5a6f1e2d3c4b5a6f1e2d3c4b5a6f1e2d3c4b5a6f1e2d3c4b5a6f1e2" },
      { "distinct_id": "user_456", "device_token": "a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2" }
    ]
  }'
```

The response says how many devices were stored and which people need to be sent again:

```json
{
    "imported": 2,
    "failed_distinct_ids": []
}
```

- A person with several devices gets one row per device.
- Sending the same row again is safe. It doesn't add a second device.
- Every token is stored encrypted on the person, the same way the SDK stores it.

## Import a large list

Split the list into batches of 1,000 and resend any rows whose `distinct_id` comes back in `failed_distinct_ids`. Imports are limited to 60 requests per minute per project. Above that the API answers `429` with a `Retry-After` header, so wait that many seconds and try again.

The script below does all of this. Rows that still fail after five attempts go into `not_imported.csv`, and the script exits with an error so you know the import isn't complete.

This Python script reads a CSV with `distinct_id` and `device_token` columns:

```python
import csv
import sys
import time

import requests

POSTHOG_HOST = "https://us.posthog.com"
PROJECT_ID = "<project_id>"
CHANNEL_ID = "<channel_id>"
PERSONAL_API_KEY = "<personal_api_key>"
BATCH_SIZE = 1000
ATTEMPTS = 5

url = f"{POSTHOG_HOST}/api/environments/{PROJECT_ID}/integrations/{CHANNEL_ID}/push_tokens/"
headers = {"Authorization": f"Bearer {PERSONAL_API_KEY}"}

with open("devices.csv", newline="") as f:
    rows = [{"distinct_id": r["distinct_id"], "device_token": r["device_token"]} for r in csv.DictReader(f)]

not_imported = []
for start in range(0, len(rows), BATCH_SIZE):
    batch = rows[start : start + BATCH_SIZE]
    for attempt in range(ATTEMPTS):
        try:
            response = requests.post(url, headers=headers, json={"subscriptions": batch}, timeout=(10, 60))
        except requests.RequestException:
            time.sleep(2**attempt)
            continue
        if response.status_code == 429:
            time.sleep(int(response.headers.get("Retry-After", "60")))
            continue
        if response.status_code >= 500:
            time.sleep(2**attempt)
            continue
        response.raise_for_status()
        failed = set(response.json()["failed_distinct_ids"])
        batch = [row for row in batch if row["distinct_id"] in failed]
        if not batch:
            break
        time.sleep(2)
    not_imported.extend(batch)
    print(f"Rows {start} to {min(start + BATCH_SIZE, len(rows))}: {len(batch)} not imported")

if not_imported:
    with open("not_imported.csv", "w", newline="") as f:
        writer = csv.DictWriter(f, fieldnames=["distinct_id", "device_token"])
        writer.writeheader()
        writer.writerows(not_imported)
    print(f"{len(not_imported)} rows not imported. Run the script again on not_imported.csv.")
    sys.exit(1)
```

## Billing

Each row you send is recorded on its person as one event, so an import of 10,000 devices counts as 10,000 events toward your [product analytics](/pricing) usage. Rows you send again count again.

## Check the import

Each device is stored as a `$device_push_subscription_…` person property. To count the people who have at least one device, run this in the [SQL editor](/docs/data-warehouse/sql):

```sql
SELECT count()
FROM persons
WHERE arrayExists(key -> startsWith(key, '$device_push_subscription_'), JSONExtractKeys(properties))
```

Then send a test push to one of them from a workflow that uses the same channel.
