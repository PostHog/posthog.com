Get a signed request on your own endpoint when a transactional email is sent, delivered, opened, clicked, bounced, marked as spam, or fails. Each request carries the message ID the send returned, so you can match it to your own records.

> Delivery webhooks are rolling out. If there's no **Webhooks** tab, your project doesn't have them yet.

## Add a webhook

1. Open [**Transactional**](https://app.posthog.com/transactional/webhooks) and go to the **Webhooks** tab.
2. If [engagement events](/docs/workflows/email/engagement-events) are off, click **Turn on engagement events**. Webhooks are sent from them, and they count toward your event usage.
3. Click **Add webhook**, and enter an **Endpoint URL** that starts with `https://`.
4. Pick the **Transactional emails** to watch, or leave it empty for all of them, including ones you add later.
5. Pick the **Events**, and add the webhook.
6. Copy the signing secret. You can't see it again.

Pause or delete a webhook from its menu in the list.

## Events

| Event | `type` |
| --- | --- |
| Sent | `email.sent` |
| Delivered | `email.delivered` |
| Opened | `email.opened` |
| Link clicked | `email.clicked` |
| Bounced | `email.bounced` |
| Marked as spam | `email.complained` |
| Failed | `email.failed` |

The names and shape follow common email provider webhooks, so a handler that you already have needs few changes.

## Payload

```json
{
  "type": "email.delivered",
  "created_at": "2026-11-26T09:15:02Z",
  "data": {
    "created_at": "2026-11-26T09:15:02Z",
    "email_id": "<message_id>",
    "template_id": "<template_id>",
    "template_key": null,
    "to": ["ada@example.com"],
    "subject": "Reset your password",
    "distinct_id": "user_123",
    "bounce": { "type": null, "subType": null },
    "click": { "link": null }
  }
}
```

- `email_id` is the message ID that the send returned.
- `template_id` or `template_key` is set, matching what the send used. The other is `null`.
- `bounce.type` is `Permanent`, `Transient`, or `Undetermined` on a bounce, and `bounce.subType` has the provider's detail.
- `click.link` is the clicked link on a click.
- `subject` is `null` for a [sensitive](/docs/workflows/transactional/sensitive-data) email.

Delivery webhooks cover transactional emails only, not broadcasts or automations.

## Verify the signature

Requests are signed with [Standard Webhooks](https://www.standardwebhooks.com), so any Standard Webhooks library can verify them. Each request has three headers:

- `webhook-id`: stays the same across retries, so use it to ignore duplicates.
- `webhook-timestamp`: Unix seconds.
- `webhook-signature`: `v1,` and a base64 HMAC-SHA256 of `{webhook-id}.{webhook-timestamp}.{body}`. The key is your secret without its `whsec_` prefix, base64-decoded.

```js
import { Webhook } from "standardwebhooks"

const wh = new Webhook(process.env.POSTHOG_WEBHOOK_SECRET)
const event = wh.verify(rawBody, request.headers) // throws if the signature is wrong
```

## Delivery

- Any response below `400` counts as received.
- PostHog retries `408`, `429`, `500`, `502`, `503`, and `504` responses, and network errors, a few times with backoff. It doesn't retry other responses.
- Respond quickly, and do slow work after you respond.
- Events can arrive out of order. Use `created_at` to sort them.
