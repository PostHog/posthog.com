Most transactional emails live in your code: your server sends the subject and body, rendered however you like, such as with [React Email](https://react.email). You get statuses, suppression checks, metrics, and the Log, with no template in PostHog. To let your team edit an email without a deploy, use a [template in PostHog](/docs/workflows/transactional/templates) instead.

| | Content from your code | Template in PostHog |
| --- | --- | --- |
| Who edits it | Engineers, in your codebase | Anyone, in PostHog, with no deploy |
| A send carries | `template_key`, `subject`, and `html` or `text` | `template_id` and `message_data` |
| Copies and files | `cc`, `bcc`, and [attachments](/docs/workflows/transactional/attachments) | No |

## Send it

Name the email with `template_key`, and send the content:

| Field | Required | What it does |
| --- | --- | --- |
| `template_key` | Yes | Names the email, such as `password-reset`. Use the same key every time, because PostHog groups its sends and metrics under it. Letters, digits, `-`, and `_`, up to 256 characters. |
| `to` | Yes | The recipient. |
| `subject` | Yes | The subject. |
| `html` or `text` | One of them | The body, up to 5 MiB each. PostHog sends it as written. Leave out `text` and PostHog makes it from `html`. |
| `distinct_id` | No | The user's distinct ID, so the send lands on their person. |
| `from` | No | Such as `Hedgebox <security@example.com>`, on a verified domain. Defaults to the project's default sender, or its only verified sender. |
| `reply_to` | No | Up to 10 addresses. |
| `cc` | No | Up to 10 addresses that get a copy. Plain addresses only, with no names. |
| `bcc` | No | Up to 10 addresses that get a hidden copy. Plain addresses only, with no names. |
| `attachments` | No | Files to attach. See [attachments](/docs/workflows/transactional/attachments). |
| `sensitive` | No | See [sensitive data and tracking](/docs/workflows/transactional/sensitive-data). |
| `tracking` | No | Turn opens, clicks, and engagement events on or off. |

A request has `template_id` or `template_key`, not both. A project can have up to 1,000 keys, so use one key for each kind of email, never one for each recipient.

## In PostHog

Each key shows up on the **Transactional emails** tab after its first send, with its sends and metrics. Click **Link source file** to link the email to the file in your repo that sends it. Then **Copy prompt for your agent** tells your coding agent which email to change, and where.

## React Email

The Node.js SDK renders React Email components for you, from version 5.69.0:

```bash
npm install posthog-node @react-email/render react react-dom
```

Pass the component as `react`, and the SDK renders the HTML and plain text:

```jsx
await posthog.emails.send({
    to: "ada@example.com",
    templateKey: "order-shipped",
    subject: "Your order shipped",
    react: <OrderShippedEmail firstName="Ada" trackingUrl={trackingUrl} />,
    distinctId: "user_123",
    idempotencyKey: `order-shipped-${orderId}`,
})
```

- **Next.js:** send from a route on the Node.js runtime. React Email doesn't render on the edge runtime.
- **Render it yourself:** to keep a copy of the HTML, call `render` and `toPlainText` from `@react-email/render`, and pass `html` and `text` instead.

| Error | Cause |
| --- | --- |
| `invalid_form` | The send has `react` and `html`, or `react` and `templateId`. Pass one. |
| `missing_react_renderer` | Install `@react-email/render` next to `posthog-node`. |
| `react_render_failed` | The component threw, or took longer than the request timeout, 15 seconds by default. `error.cause` has the component's error. |

## Checks

PostHog sends nothing when one of these checks fails. Each returns `400`.

| Code | Cause |
| --- | --- |
| `sender_not_verified` | No verified sender can send from `from`, or there's no `from` and no verified default sender. |
| `sensitive_template` | The send has `"sensitive": false`, but a sensitive template has the same key. |
| `too_many_keys` | The project has 1,000 keys, and this `template_key` is new. |
| `invalid_request` | `cc`, `bcc`, or `attachments` breaks a rule above. `attr` names the field. |
| A field code, such as `required` | Another field is missing or breaks a rule above. `attr` names it. |

See [retries and errors](/docs/workflows/transactional/retries-and-errors) for the errors every send can get.
