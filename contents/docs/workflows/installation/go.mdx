The [Go SDK](/docs/libraries/go) sends transactional emails. This page uses the v2 module, and every v2 release can send. On the v1 module, sending needs 1.40.0 or later. Before you start, you need a transactional email ([templates and variables](/docs/workflows/transactional/templates#create-a-transactional-email)) or content from your code, and a project secret API key ([create an API key](/docs/workflows/transactional/send-from-code#create-an-api-key)). The [quick start](/docs/workflows/installation) sets up both and sends a test email in a few minutes.

New to sending from code? Read [send emails from code](/docs/workflows/transactional/send-from-code) first.

## Install

```bash
go get github.com/posthog/posthog-go/v2
```

## Set up the client

Add your project secret API key to the PostHog client that your app already has. The project token keeps capturing events. The secret key sends email, so keep it on your server.

```go
import (
    "log"
    "os"

    "github.com/posthog/posthog-go/v2"
)

client, err := posthog.NewWithConfig("<ph_project_token>", posthog.Config{
    Endpoint:  "<ph_client_api_host>",
    SecretKey: os.Getenv("POSTHOG_PROJECT_SECRET_API_KEY"),
})
if err != nil {
    log.Fatal(err)
}
defer client.Close()
```

When `SecretKey` is set, the client also polls flag definitions with it for [local evaluation](/docs/feature-flags/local-evaluation). Give the key the **Feature flag** read scope too, or the client logs a failed poll each time it polls.

Close the client when your app exits, not after each send. If your app sends through a reverse proxy or a self-hosted PostHog, see [use a proxy or self-hosted PostHog](#use-a-proxy-or-self-hosted-posthog).

## Send an email

```go
func sendPasswordReset(ctx context.Context, client posthog.Client, userID, email, firstName, resetLink, resetRequestID string) (string, error) {
    result, err := client.Emails().Send(ctx, posthog.TemplateEmail{
        To:           email,
        TemplateID:   "<template_id>",
        TemplateData: map[string]interface{}{"first_name": firstName, "reset_link": resetLink},
        DistinctID:   userID,
        // Identifies this one email, so a retry never sends it twice
        IdempotencyKey: "password-reset-" + resetRequestID,
    })
    if err != nil {
        // A *posthog.EmailError. Branch on its Code
        return "", err
    }
    return result.ID, nil
}
```

`Send` returns a `*SendEmailResult` and an error. `result.ID` is the message ID. A result means PostHog queued the email, not that it delivered it. Every error is a `*posthog.EmailError`. Read it with `errors.As`, and branch on its `Code`, one of the codes in the [errors table](/docs/workflows/transactional/retries-and-errors#what-to-retry). A wrong argument, such as a template ID that isn't a UUID, returns an `EmailError` before any request.

A `network_error` or a `503` doesn't mean that the email failed, because PostHog can still have queued it. Retry with the same idempotency key. If you resend the email through another email provider, the recipient can get it twice.

### Fields

Fields marked "template only" work only with a template made in PostHog. Fields marked "code only" work only with content from your code. A `TemplateEmail` takes the template fields, and a `CodeEmail` takes the code fields.

| Field | Required | What it does |
| --- | --- | --- |
| `To` | Yes | The recipient's email address. |
| `TemplateID` | Yes, template only | The ID of the transactional email in PostHog. |
| `TemplateData` | No, template only | Values for the template's variables. |
| `DistinctID` | No | Links the email to your user's person in PostHog. |
| `IdempotencyKey` | No | Identifies this one email, so a retry never sends it twice. |
| `MaxRetries` | No | How many times the client retries this send. Takes a pointer, such as `posthog.Ptr(0)`. |
| `TemplateKey` | Yes, code only | Names the email, so PostHog groups its metrics and sends. |
| `Subject` | Yes, code only | The subject line. |
| `HTML` | At least one of `HTML` or `Text`, code only | The HTML body. |
| `Text` | At least one of `HTML` or `Text`, code only | The plain text body. PostHog makes it from `HTML` if you leave it out. |
| `From` | No, code only | The sender. Without it, PostHog uses the project's default sender. |
| `ReplyTo` | No, code only | A list of reply-to addresses. |
| `Cc` | No, code only | A list of copy addresses. |
| `Bcc` | No, code only | A list of blind copy addresses. |
| `Attachments` | No, code only | A list of `posthog.EmailAttachment` files. |
| `Sensitive` | No, code only | Marks the email as sensitive, for login links, reset tokens, or codes. |
| `Tracking` | No, code only | What PostHog tracks: opens, clicks, and engagement events. |

Every v2 release takes every field. On v1, `Sensitive` and `Tracking` need 1.43.0, and `Cc`, `Bcc`, and `Attachments` need 1.44.0.

### Timeouts and retries

The client retries for you. It retries network errors, rate limits, an in-flight idempotency key, and a `503` up to two times, with the same idempotency key. It waits about 1 second and then 2 seconds, or longer if the server's `Retry-After` asks for it. When `Retry-After` asks for more than 30 seconds, the client returns the error at once. Each request times out after 15 seconds.

To change this, set `EmailRequestTimeout` and `EmailRequestMaxRetries` in `posthog.Config`, or `MaxRetries` on one send. The retry settings take a pointer, so pass `posthog.Ptr(0)` to turn retries off.

## Send from a background job

Send from a job queue when the email shouldn't slow down the request, such as an email address check after a signup. Let the queue own the retries:

- Set `MaxRetries: posthog.Ptr(0)`, so that the client doesn't retry inside the job.
- Keep the idempotency key the same on every attempt.
- Finish the retries within 7 days. PostHog remembers an idempotency key for 7 days after it queues the email, so a later retry can send the email twice.
- Retry only the errors that a later attempt can fix. Every other code fails the same way again.

This example uses [River](https://riverqueue.com/docs), which keeps its jobs in Postgres. River retries a job when `Work` returns an error. `river.JobCancel` stops the job for good, even when it has attempts left.

```go
import (
    "context"
    "errors"
    "slices"

    "github.com/posthog/posthog-go/v2"
    "github.com/riverqueue/river"
)

// A later attempt can fix these. Any other code fails the same way again.
var retryableCodes = []string{"network_error", "idempotency_key_in_flight", "throttled", "delivery_unavailable"}

type PasswordResetArgs struct {
    UserID         string `json:"user_id"`
    Email          string `json:"email"`
    FirstName      string `json:"first_name"`
    ResetLink      string `json:"reset_link"`
    ResetRequestID string `json:"reset_request_id"`
}

func (PasswordResetArgs) Kind() string { return "password_reset_email" }

// Five attempts finish within minutes, well inside the 7 days that PostHog keeps an idempotency key
func (PasswordResetArgs) InsertOpts() river.InsertOpts { return river.InsertOpts{MaxAttempts: 5} }

type PasswordResetWorker struct {
    river.WorkerDefaults[PasswordResetArgs]
    PostHog posthog.Client
}

func (w *PasswordResetWorker) Work(ctx context.Context, job *river.Job[PasswordResetArgs]) error {
    args := job.Args
    _, err := w.PostHog.Emails().Send(ctx, posthog.TemplateEmail{
        To:           args.Email,
        TemplateID:   "<template_id>",
        TemplateData: map[string]interface{}{"first_name": args.FirstName, "reset_link": args.ResetLink},
        DistinctID:   args.UserID,
        // The same key on every attempt, so a retried job never sends the email twice
        IdempotencyKey: "password-reset-" + args.ResetRequestID,
        // River retries the job, so the client doesn't retry on its own
        MaxRetries: posthog.Ptr(0),
    })
    var emailErr *posthog.EmailError
    if errors.As(err, &emailErr) && !slices.Contains(retryableCodes, emailErr.Code) {
        // River doesn't run a cancelled job again
        return river.JobCancel(err)
    }
    return err
}
```

Register the worker with `river.AddWorker(workers, &PasswordResetWorker{PostHog: client})`.

## Link emails to your users

Pass the distinct ID that you pass to `identify()` as `DistinctID`, and leave it out for someone who isn't a user yet. See [link emails to your users](/docs/workflows/transactional/send-from-code#link-emails-to-your-users) for how PostHog records each case.

## Send content from your code

`Send` also takes a `CodeEmail`, with content that your code rendered and no template in PostHog. Render it first with your template engine, such as `html/template`.

```go
func sendPasswordReset(ctx context.Context, client posthog.Client, userID, email, html, resetRequestID string) (string, error) {
    result, err := client.Emails().Send(ctx, posthog.CodeEmail{
        To:             email,
        TemplateKey:    "password-reset",
        Subject:        "Reset your password",
        HTML:           html,
        From:           "Hedgebox <security@example.com>",
        DistinctID:     userID,
        IdempotencyKey: "password-reset-" + resetRequestID,
    })
    if err != nil {
        return "", err
    }
    return result.ID, nil
}
```

`CaptureEngagement` is deprecated. Set `Tracking: posthog.EmailTrackingWith(posthog.EmailTrackingOptions{Engagement: posthog.Ptr(false)})` instead, and don't set both.

See [content from your code](/docs/workflows/transactional/from-code) for what each field does and the checks PostHog runs.

### Copies and attachments

Each file in `Attachments` is a `posthog.EmailAttachment` with `Filename` and the file's bytes as `Content`, and can also have `ContentType` and `ContentID`. The client uploads each file before it sends the email, and checks the limits first. If an upload fails, `Send` returns an error, and PostHog sends nothing.

```go
_, err := client.Emails().Send(ctx, posthog.CodeEmail{
    To:          email,
    TemplateKey: "receipt",
    Subject:     "Your receipt",
    HTML:        html,
    Cc:          []string{"billing@example.com"},
    Attachments: []posthog.EmailAttachment{
        {Filename: "receipt.pdf", Content: pdfBytes, ContentType: "application/pdf"},
    },
    DistinctID: userID,
})
```

See [attachments](/docs/workflows/transactional/attachments) for the limits, inline images, and errors.

### Open and click tracking

To track the clicks of an email with no secrets:

```go
_, err := client.Emails().Send(ctx, posthog.CodeEmail{
    To:          "ada@example.com",
    TemplateKey: "order-shipped",
    Subject:     "Your order shipped",
    HTML:        html,
    Sensitive:   posthog.Ptr(false),
    Tracking:    posthog.EmailTrackingWith(posthog.EmailTrackingOptions{Clicks: posthog.Ptr(true)}),
})
```

`Tracking` takes `posthog.EmailTrackingOn()`, `posthog.EmailTrackingOff()`, or `posthog.EmailTrackingWith(...)` with `Opens`, `Clicks`, and `Engagement`. See [sensitive data and tracking](/docs/workflows/transactional/sensitive-data) for the defaults and rules.

## Check an email's status

```go
func emailBounced(ctx context.Context, client posthog.Client, messageID string) (bounced bool, known bool, err error) {
    status, err := client.Emails().Get(ctx, messageID)
    var emailErr *posthog.EmailError
    if errors.As(err, &emailErr) && emailErr.Code == "not_found" {
        // The first status can take a few seconds to arrive. Try again later.
        return false, false, nil
    }
    if err != nil {
        return false, false, err
    }
    return status.Status == "bounced", true, nil
}
```

`Get` returns an `*EmailStatus` with `ID`, `Status`, `CreatedAt`, `StatusAt`, and `Reason`.

The client doesn't retry a `not_found`, which you can get right after a send. Try again a few times with a short wait before you treat the email as missing.

See [status and troubleshooting](/docs/workflows/transactional/status) for what each status and reason means.

## Test without sending email

Start an `httptest.Server` and set its URL as both `Endpoint` and `AppHost`, to see exactly what your code sends with no request to PostHog. The server uses `http`, so also set `AllowInsecureAppHost`. This tests your integration, not delivery. To test delivery, send a real email to your own address and check the [**Log**](/docs/workflows/transactional#see-each-send) on the **Transactional** tab.

```go
package email_test

import (
    "context"
    "net/http"
    "net/http/httptest"
    "strings"
    "testing"

    "github.com/posthog/posthog-go/v2"
)

func TestSendPasswordReset(t *testing.T) {
    keys := make(chan string, 1)
    server := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        if !strings.HasSuffix(r.URL.Path, "/messaging/send/email/") {
            // The client also polls flag definitions here with the secret key
            http.NotFound(w, r)
            return
        }
        keys <- r.Header.Get("Idempotency-Key")
        w.WriteHeader(http.StatusAccepted)
        _, _ = w.Write([]byte(`{"message_id":"msg_1","replayed":false}`))
    }))
    defer server.Close()

    client, err := posthog.NewWithConfig("phc_test", posthog.Config{
        Endpoint:             server.URL,
        AppHost:              server.URL,
        SecretKey:            "phs_test",
        AllowInsecureAppHost: true, // The test server uses http
    })
    if err != nil {
        t.Fatal(err)
    }
    defer client.Close()

    result, err := client.Emails().Send(context.Background(), posthog.TemplateEmail{
        To: "jane@example.com",
        // The client checks that this is a UUID before it sends, so use any UUID
        TemplateID:     "0190f6d2-7c1e-7b3a-9f5e-1c2d3e4f5a6b",
        IdempotencyKey: "password-reset-1",
    })
    if err != nil {
        t.Fatal(err)
    }
    if result.ID != "msg_1" {
        t.Errorf("got message ID %q", result.ID)
    }
    if key := <-keys; key != "password-reset-1" {
        t.Errorf("got idempotency key %q", key)
    }
}
```

## Use a proxy or self-hosted PostHog

On PostHog Cloud, the client sends email to your region's app host, even when `Endpoint` is an ingestion host such as `us.i.posthog.com`. If `Endpoint` is a reverse proxy or a self-hosted PostHog, set `AppHost` to your PostHog app URL. It must use `https`. Without it, a send fails with `missing_app_host`. The client doesn't send email requests to a host that might be a proxy.

With `AppHost` set, every request that carries the secret key goes to `AppHost`, including flag definitions for local evaluation. Your proxy never sees the key.

From v2.1.1, the client sends email to `/api/messaging/`. A self-hosted PostHog needs a version from 2026-11-18 or later, or it answers with a `404`.
