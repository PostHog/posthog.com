Use the API to send transactional emails from any language. The SDKs for [Node.js](/docs/workflows/installation/node), [Python](/docs/workflows/installation/python), [Go](/docs/workflows/installation/go), [.NET](/docs/workflows/installation/dotnet), [Rust](/docs/workflows/installation/rust), [Ruby](/docs/workflows/installation/ruby), [Elixir](/docs/workflows/installation/elixir), and [PHP](/docs/workflows/installation/php) call this API and retry with idempotency keys for you. If your language has an SDK, start there. The examples on this page show each SDK next to cURL.

Your code sends the subject and HTML, so the email lives in your codebase. Before you start, you need a [verified sending domain](/docs/workflows/domain) and a [project secret API key](/docs/workflows/transactional/send-from-code#create-an-api-key). The [quick start](/docs/workflows/installation) sets up the key and sends a test email in a few minutes. New to sending from code? Read [send emails from code](/docs/workflows/transactional/send-from-code) first.

Each SDK page shows how to set up the client and handle errors.

- **Host** - The examples send to `https://us.posthog.com/api/messaging/send/email/`. Use `https://us.posthog.com` or `https://eu.posthog.com`, the host where you log in to PostHog. Don't use an ingestion host like `us.i.posthog.com`. If you self-host PostHog, use the URL of your instance.
- **Project** - The path has no project ID. PostHog sends from the project that the key belongs to.

### Request

Send these headers:

| Header | Value |
| --- | --- |
| `Authorization` | `Bearer` followed by your project secret API key |
| `Content-Type` | `application/json` |
| `Idempotency-Key` | Optional. 1 to 255 visible ASCII characters that identify this one email, so a retry never sends it twice. See [idempotency keys](/docs/workflows/transactional/retries-and-errors#idempotency-keys). |

Send a JSON body with these fields. Name the email with `template_key`, and send the content in the body. For a [React Email](https://react.email) component, render it to HTML with `render` from `@react-email/render`, and send the result as `html`.

| Field | Required | Description |
| --- | --- | --- |
| `template_key` | Yes | A name for this email, such as `password-reset`: up to 256 letters, digits, hyphens (`-`), and underscores (`_`). PostHog groups the metrics and the sends of this email under the key, so use the same key every time. A project can have up to 1,000 keys. |
| `to` | Yes | The recipient's email address. One address for each request. |
| `subject` | Yes | The subject line. |
| `html` | One of `html` and `text` | The HTML body, up to 5 MiB. PostHog sends it as you wrote it and fills no placeholders. |
| `text` | One of `html` and `text` | The plain text body, up to 5 MiB. If you leave it out, PostHog makes it from `html`. |
| `distinct_id` | No | The distinct ID of the recipient's person. PostHog records the email's [engagement events](/docs/workflows/email/engagement-events) on this person. See [link emails to your users](#link-emails-to-your-users). |
| `from` | No | The sender, as `security@example.com` or `Hedgebox <security@example.com>`, on a domain that your project verified. If you leave it out, PostHog uses the project's default sender, or its only verified sender when it has no default. |
| `reply_to` | No | A list of up to 10 addresses that replies go to, without a display name. |
| `sensitive` | No | `true` when the email carries login links, reset tokens, or codes. See [sensitive emails](#sensitive-emails). |
| `tracking` | No | What PostHog tracks: opens, clicks, and [engagement events](/docs/workflows/email/engagement-events). Send `true`, `false`, or an object. See [open and click tracking](#open-and-click-tracking). |
| `capture_engagement` | No | Deprecated. Send `"tracking": {"engagement": false}` instead. `false` still turns off engagement events for this email. A request can't have both `capture_engagement` and `tracking`. |

The body also takes [copies and attachments](#copies-and-attachments). To send a [template from PostHog](#send-a-template-from-posthog) instead, send `template_id` and `message_data` in place of `template_key`, `subject`, and the body.

### Response

A successful request returns `202 Accepted`:

```json
{
  "message_id": "01963d8a-6f2c-7d4e-9b1a-3c5e8f2a7b10",
  "replayed": false
}
```

A `202` means that PostHog queued the email, not that it was delivered. To see what happened to it, [check its status](#check-an-emails-status) with its `message_id`, or open the send in the [**Log**](/docs/workflows/transactional#see-each-send) tab.

`replayed` is `true` when an earlier request with the same `Idempotency-Key` already queued this email. PostHog then sends no new email, and `message_id` is the ID of the first send. A retry with the same `Idempotency-Key` counts as the [same request](/docs/workflows/transactional/retries-and-errors#idempotency-keys) when every field has the same value as in the first request.

When a send fails, the response carries a `code`. See [errors](/docs/workflows/transactional/retries-and-errors#what-to-retry), the [checks for content from your code](#checks-for-content-from-your-code), and the [checks for files](#checks-for-files). A `404` with the code `not_found` on every send means that the send API isn't on for your project yet.

### `delivery_unavailable`

A `503` with the code `delivery_unavailable` means that PostHog couldn't confirm that it queued the email. PostHog can still send it, so retry with the same `Idempotency-Key`. If you resend the email through another email provider, the recipient can get it twice. The SDKs retry a `503` for you.

### Sensitive emails

Mark the email as sensitive when it carries login links, reset tokens, or codes. For a sensitive email, PostHog:

- **Keeps links unchanged** - PostHog doesn't rewrite links to count clicks, so a token never goes through a tracking redirect. [`tracking`](#open-and-click-tracking) can still turn clicks on.
- **Leaves the subject off engagement events** - The email's [engagement events](/docs/workflows/email/engagement-events) don't carry its subject.
- **Keeps no copy of the content** - PostHog doesn't keep the email's subject or body.

`sensitive` takes `true` or `false`. If you leave it out, the email takes the [**Protect sensitive data**](/docs/workflows/transactional/sensitive-data) setting of the template in your project with the same key. When no template has the key, the email is sensitive.

Send `"sensitive": false` for an email that carries no secrets, such as an order confirmation, so that PostHog tracks its clicks. `sensitive` doesn't change opens or engagement events. When the template with the same key has **Protect sensitive data** on, PostHog refuses `"sensitive": false` with the code `sensitive_template`.

```json
{
  "template_key": "order-shipped",
  "to": "jane@example.com",
  "subject": "Your order is on its way",
  "html": "<p>Hi Jane, your order has shipped.</p>",
  "sensitive": false
}
```

### Open and click tracking

`tracking` decides what PostHog tracks for an email from your code. Send `true`, `false`, or an object with any of `opens`, `clicks`, and `engagement`:

| `tracking` | Opens | Clicks | Engagement events |
| --- | --- | --- | --- |
| Left out | On | See [clicks](#clicks-and-sensitive-emails) | On |
| `true` | On | On | On |
| `false` | Off | Off | Off |
| An object | `opens`, on by default | `clicks`, default as when left out | `engagement`, on by default |

- **Opens** - PostHog adds an open pixel to the email, so it can count opens.
- **Clicks** - PostHog rewrites the email's links to go through a tracking redirect, so it can count clicks.
- **Engagement events** - PostHog captures the email's [engagement events](/docs/workflows/email/engagement-events), such as sent, opened, and clicked, on the recipient's person. If the project's **Capture email engagement events** setting is off, PostHog captures nothing, whatever you send.

A key that you leave out of the object keeps its default, so `{}` is the same as leaving out `tracking`.

#### Clicks and sensitive emails

A tracked link goes through a redirect, so a login link or a reset token in it goes through the redirect too. When you leave out `clicks`, PostHog follows the click tracking setting of the template with the same key, if it has one. Otherwise, it tracks clicks only for an email that isn't [sensitive](#sensitive-emails).

- **An email without secrets** - Send `"sensitive": false`, and PostHog tracks its clicks.
- **A sensitive email with safe links** - Send `"tracking": {"clicks": true}` or `"tracking": true`. PostHog tracks its clicks and keeps the email's other protections.
- **Links that must stay unchanged** - Send `"tracking": {"clicks": false}`.

A `clicks` value that you send wins over `sensitive`. To keep one link unchanged, add `data-ph-no-track` or `clicktracking="off"` to its `<a>` tag, as for [workflow emails](/docs/workflows/transactional/sensitive-data#tracking).

#### Turn tracking off

With `"tracking": false`, the email goes out without the open pixel and without rewritten links, and PostHog captures no engagement events for it. You can still [read the email's status](#check-an-emails-status). `false` also turns off any kind of tracking that PostHog adds later.

```json
{
  "template_key": "welcome",
  "to": "jane@example.com",
  "subject": "Welcome to Hedgebox",
  "html": "<p>Hi Jane, welcome to Hedgebox.</p>",
  "tracking": false
}
```

In a form-encoded request, `tracking` and `sensitive` take `true` or `false`. Send JSON to use the `tracking` object.

#### Requests that PostHog refuses

PostHog returns a `400` and sends nothing when:

- **An unknown key** - The object has a key other than `opens`, `clicks`, and `engagement`.
- **Clicks without opens** - `opens` is `false` and `clicks` is `true`. Click tracking needs open tracking. With `opens` set to `false` and `clicks` left out, PostHog tracks no clicks.
- **Both fields** - The request has `tracking` and `capture_engagement`. Move the value of `capture_engagement` to `tracking.engagement`.
- **A [template send](#send-a-template-from-posthog)** - The request has `template_id` and `tracking` or `sensitive`. A template uses its own settings.

### Copies and attachments

A send also takes these fields. A [template send](#send-a-template-from-posthog) takes none of them.

| Field | Required | Description |
| --- | --- | --- |
| `cc` | No | One address or a list of up to 10 that get a copy, without a display name. |
| `bcc` | No | One address or a list of up to 10 that get a hidden copy, without a display name. The other recipients don't see them. |
| `attachments` | No | A list of up to 10 files that you [uploaded first](#send-files). Each file is an object with `sha256`, `filename`, and optionally `content_type`, such as `application/pdf`, and `content_id`. |

- **Size** - An email can have 10 files and 40 MB after Base64 encoding, about 29 MB of files. Base64 makes each file about a third larger, and the HTML and text count too. One file can use all of the limit.
- **Inline images** - Set `content_id` on a file, and use it in the HTML as `<img src="cid:logo">`.
- **Content type parameters** - `content_type` can have parameters after the type. For a calendar invite, add `method=REQUEST`, so that mail apps can show the file as an invitation, not as a plain file:

  ```json
  {
    "sha256": "1c54c1de7da52dae1aa7c8caea31c87272055e3f5308b8a81b456bce26c721ba",
    "filename": "invite.ics",
    "content_type": "text/calendar; charset=utf-8; method=REQUEST"
  }
  ```

  PostHog refuses a `name` or `filename` parameter, because the file name comes from `filename`.
- **Blocked files** - PostHog refuses file types that mailbox providers block, such as `.exe`, and a filename with a path.
- **Viruses** - PostHog's email provider scans each file. If it finds a virus, the email gets the status `failed` with the reason `provider_rejected`.
- **SDKs** - The SDKs hash, upload, and attach the files for you. Give each file's bytes to the SDK.
- **Older self-hosted PostHog** - A version that doesn't take these fields refuses the send with a `400` that names the field. It never sends the email without the field.

### Send files

The files of an email go to PostHog before the email. The SDKs do these steps for you. With the API, do them yourself:

1. **Hash each file.** Get the SHA-256 of the file's bytes, as 64 lowercase hex characters, and the file's size in bytes.
2. **Ask where to upload.** Send the hash and the size of each file to the [upload route](#ask-where-to-upload). PostHog answers `present` for a file that it already has, and `upload` with a URL for each other file.
3. **Upload the files.** Send the bytes of each `upload` file to its URL. Don't send your PostHog API key with the upload.
4. **Send the email.** When all uploads succeed, send the email with the `sha256` and the `filename` of each file in `attachments`.

Ask where to upload before each send, also for a file that you sent before. A file that you send to many recipients, such as your terms, uploads only once while PostHog still has it.

#### Ask where to upload

```
POST https://us.posthog.com/api/messaging/attachments/uploads/
```

Send the `Authorization` and `Content-Type` headers of a [send](#request). The key needs the `transactional_email:write` scope. Send a JSON body with a `files` list of 1 to 10 files, all for one email:

| Field | Required | Description |
| --- | --- | --- |
| `sha256` | Yes | The SHA-256 of the file's bytes, as 64 lowercase hex characters. |
| `size` | Yes | The size of the file in bytes, at least 1. |

```bash
curl -X POST "https://us.posthog.com/api/messaging/attachments/uploads/" \
  -H "Authorization: Bearer $POSTHOG_PROJECT_SECRET_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "files": [
      {"sha256": "d00ca3c2296eace098658a8576dafec8a959f5da536a51c8f9d060c00e427252", "size": 48213},
      {"sha256": "aba4cc7ef2a4423000b9ec5269993717c92b29f092eac5b791c7e9ce24a69306", "size": 120544}
    ]
  }'
```

A successful request returns `200`, with one answer for each file, in the order of the request:

```json
{
  "files": [
    {
      "sha256": "d00ca3c2296eace098658a8576dafec8a959f5da536a51c8f9d060c00e427252",
      "status": "upload",
      "url": "https://<bucket>.s3.us-east-1.amazonaws.com/<key>?X-Amz-Algorithm=AWS4-HMAC-SHA256&...",
      "method": "PUT",
      "headers": {
        "Content-Length": "48213",
        "x-amz-checksum-sha256": "0AyjwilurOCYZYqFdtr+yKlZ9dpTalHI+dBgwA5CclI="
      },
      "url_expires_at": "2026-11-10T09:15:00Z"
    },
    {
      "sha256": "aba4cc7ef2a4423000b9ec5269993717c92b29f092eac5b791c7e9ce24a69306",
      "status": "present",
      "expires_at": "2026-12-16T09:00:00Z"
    }
  ]
}
```

- **`present`** - Your project uploaded this file before. Upload nothing. `expires_at` is when PostHog deletes the file if no send uses it before then.
- **`upload`** - Send the file's bytes to `url`, with `method` and the `headers` exactly as given, before `url_expires_at`. The URL is valid for 15 minutes. The file counts toward your project's daily upload limit when PostHog gives you the URL, even if you don't upload it, so upload each file soon after you ask.

#### Upload a file

```bash
curl -X PUT "<url>" \
  -H "Content-Length: 48213" \
  -H "x-amz-checksum-sha256: 0AyjwilurOCYZYqFdtr+yKlZ9dpTalHI+dBgwA5CclI=" \
  --data-binary @invoice-1042.pdf
```

A successful upload returns `200`. It fails with a `400` or a `403` when the bytes don't match `size` and `sha256`, when a header isn't as given, or when the URL expired. Ask where to upload again to get a new URL. Don't send the email until all uploads succeed.

#### Allow the upload host

Uploads go to Amazon S3, not to the PostHog host, from the SDKs too. If your network limits outgoing traffic, let your servers connect with HTTPS to the host of `url`:

| PostHog Cloud | Upload host |
| --- | --- |
| US | A host that ends in `.s3.us-east-1.amazonaws.com` |
| EU | A host that ends in `.s3.eu-central-1.amazonaws.com` |

#### Send the email with its files

```bash
curl -X POST "https://us.posthog.com/api/messaging/send/email/" \
  -H "Authorization: Bearer $POSTHOG_PROJECT_SECRET_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: receipt-1042" \
  -d '{
    "to": "jane@example.com",
    "template_key": "receipt",
    "subject": "Your receipt for order 1042",
    "html": "<p>Thanks for your order. Your invoice and our terms are attached.</p>",
    "attachments": [
      {"sha256": "d00ca3c2296eace098658a8576dafec8a959f5da536a51c8f9d060c00e427252", "filename": "invoice-1042.pdf", "content_type": "application/pdf"},
      {"sha256": "aba4cc7ef2a4423000b9ec5269993717c92b29f092eac5b791c7e9ce24a69306", "filename": "terms.pdf", "content_type": "application/pdf"}
    ]

```

### Checks for files

These checks apply to the upload route and to sends with `attachments`, in addition to the [errors](/docs/workflows/transactional/retries-and-errors#what-to-retry) of every send. After a `400`, a `404`, or a `429`, PostHog sends nothing. The body of a `400` or a `429` also has `why` and `fix`, which tell you the cause and what to do.

| Status | Code | Route | Cause | What to do |
| --- | --- | --- | --- | --- |
| `400` | `field_not_accepted` | Both | PostHog can't send files for your project yet. | Send the email without files. |
| `404` | `not_found` | Upload | Content from your code is off for your project, or your PostHog version has no upload route. | Send the email without files. |
| `400` | `too_many_attachments` | Both | The email has more than 10 files. | Send 10 files at most. Link to other files from the email body. |
| `400` | `message_too_large` | Both | The email is over 40 MB after Base64 encoding. On the upload route, `attr` names the largest file, such as `files__1__size`. | Send fewer or smaller files, or link to large files from the email body. |
| `400` | `attachment_not_uploaded` | Send | Your project has no uploaded file with this SHA-256. The upload didn't finish, the file expired, or a different project uploaded it. `attr` names the file, such as `attachments__0__sha256`. | Ask where to upload again, upload the file, and send the email again. |
| `400` | `blocked_file_type` | Send | Mailbox providers block this file type, such as `.exe`. | Send a different file type, or link to the file from the email body. |
| `400` | `unsafe_filename` | Send | `filename` has a path or a line break. | Send only the file name, such as `invoice.pdf`. |
| `400` | `not_mime_type` | Send | `content_type` isn't a MIME type, or it has a `name` or `filename` parameter. | Send a type such as `application/pdf` or `text/calendar; method=REQUEST`, or leave out `content_type`. Set the file name in `filename`. |
| `400` | `unsafe_content_id` | Send | `content_id` has `<`, `>`, or a line break. | Send only the ID, such as `logo`. |
| `400` | `content_too_large` | Both | The request body is over 20 MB. | Make the request smaller. Files go to the upload URL, never in the request body. |
| `429` | `upload_quota_exceeded` | Upload | Your project asked to upload all the file bytes that it can upload today. A file counts when PostHog gives you its upload URL, even if you don't upload it, and again each time that you ask for a new URL. The day starts at midnight UTC. | Send files that PostHog already has, because they don't count. Link to new files from the email body. Or ask again after midnight UTC. |
| `503` | `delivery_unavailable` | Both | PostHog couldn't get to its file storage. On a send, it can also mean that PostHog couldn't confirm that it queued the email, so PostHog can still send it. See [`delivery_unavailable`](#delivery_unavailable). | Send the same request again after a short wait. For a send, use the same `Idempotency-Key`, so that the email doesn't go out twice. |

Other problems with `attachments` or `files`, such as a hash that isn't 64 lowercase hex characters, return the code `invalid_request`, and `attr` names the field.

### Checks for content from your code

These checks apply to content from your code, in addition to the [errors](/docs/workflows/transactional/retries-and-errors#what-to-retry) of every send. PostHog sends nothing when a check fails.

| Status | Code | Cause | What to do |
| --- | --- | --- | --- |
| `400` | A code for the field, such as `required` or `invalid` | A field is missing or breaks a rule above, or PostHog doesn't take the field. The `type` is `validation_error`, and `attr` names the field, such as `subject`. | Fix the field. If the field comes from a newer SDK, update PostHog or leave the field out. |
| `400` | `sender_not_verified` | No verified sender of the project can send from the `from` address. Or the request has no `from`, and the project has no verified sender. | Send from an address on a verified domain, or [verify a domain](/docs/workflows/domain). |
| `400` | `sender_required` | The request has no `from`, and the project has more than one verified sender and no default sender. | Send `from`, or set a default sender. |
| `400` | `sensitive_template` | The request has `"sensitive": false`, and the template with the same key has **Protect sensitive data** on. | Leave out `sensitive`, or turn off the template's setting. |
| `400` | `too_many_keys` | The `template_key` is new, and the project already has 1,000 keys. | Reuse one key for each type of email. |

## Link emails to your users

Pass the distinct ID that you pass to `identify()` as `distinct_id`. This is usually your user's ID. PostHog then records the email's [engagement events](/docs/workflows/email/engagement-events), such as sent, opened, and clicked, on that user's person, in the same timeline as their product events.

- **No distinct ID** - PostHog records the email on a person whose distinct ID is the email address. That's a different person from your user, unless your app identifies users by their email address.
- **Not a user yet** - For an invite, or an email address check before the account exists, leave `distinct_id` out.

## Send a template from PostHog

You can also keep an email in PostHog as a [template](/docs/workflows/transactional/templates#create-a-transactional-email), so your team edits the copy without a deploy. Use the same route and headers. Send these fields in place of `template_key`, `subject`, and the body:

| Field | Required | Description |
| --- | --- | --- |
| `template_id` | Yes | The ID of the transactional email to send. |
| `message_data` | No | An object with the values for the template's `{{ variables.* }}` placeholders. For example, `{"reset_link": "https://example.com/reset"}` fills `{{ variables.reset_link }}`. The template can't read person properties, so pass all the data that the email needs here. |

`to` and `distinct_id` work as for any send. In the template, use the same names that you send in `message_data`:

```liquid
Hi {{ variables.first_name }}, use this link to reset your password: {{ variables.reset_link }}
```

```bash
curl -X POST "https://us.posthog.com/api/messaging/send/email/" \
  -H "Authorization: Bearer $POSTHOG_PROJECT_SECRET_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: password-reset-8f14e45f" \
  -d '{
    "template_id": "<template_id>",
    "to": "jane@example.com",
    "distinct_id": "user_123",
    "message_data": { "first_name": "Jane", "reset_link": "https://example.com/reset?token=abc123" }
  }'
```

A request has `template_id` or `template_key`, not both. Content from your code takes no `message_data`, because PostHog fills no placeholders. A template send takes no field of the [request table](#request) other than `to` and `distinct_id`, and no [copies or attachments](#copies-and-attachments), because the template uses its own settings. PostHog refuses a field in the wrong kind of send with a `400` that names the field in `attr`.

## Check an email's status

To find out what happened to an email, read its status with the `message_id` from the send:

<MultiLanguage selector="tabs">

```bash file=REST
curl "https://us.posthog.com/api/messaging/emails/<message_id>/" \
  -H "Authorization: Bearer $POSTHOG_PROJECT_SECRET_API_KEY"
```

```js file=Node.js
const { data: status, error } = await posthog.emails.get("<message_id>")
```

```python file=Python
status = posthog.emails.get("<message_id>")
```

```go file=Go
status, err := client.Emails().Get(ctx, "<message_id>")
```

```csharp file=.NET
var status = await posthog.Emails.GetAsync("<message_id>");
```

```rust file=Rust
let status = posthog.emails().get("<message_id>").await?;
```

```ruby file=Ruby
status = posthog.emails.get('<message_id>')
```

```elixir file=Elixir
{:ok, status} = PostHog.Emails.get("<message_id>")
```

```php file=PHP
$status = PostHog::emails()->get('<message_id>');
```

</MultiLanguage>

The examples read `https://us.posthog.com/api/messaging/emails/<message_id>/`. Send the same `Authorization` header as for a send. Only a project secret API key can read a status, and it needs the `transactional_email:read` or `transactional_email:write` scope. A key with a `hog_flow` scope still works.

A found email returns `200`:

```json
{
  "id": "01963d8a-6f2c-7d4e-9b1a-3c5e8f2a7b10",
  "status": "delivered",
  "created_at": "2026-10-28T16:27:44.364000Z",
  "status_at": "2026-10-28T16:27:49.625000Z",
  "reason": null
}
```

See [statuses and reasons](/docs/workflows/transactional/status) for what each value means.

A `404` with the code `not_found` right after a send means that the status isn't there yet. A new send can take a few seconds to get its first status, so retry after a short wait. Later, a `404` means that the email is older than 30 days or the ID is wrong. See [check a status](/docs/workflows/transactional/status#check-a-status). The route returns `401` when the request has no project secret API key, `403` when the key doesn't have the scope, and `429` when you read too often.

If you lost the response of a send, read the status by its idempotency key instead: `GET https://us.posthog.com/api/messaging/emails/status/?idempotency_key=<key>`. It answers the same way, for the latest send with that key.

Each project secret API key can read 600 statuses per minute and 20,000 per hour, and all the keys of one project share those limits. Reads have their own limits, so they don't use up the limits for sends.
