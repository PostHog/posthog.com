The [Elixir SDK](/docs/libraries/elixir) sends transactional emails from version 2.19.0. Before you start, [create a transactional email](/docs/workflows/transactional-emails#create-a-transactional-email) and [create a project secret API key](/docs/workflows/transactional-emails#create-an-api-key).

## Install

Add `posthog` to your list of dependencies in `mix.exs`:

```elixir
def deps do
  [
    {:posthog, "~> 2.19"}
  ]
end
```

## Set up the client

Set `secret_key` to your project secret API key in the PostHog config your application already has. The SDK still captures events with your project token. Keep the key out of your source code:

```elixir file=config/runtime.exs
config :posthog,
  api_host: "<ph_client_api_host>",
  api_key: "<ph_project_token>",
  secret_key: System.fetch_env!("POSTHOG_PROJECT_SECRET_API_KEY")
```

- **Local evaluation:** When `secret_key` is set, the SDK also loads flag definitions with it for [local evaluation](/docs/feature-flags/local-evaluation) when it starts. Give the key the **Feature flag** read scope too, or set `enable_local_evaluation: false`.
- **Host:** On PostHog Cloud, the SDK sends email to the app host of your region, even when `api_host` is an ingestion host such as `us.i.posthog.com`. For any other host, such as a reverse proxy or a self-hosted instance, set `app_host` to your PostHog app URL. Email requests never go to a host that might be a proxy. Flag definitions for local evaluation still load from `api_host` with the secret key, so set `enable_local_evaluation: false` when the proxy must not see the key.

## Send an email

```elixir
def send_password_reset(user, reset_link, reset_request_id) do
  # Returns {:error, %PostHog.Emails.Error{}} when PostHog doesn't queue the email.
  # Branch on error.code.
  with {:ok, result} <-
         PostHog.Emails.send(
           to: user.email,
           template_id: "<template_id>",
           template_data: %{first_name: user.first_name, reset_link: reset_link},
           distinct_id: to_string(user.id),
           # Identifies this one email, so a retry never sends it twice
           idempotency_key: "password-reset-#{reset_request_id}"
         ) do
    {:ok, result.id}
  end
end
```

`send/2` returns `{:ok, %PostHog.Emails.SendResult{}}`, and `result.id` is the message ID. A send that PostHog doesn't queue returns `{:error, %PostHog.Emails.Error{}}`, with the `code` from the [errors table](/docs/workflows/transactional-emails#errors). A wrong option returns an error with an `invalid_*` code before any request. After a `network_error` or a `503`, PostHog might have queued the email. Retry with the same idempotency key rather than sending the email through another provider, or the recipient can get it twice.

To send through a PostHog instance other than the default one, pass its name first: `PostHog.Emails.send(MyPostHog, options)`.

### Timeouts and retries

Each request times out after 15 seconds. The SDK retries network errors, rate limits, an in-flight idempotency key, and a `503` up to two times, with the same idempotency key. It waits about 1 and then 2 seconds, or longer if the server's `Retry-After` asks for it. A `Retry-After` over 30 seconds returns the error at once. A send blocks the calling process until it finishes.

To change this, set `email_request_timeout_ms` and `email_request_max_retries` in the config, or `max_retries` on one send. When a job queue such as Oban already retries the send, set the retries to `0` and pass an `idempotency_key` that identifies the email.

## Link emails to your users

Pass the distinct ID that you pass to `identify()`, usually the ID your app gives that user, as `distinct_id`. PostHog then records the send, and its [engagement events](/docs/workflows/engagement-events) such as sent, opened, and clicked, against that user's person, next to their product events. The SDK doesn't take it from `PostHog.set_context/2`.

- **If you leave it out,** PostHog records the email against a person whose distinct ID is the recipient's email address. Unless your app identifies users by their email address, that's a separate person from your user.
- **For someone who isn't a user yet,** such as an invite or an email address check before the account exists, there's no distinct ID to pass. Leave `distinct_id` out.

## Send content from your code

`send/2` also takes content that your code rendered, without a template in PostHog. Name the email with `template_key`, and pass `subject` and `html`, `text`, or both. PostHog sends the content as you wrote it, so render it with your template engine first, such as EEx or Phoenix templates.

```elixir
def send_password_reset(user, html, reset_request_id) do
  with {:ok, result} <-
         PostHog.Emails.send(
           to: user.email,
           template_key: "password-reset",
           subject: "Reset your password",
           html: html,
           from: "Hedgebox <security@example.com>",
           distinct_id: to_string(user.id),
           idempotency_key: "password-reset-#{reset_request_id}"
         ) do
    {:ok, result.id}
  end
end
```

- **Key:** `template_key` names the email, such as `password-reset`. PostHog groups the email's metrics and sends under it, so use the same key every time you send this email.
- **Text:** If you leave out `text`, PostHog makes it from `html`.
- **Sender:** `from` needs an address on a domain that your project verified. Without it, PostHog uses the project's default sender. `reply_to` takes one address or a list.
- **Engagement:** PostHog captures the email's engagement events unless you pass `capture_engagement: false`.
- **One form per send:** A send has `template_id` or `template_key`, not both. Content from your code takes no `template_data`, because PostHog renders nothing.

See [content from your code](/docs/workflows/transactional-emails/api#send-content-from-your-code) for each field and its checks.

### Copies and attachments

<CalloutBox icon="IconInfo" title="Coming in a later SDK version" type="fyi">

Copies and attachments aren't in a released version of the Elixir SDK yet. This section shows how they will work.

</CalloutBox>

Content from your code will take `cc`, `bcc`, and `attachments`. `cc` and `bcc` take one address or a list of plain addresses. Each attachment is a map with `filename` and the file's bytes as `content`, and optionally `content_type`. The SDK encodes the bytes for you.

```elixir
PostHog.Emails.send(
  to: user.email,
  template_key: "receipt",
  subject: "Your receipt",
  html: html,
  cc: "billing@example.com",
  attachments: [
    %{filename: "receipt.pdf", content: File.read!(pdf_path), content_type: "application/pdf"}
  ],
  distinct_id: to_string(user.id)
)
```

See [copies and attachments](/docs/workflows/transactional-emails/api#copies-and-attachments) for the limits.

## Check an email's status

```elixir
def email_bounced(message_id) do
  case PostHog.Emails.get(message_id) do
    {:ok, %PostHog.Emails.Status{status: status}} ->
      {:ok, status == "bounced"}

    # The first status can take a few seconds to arrive. Try again later.
    {:error, %PostHog.Emails.Error{code: "not_found"}} ->
      {:ok, nil}

    {:error, error} ->
      {:error, error}
  end
end
```

`get/2` returns `{:ok, %PostHog.Emails.Status{}}` with `id`, `status`, `created_at`, `status_at`, and `reason`. See [statuses and reasons](/docs/workflows/transactional-emails#check-an-emails-status). The SDK doesn't retry a `not_found`, so retry it yourself a few times, with a wait in between, before you treat the email as missing. A status that isn't there yet doesn't mean the email failed.
