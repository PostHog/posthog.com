If you capture events with PostHog, your people are already here. You move what's around them: opt-outs, suppressions, automations, and push devices. Automations import as drafts, and never send until you turn them on.

## What moves

| From Customer.io | In PostHog |
| --- | --- |
| Subscription topics | Marketing [categories](/docs/workflows/email/opt-outs) |
| Global unsubscribes and topic preferences | Opt-outs |
| Bounced and invalid addresses | [Suppression list](/docs/workflows/email/suppression). Blocks all email. |
| Spam reports | Suppression list. Blocks marketing email. |
| Campaigns | Draft [automations](/docs/workflows/automations), with their emails, snippets, layouts, and images |
| Dynamic segments that a campaign uses | Realtime cohorts, when every rule has an exact match |
| Push device tokens | Devices on a PostHog push channel |

Most segments, transactional messages, newsletters, forms, collections, and delivery history stay in Customer.io. So do people's profiles: a contacts import is rolling out.

## 1. Set up sending

[Set up your domain](/docs/workflows/domain), and add a sender for each from-address your Customer.io emails use. The automation import matches each email to the sender with the same address.

## 2. Import opt-outs and suppressions

Do this first. It creates the categories that imported automations use.

1. In Customer.io, create an **App API key** under **Settings** > **Account Settings** > **API Credentials**.
2. In [Workflows](https://app.posthog.com/workflows/opt-outs), go to **Messaging** > **Opt-outs** and click **Import from another tool**, or **Import from Customer.io** if it's the only provider listed. Pick **Customer.io**, paste the key, and click **Start import**. This imports subscription topics, suppressed addresses, and global unsubscribes. PostHog keeps the key, so you can import again later.
3. Customer.io's API doesn't share per-topic preferences, so export them as a CSV. On Customer.io's **People** page, filter on `cio_subscription_preferences` **exists**, and export `cio_subscription_preferences` and `email`. Upload the CSV in step 2 of the same window.

While you run both tools, keep opt-outs in sync both ways. Steps 3 and 4 of the same window set this up:

- **Customer.io to PostHog:** in Customer.io, go to **Integrations** > **Add integration** > **Reporting webhook**, and paste the URL that PostHog gives you. Then paste the webhook's signing secret in PostHog.
- **PostHog to Customer.io:** enter your Customer.io **Region**, **Site ID**, and **Track API key**. Only categories imported from Customer.io sync back.

## 3. Import automations

On the [Workflows](https://app.posthog.com/workflows) tab, click **Import from another tool**, then **Automations, as draft workflows**. Ask your agent with the Customer.io and PostHog MCPs connected, or upload JSON files exported with the Customer.io CLI.

The import shows a preview first and saves nothing. Each draft gets notes:

- **Needs your input before you enable it:** a setting only you can give, such as a sender or a branch condition.
- **Works differently in PostHog:** check it. For example, a wait longer than 30 days becomes 30 days.
- **Left out:** rebuild it another way, such as an SMS step.

Importing a campaign again replaces its draft, and discards any edits you made to that draft. An automation you already turned on never changes.

## 4. Move push devices

Devices reach PostHog when your app registers them with the PostHog SDK, or when you [import your device tokens](/docs/workflows/push/import-device-tokens). Ask your agent to "import our Customer.io push tokens" to do it in batches.

## 5. Test and turn on

Open each draft, handle its notes, and send a test. Turn on the PostHog automation as you turn off the Customer.io campaign, so nobody gets the same email twice.

Right before you stop sending from Customer.io, run the opt-out import again and upload a new CSV, so late unsubscribes come over.

See [switch over safely](/docs/workflows/migrate#switch-over-safely) for the full checklist.
