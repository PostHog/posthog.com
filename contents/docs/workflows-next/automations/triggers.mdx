## Trigger types

**People**

| Trigger | Starts when |
| --- | --- |
| **Event** | Someone does something in your product, such as `signed_up`. |
| **Batch** | You click **Trigger**, or on a schedule. It runs once for each person in an audience you define. |
| **Survey response** | Someone answers a [survey](/docs/surveys). |
| **Cohort membership** | Someone joins or leaves a [cohort](/docs/data/cohorts). Rolling out. |

**Systems and schedules**

| Trigger | Starts when |
| --- | --- |
| **Schedule** | A time you set, once or on repeat. It runs with no person or event. Use **Batch** to reach people on a schedule. |
| **Webhook** | Your own system sends a request to the automation's URL. |
| **Manual** | You click **Trigger** in the editor. |
| **Tracking pixel** | Something loads the automation's 1x1 image, such as a web page or an email. |

**Tools you already use**

| Trigger | Starts when |
| --- | --- |
| **Slack message posted** | Someone posts in a Slack channel that PostHog is in. See [Slack](/docs/workflows-next/automations/slack-sms-webhooks#slack). |
| **GitHub activity** | Something happens on a GitHub repository. |
| **Support** | A [support](/docs/support/workflows) ticket is created, changes status, is assigned, or gets a message or a private note. Each is its own trigger, such as **New ticket created**. |
| **Account tag, property, or relationship changed** | An account changes. Rolling out. |
| **Data warehouse row synced** | A row is synced into a [data warehouse](/docs/data-warehouse) table. Rolling out. |
| **Materialized view row updated** | A materialized view adds or updates a row. Rolling out. |

Triggers that are rolling out show only in projects that have them.

## Event triggers

Add one or more events or actions. Under **Additional filters**, add conditions that apply to all of them, such as a person property. Turn on **Filter out internal and test users** to skip your own team.

Below the filters, the trigger shows how many events matched in the last 7 days, so you can see how often it will fire.

## Webhook triggers

Save the automation, and the trigger shows its **Webhook URL**. Send it a request with any JSON payload. In the trigger's settings, use `request.body` and `request.headers` to fill in the event and person for the run.

The request only starts the run. It doesn't record an event in PostHog. To record one, add a **Capture event** step.

To stop a retried request from starting a second run, send an `Idempotency-Key` header:

```bash
curl -X POST "<your-webhook-url>" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: order-1042" \
  -d '{"order_id": "1042"}'
```

| Request | Response |
| --- | --- |
| First request with a key, or no key | `201` with `{"status": "queued"}`. The run starts. |
| Same key again within 4 days | `200` with `{"status": "duplicate"}`. No run starts. |
| Key longer than 255 characters | `400`. No run starts. |

Each key applies to one automation. The same key on two automations starts a run on each.

## How often one person can enter

Event and cohort membership triggers have a **Frequency** setting:

| Option | What it does |
| --- | --- |
| **Every time the trigger fires** | Each event starts a new run. This is the default. |
| **One time per period** | A person enters once, then not again until the period ends. Pick a period from 5 minutes to 365 days, or **ever**. |
| **Once per calendar day** | A person enters at most once each day. |

Use **ever** for a welcome series. Use a short period when the same event can arrive twice, such as from a server retry.

Account triggers limit entry per account instead of per person.

Frequency is not the same as the [frequency cap](/docs/workflows-next/email/frequency-cap#frequency-cap-or-trigger-frequency), which limits marketing messages across all automations and broadcasts.

## Conversion goal and exit

Event triggers have a **Conversion goal**. A person converts when they meet all the conditions you set:

- **Property changes:** a person property, such as `plan` is `growth`.
- **Events:** an event, such as `subscription_started`.
- **Cohort membership:** they join or leave a cohort. Rolling out.

A person counts as converted only within the **Conversion window**, which starts when they enter. The default is 90 days. Each conversion is recorded as a `$workflows_conversion` event, which you can use in insights and cohorts. This event counts toward your event usage.

Event and cohort membership triggers also have an **Exit condition**:

- **Exit only once workflow reaches the end**. This is the default.
- **Exit when trigger filters no longer match**. On a cohort membership trigger, this is when the person leaves or rejoins the cohort.
- **Exit when conversion goal is met**.
- **Exit when trigger filters no longer match, or when conversion goal is met**.

## Limit the sending rate

When the automation has an email step, the trigger also has **Email sending rate limit**. Turn on **Limit sending rate**, and set the most emails to send per minute or per hour. This spreads a burst of sends over time.
