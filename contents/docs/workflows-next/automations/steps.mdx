After the trigger, add steps to send, wait, branch, and act. Click **+** on the canvas to open the step list.

<!-- shot: automation-add-step -->

## Send

| Step | What it does |
| --- | --- |
| **Email** | Sends an email, written in the [email editor](/docs/workflows-next/email-editor). |
| **Push** | Sends a push notification to the person's devices. |
| **SMS** | Sends a text message. |
| **Slack** | Posts a message to your team's Slack channel. |
| **Webhook** | Calls your own system. |
| **Destinations** | Sends to any of PostHog's [destinations](/docs/cdp/destinations), such as a CRM. |

Email steps have their own settings:

- **Track opens and link clicks:** on by default. Turn it off for emails where tracking isn't wanted.
- **Skip the frequency cap:** for emails people need on time, such as a welcome email. Opt-outs still apply.
- **Message category:** so people can opt out of this kind of email. See [sending rules](/docs/workflows-next/sending-rules#opt-outs).

## Wait

| Step | What it does |
| --- | --- |
| **Delay** | Waits a set time, such as 2 days. |
| **Time window** | Waits for a time window, such as weekdays from 9 to 5, in a time zone you pick or the person's own. |
| **Wait until** | Waits until the person does an event or matches a condition, up to a time limit. It has one exit for a match, and one for the time limit. |

A **Wait until** step only resumes for events from the person in that run, and its filters use fixed values. It can't match an event to a property of the trigger, such as the same `order_id`.

## Branch

| Step | What it does |
| --- | --- |
| **Conditional branch** | Splits people by person properties, event properties, or variables. Each condition gets its own path, and everyone else takes the last one. |
| **Cohort branch** | Splits people by whether they're in a cohort. |
| **Random branch** | Splits people at random, such as 50/50, to test two versions. |

<!-- shot: automation-branch -->

## Act in PostHog

| Step | What it does |
| --- | --- |
| **Capture event** | Records an event on the person, to chain automations or measure them in insights. |
| **Update person property** | Sets a person property, such as `onboarding_stage`. |
| **Set group property** | Sets a property on the person's group. |
| **Set variable** | Saves a value for later steps. |
| **Add to static cohort** | Adds the person to a cohort. |
| **Opt out of messages** | Opts the person out of a message category. |

Some steps are still rolling out, so your project might not have them all yet.

## AI

Classify a message, start an AI task, or have Replay Vision watch the person's session, then branch on the answer. See [AI steps](/docs/workflows-next/automations/ai-steps).

## Use results in later steps

A step's result can be saved as a variable, such as the ID a webhook returns. Later steps use it as `{{ variables.ticket_id }}`, in an email, a branch condition, or another webhook.
