AI steps let an automation look at something and decide, such as what a support message is about, or whether a new signup struggled. The automation waits for the answer, then branches on it.

| Step | What it does |
| --- | --- |
| **Classify with AI** | Sorts text, such as a ticket or a survey answer, into categories you pick, with a confidence score. |
| **Create AI task** | Starts an AI agent with your instructions, repositories, and connectors, then continues with its result. |
| **Replay Vision** | Watches the person's session recording and answers a question about it. |
| **Run scout** | Runs a scout, and continues with what it found. |

## AI tasks

The **Create AI task** step starts an agent with instructions you write. It can read your PostHog data, work in your GitHub repositories, and call your tools. The automation waits for it to finish, up to about 3 hours, then carries on with what it returned.

### Set it up

Write the **Instructions**, using the trigger's data, such as `Read ticket {event.properties.ticket_id} and decide who should handle it.` Then pick what the agent can use. All of these are optional:

| Field | What it does |
| --- | --- |
| **Repositories** | GitHub repositories it can work in, as `org/repo`. Up to 20. |
| **Connectors** | MCP servers it can call, from the ones shared with your project. |
| **Skills** | Skills from your skills store. |
| **PostHog access** | **Read only** by default. **Full access** lets it change things, such as person properties. |
| **Model** | The model and reasoning effort. |
| **Maximum parallel tasks** | Skips new runs while this many tasks are still going. 5 by default. |
| **Reply in the Slack thread** | On a Slack trigger, the agent replies in the thread that started it, and replies there go back to the agent. |

Each task also shows up in **Tasks**, where you can follow the agent's work.

### Get answers back

Tell the agent which answers you want, and it hands them back as fields that later steps can use:

1. On the step, open **Output variables** and add a mapping, such as the result path `output.verdict` into a variable called `verdict`.
2. Pick the variable's type: text, number, or true or false. The agent returns that type.
3. Ask for it in the instructions: "Set `verdict` to `bug`, `question`, or `feature_request`."

Later steps use it as `{{ variables.verdict }}`, such as a **Conditional branch** that posts bugs to Slack and replies to questions by email.

<!-- shot: automation-ai-task-branch -->

You can ask for up to 20 fields, and each text field holds up to 1,500 characters. If the agent doesn't fill one, the step still finishes, the variable stays empty, and the run's log warns you.

The step also returns:

| Result path | What it holds |
| --- | --- |
| `status` | `completed`, or `failed` or `cancelled` when it fails |
| `final_message` | The agent's last message |
| `pr_urls` | Pull requests it opened |
| `output.<name>` | The fields you asked for |

### When it fails

If the task fails, is cancelled, or runs out of time, the step's **On error** setting decides what's next. With **Continue**, later steps see `status` and `error_message`, so a branch can send the failure to Slack.

A workflow can start 100 tasks a day, and a project 500. An admin can raise both in **Settings** > **Workflows** > **AI task limits**.

See [AI tasks](/docs/workflows/ai-tasks) for more examples.

## Replay Vision

The **Replay Vision** step watches the session behind the trigger. Pick what you want back:

- **Ask a question:** a yes or no answer, such as "Did they get stuck setting up?"
- **Categorize:** which of your categories fit.
- **Score:** a number on a scale you set, such as how smooth onboarding was from 1 to 5.
- **Summarize:** a title, summary, and chapters.
- **Use a saved scanner:** the answer from a [scanner](/docs/replay-vision/creating-scanners) you already have.

By default it waits for the session to end, then watches the whole thing. Branch on the answer, so you only email the people who struggled.

## Tips

- **Ask one clear question.** "Did they upload a file?" beats "How did onboarding go?"
- **Branch on the answer.** An AI step is most useful when the next step depends on it.
- **Plan for no answer.** Every AI step can fail or come back empty, so give that path somewhere to go.
