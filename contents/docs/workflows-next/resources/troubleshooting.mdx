Start with the logs. Every run records each step it took, and why a step failed or was skipped.

## An email didn't arrive

1. **Find the send.** For a transactional email, check the [**Log**](/docs/workflows-next/transactional#see-each-send). For a broadcast, open **Not sent** on the broadcast. For an automation, open the run on **Invocations**.
2. **Read the reason.** A skipped or failed send says why. The common reasons are in the table below. For transactional statuses, see [status and troubleshooting](/docs/workflows-next/transactional/status).
3. **Was it delivered?** Then the recipient's mail server accepted it. Check the spam folder, and that your [domain's DNS records](/docs/workflows-next/domain#the-dns-records) are still in place.

| The log says | What to do |
| --- | --- |
| `Recipient has opted out` | They opted out of the email's category. See [opt-outs](/docs/workflows-next/email/opt-outs). |
| `on the suppression list` | Email to this address bounced or was reported as spam before. See [suppression list](/docs/workflows-next/email/suppression). |
| `recipient reached the frequency cap` | They already got the most marketing email you allow. See [frequency cap](/docs/workflows-next/email/frequency-cap). |
| `the recipient has no email address` | Add a filter so only people with an email address reach the step. |
| `is not a valid email address` or `has no reachable mail servers` | The address would hard bounce, so PostHog didn't send. Fix the address. |
| `email sending is paused for this workflow` | Too many bounces or spam reports from this automation. Clean up its audience, then resume it. |
| `email sending is suspended for this project` | See [deliverability](/docs/workflows-next/email/deliverability#when-something-goes-wrong). |

To find every bounce or spam report, click **Bounced** or **Marked as spam** on an automation's **Metrics** tab. It opens **Invocations**, filtered to those runs.

## Emails go to spam

- [Set up your domain](/docs/workflows-next/domain), so SPF and DKIM pass, and add the DMARC record.
- Use a real sender name and the same from address every time.
- Check your rates on **Reputation**, and read [deliverability](/docs/workflows-next/email/deliverability).

## No sender in the email step

Add one first. See [set up your domain](/docs/workflows-next/domain), or use the [test sender](/docs/workflows-next/email/test-sender) for now. Only project admins can add a sender.

## A variable is blank, or the email won't send

| Problem | Fix |
| --- | --- |
| A blank where a name should be | The person doesn't have the property. Add `\| default: 'there'`. |
| `TokenizationError` | Use single quotes inside `{{ }}`, not double quotes. |
| `expected "\|" before filter` | A property starts with `$`. Use `person.properties['$email']`. |
| A merge tag can't be read | Check the tag for typos. |
| A merge tag in a link is broken | Edit the link and type the tag again. |
| `Total variable size ... exceeds 5KB limit` | All of a run's variables together must fit in 5 KB. On the step that saves the variable, save only the field you need, not the whole response. |

See [Liquid and variables](/docs/workflows-next/email/liquid#when-it-goes-wrong) and [use results in later steps](/docs/workflows-next/automations/steps#use-results-in-later-steps).

## Nobody entered the automation

- **Is it on?** A draft doesn't run.
- **Does the event arrive?** Event names must match exactly. The trigger shows how many events matched in the last 7 days.
- **Did they enter before?** With **One time per period** set to **ever**, a person enters only once. See [how often one person can enter](/docs/workflows-next/automations/triggers#how-often-one-person-can-enter).

## An automation won't turn on

PostHog checks every step before it turns on, and lists what to fix, such as a missing trigger event or email address. You can save a draft that isn't finished.

## A batch run failed with nobody in it

PostHog couldn't find the audience, so nobody was added. Open the run on **Invocations** to read its log. Most often, the audience query timed out. PostHog tries 5 times before it gives up. Use fewer or simpler filters, or a smaller audience, and run it again. If it keeps failing, [contact support](https://app.posthog.com/#panel=support) with the automation and the time of the run.

## I need to stop it now

Cancel runs from **Invocations**. Turning an automation off only stops new people from entering. People already in it stop at their next step. See [stop runs](/docs/workflows-next/automations/debug#stop-runs).

## A send from code returned an error

The error `code` says why, and whether to retry. See [retries and errors](/docs/workflows-next/transactional/retries-and-errors).

## Push notifications aren't arriving

Open the run's logs:

- **No active device token found:** the device never registered. Check your [SDK setup](/docs/workflows-next/push#register-devices).
- **Rejected the device token as invalid:** the device registered with a different Firebase project or bundle ID. For APNs, check that the channel's **Environment** matches your app build.
- **Rejected the integration credentials:** check the Firebase service account key, or the APNs signing key, key ID, and team ID.
- **The device is no longer reachable:** the app was uninstalled or the token expired. PostHog removes the token.

See [push troubleshooting](/docs/workflows-next/push#troubleshooting).
