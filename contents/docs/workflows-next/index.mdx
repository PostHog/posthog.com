## Send email from your code

Create the email in PostHog, then send it with one call from the PostHog SDK that your server already runs:

<MultiLanguage selector="tabs">

```js file=Node.js
import { PostHog } from "posthog-node"

const posthog = new PostHog("<ph_project_token>", {
    host: "<ph_client_api_host>",
    secretKey: process.env.POSTHOG_PROJECT_SECRET_API_KEY,
})

await posthog.emails.send({
    to: "ada@example.com",
    templateId: "<template_id>",
    templateData: { first_name: "Ada" },
    distinctId: "user_123",
})
```

```python file=Python
import os
from posthog import Posthog

posthog = Posthog(
    "<ph_project_token>",
    host="<ph_client_api_host>",
    secret_key=os.environ["POSTHOG_PROJECT_SECRET_API_KEY"],
)

posthog.emails.send(
    to="ada@example.com",

    template_data={"first_name": "Ada"},
    distinct_id="user_123",
)
```

```go file=Go
import (
    "context"
    "os"

    "github.com/posthog/posthog-go/v2"
)

client, _ := posthog.NewWithConfig("<ph_project_token>", posthog.Config{
    Endpoint:  "<ph_client_api_host>",
    SecretKey: os.Getenv("POSTHOG_PROJECT_SECRET_API_KEY"),
})
defer client.Close()

client.Emails().Send(context.Background(), posthog.TemplateEmail{
    To:           "ada@example.com",
    TemplateID:   "<template_id>",
    TemplateData: map[string]interface{}{"first_name": "Ada"},
    DistinctID:   "user_123",
})
```

PostHog links the email to the person with the distinct ID, so its events land next to everything else that the person did. You can also send over the [API](/docs/workflows/transactional-emails/api), or keep your [React Email](/docs/workflows/transactional-emails/react-email) templates. See the [SDK docs](/docs/workflows/transactional-emails) to set up your key and template.

## Automations that improve themselves

An automation starts when someone does something, then waits, branches, and sends email or push notifications. It can also send a Slack message to your team. On self-driving automations, PostHog watches how each step performs and suggests changes, and you approve them. See the [automation builder](/docs/workflows/workflow-builder).

## Built to land in the inbox

- **No IP address to warm up.** Email goes out over shared Amazon SES IP addresses with a good reputation. See [sending reputation and allowance](/docs/workflows-next/channels/deliverability).
- **Transactional email never waits.** Password resets and receipts go out at once, even when your daily allowance for other email is used up.
- **Opt-out categories.** People can turn off your newsletter and still get their password reset. See [opt-outs and suppression](/docs/workflows/opt-outs).
- **Automatic suppression list.** A hard bounce or a spam complaint stops future sends to that address. No automation step can skip this check.
- **Frequency cap.** Set how many marketing messages one person can get in a window of days. See [frequency cap](/docs/workflows/frequency-cap).
