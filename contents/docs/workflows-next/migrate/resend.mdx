PostHog imports your Resend suppression list, unsubscribes, topics, contacts, templates, and automations in one background import.

> The Resend import is rolling out. If Resend isn't in the list, your project doesn't have it yet.

## What moves

| From Resend | In PostHog |
| --- | --- |
| Suppression list | [Suppression list](/docs/workflows-next/email/suppression). Hard bounces block all email. Spam complaints and addresses your team added block marketing email only, so they still get transactional email. Resend blocks all email to them. |
| Unsubscribed contacts | Opted out of all marketing email |
| Public topics, and who opted out of each | Marketing [categories](/docs/workflows-next/email/opt-outs) and opt-outs |
| Contacts and their properties | People, matched by email, or new people when nobody matches. A cohort of all contacts, and one for each segment. |
| Templates | Templates, keyed by their Resend alias |
| Automations | Draft automations |
| Domains | A list, so you know which to add |

API keys, webhooks, private topics, send history, and stats stay in Resend.

## Run the import

1. Create an API key at [resend.com/api-keys](https://resend.com/api-keys) with **Full access**. Resend has no read-only keys, so PostHog refuses a sending-only key. PostHog only reads, and deletes the key when the import ends.
2. In [Workflows](https://app.posthog.com/workflows/opt-outs), go to **Messaging** > **Opt-outs** and click **Import from another tool**.
3. Pick **Resend**, paste the key, pick what to import, and click **Start import**.

<!-- shot: resend-import: the Resend import, with the key field and the list of steps -->

Resend shares topic preferences and contact properties one contact at a time, so PostHog reads about 25,000 contacts an hour. If the import stops partway, start it again with the key, and it picks up where it left off.

The **Contacts** step needs **Suppression list**, **Unsubscribed contacts**, and **Topic preferences** in the same import, so nobody who left in Resend gets marketing email. Each person it creates or updates counts as an event on your bill.

## Switch your sending

- **Domains:** add each domain in PostHog and publish its new records. If Resend uses the `feedback` subdomain, pick another MAIL FROM subdomain in PostHog. The import says when this applies.
- **Templates:** Resend fills `FIRST_NAME` and other contact fields itself. PostHog doesn't, so your code passes them.
- **Code:** send each template by its key: the Resend alias, or `resend-<id>` when it has none. A send to a hard-bounced address fails with `recipient_suppressed`. Don't retry it.
- **Automations:** each draft lists the events your app must send to PostHog. Turn it on as you turn off the Resend one.

See [switch over safely](/docs/workflows-next/migrate#switch-over-safely) for the full checklist.
