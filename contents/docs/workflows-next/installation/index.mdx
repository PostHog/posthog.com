Install PostHog in up to three places. On your server, the SDK sends email. In your app, it captures the events and people that broadcasts and automations use. In your coding agent, the MCP builds and reports on your email for you. If you already use PostHog for product analytics, your app is set up.

## Send email from your server

Run the wizard from your server project. It installs the SDK, adds your API key, and adds the first send.

For another language, use the [API](/docs/workflows-next/installation/api). Send only from your server: a send needs your secret API key, so the browser and mobile SDKs can't send email.

## Capture events from your app

Install PostHog in your app or site. Its events can start an automation, such as a welcome email on `signed_up`. Its person properties choose who gets a broadcast. [Identify](/docs/product-analytics/identify) each user with their `email`, so PostHog knows where to send.

## Connect your agent

The PostHog MCP lets Claude Code, Cursor, Codex, and other agents write emails, build broadcasts and automations, move you off another provider, and tell you how each email did. Your agent saves its changes as drafts, and you publish them.
