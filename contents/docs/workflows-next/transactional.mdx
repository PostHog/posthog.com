A transactional email goes to one person when your code sends it, such as a password reset, a sign-in code, or a receipt. In the **Transactional** app in [PostHog](https://app.posthog.com/transactional), you create these emails, see every send, and see what each person did next.

New here? [Send your first one from code](/docs/workflows-next/installation).

## Create an email

Click **New transactional email**. Give it a name, pick a sender, and write it in the [email editor](/docs/workflows-next/email-editor). Under **Variables your code sends**, add the values your code passes with each send, such as `first_name`. Your code then sends the email by its template ID. See [templates and variables](/docs/workflows-next/transactional/templates).

Transactional emails ignore marketing opt-outs, so don't use them for marketing. After you publish an email, later edits save as a draft until you publish again.

For sign-in codes and reset links, turn on **Protect sensitive data** on the email's **API** tab. PostHog keeps no copy of what each email contained, and turns off link click tracking by default. See [sensitive data and tracking](/docs/workflows-next/transactional/sensitive-data).

## Emails your code writes

When your code renders the content itself, such as with [React Email](/docs/workflows-next/transactional/from-code#react-email), the email shows in the list under the key that your code sends. Link it to the file that sends it, and **Copy prompt for your agent** tells your coding agent which email to change and where. See [send content from your code](/docs/workflows-next/transactional/from-code).

## See each send

The **Log** tab lists every send from the last 30 days. Filter it by email, status, or bounce reason. Open a send to see:

- Its timeline: sent, delivered, opened, and clicked.
- The email the person got, unless the email protects sensitive data.
- What the person did in the 7 days before and after, with a link to the [session replay](/docs/session-replay).

Your code can also read a send's status. See [check an email's status](/docs/workflows-next/transactional/status).

## Metrics and conversions

The **Metrics** tab counts sends, deliveries, bounces, spam complaints, opens, and clicks, for each email or each sending domain. **What happened after** shows how many people did an event, such as `paid_bill`, after an email. Each email's **Impact** tab shows the funnel from send to click to that event. The Impact tab is rolling out, so your project might not have it yet.

See [transactional email metrics](/docs/workflows-next/metrics#transactional-emails). PostHog counts opens and clicks only for emails sent with [tracking](/docs/workflows-next/email/link-tracking) on.

## Webhooks

Delivery webhooks are rolling out, so your project might not have the **Webhooks** tab yet.

On the **Webhooks** tab, add an endpoint URL and pick the events: sent, delivered, bounced, marked as spam, failed, opened, and link clicked. PostHog posts them with types such as `email.delivered` and `email.clicked`, so a webhook handler that you wrote for another provider needs few changes. See [delivery webhooks](/docs/workflows-next/transactional/webhooks).

For every sending endpoint and field, see the [transactional email API reference](/docs/api/messaging).
