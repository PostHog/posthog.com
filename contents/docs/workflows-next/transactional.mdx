Transactional emails go to one person when your code says so: password resets, sign-in codes, receipts. Your code sends them. The **Transactional** tab in [Workflows](https://app.posthog.com/workflows) shows each send and what the person did next.

New here? [Send your first one from code](/docs/workflows-next/installation).

## Create an email

On the **Transactional** tab, create an email, write it in the [email editor](/docs/workflows-next/email-editor), and add the variables your code sends, such as `first_name`. Your code sends it by template ID.

Transactional emails skip marketing opt-outs, so don't use them for marketing. Once published, edits save as a draft until you publish again.

For sign-in codes and reset links, turn on **Protect sensitive data**. PostHog won't store the email's content, and records only the domain of a clicked link.

## Emails your code writes

If your code sends the content itself, such as a [React Email](/docs/workflows-next/transactional/from-code#react-email) template, the email shows up here under the key your code sends. Link it to the file that sends it. **Copy prompt for your agent** tells your coding agent which email to change and where.

## Log

The **Log** lists every send from the last 30 days. Filter by email, status, or bounce reason. Open a send to see:

- Its steps: queued, sent, delivered, opened, clicked.
- The email the person got.
- What the person did 7 days before and after, with a link to the [session replay](/docs/session-replay).

## Metrics

The **Metrics** tab counts sends, deliveries, opens, clicks, bounces, and spam complaints, by email or by sending domain.

## Conversions

Open an email and pick a conversion event, such as `subscription_started`. PostHog shows the funnel from send to click to conversion. Add a revenue property to see revenue.

Opens and clicks need [engagement events](/docs/workflows/engagement-events) turned on.

## Webhooks

On the **Webhooks** tab, add a URL and pick events: sent, delivered, bounced, marked as spam, failed, opened, link clicked. PostHog posts them as `email.delivered`, `email.clicked`, and so on, so a webhook handler from another provider needs few changes. See [delivery webhooks](/docs/workflows-next/transactional/webhooks).
