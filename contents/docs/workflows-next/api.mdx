Use the API to send email from any language, see what you sent, and manage templates, broadcasts, automations, and opt-outs from your own systems.

There are two kinds of endpoint:

- **Sending endpoints** run on your server with a project secret API key. They send email, upload attachments, read a send's status, and update a person's opt-outs.
- **Project endpoints** use a personal API key. They read your send logs, and manage templates, broadcasts, automations, opt-outs, and the suppression list.

## Before you start

1. **Set up your domain:** [verify the domain](/docs/workflows-next/domain) that you send from.
2. **Create a key:** create the key that the endpoint needs. See [authentication](#authentication).

## Send email

`POST /api/messaging/send/email/` sends one email from a template, or with content that you pass. The [server SDKs](/docs/workflows-next/installation) call it for you. The project path, `POST /api/projects/:project_id/messaging/send/email/`, also works.

```bash
curl -X POST "https://us.posthog.com/api/messaging/send/email/" \
  -H "Authorization: Bearer $POSTHOG_PROJECT_SECRET_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"to": "ada@example.com", "template_id": "<template_id>", "message_data": {"first_name": "Ada"}, "distinct_id": "user_123"}'
```

| Endpoint | What it does |
| --- | --- |
| `POST /api/messaging/send/email/` | Send one email. |
| `POST /api/messaging/send/email_batch/` | Send one email to up to 100 recipients, each with their own copy. |
| `POST /api/messaging/attachments/uploads/` | Get upload URLs for files to attach to an email. |
| `GET /api/messaging/emails/:message_id/` | Get the status of one send, such as delivered or bounced. |
| `POST /api/messaging/preferences/` | Update a person's opt-outs from your own preferences page. |

See [send email with the API](/docs/workflows-next/installation/api) for the full request, the errors, and how to retry safely.

## Authentication

Send the key as a bearer token.

- **Sending endpoints:** use a [project secret API key](/docs/api/project-secret-api-keys). Give it the `transactional_email:write` scope to send and upload attachments, `transactional_email:read` to read a send's status, and `messaging_preference:write` to update opt-outs. Keep the key on your server.
- **Project endpoints:** use a [personal API key](/docs/api/personal-api-keys) with `hog_flow:read` to read and `hog_flow:write` to make changes. The send logs and the suppression list also need `person:read`, because they show recipients. Counts of what people did after an email, and their activity around it, also need `query:read`.

Keep a `hog_flow:write` key as safe as a password. It can turn on automations that email real people.
