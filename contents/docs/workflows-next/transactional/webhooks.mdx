Get a signed request on your own endpoint when a transactional email is sent, delivered, opened, clicked, bounced, marked as spam, or fails. Each request carries the message ID the send returned, so you can match it to your own records.

> Delivery webhooks are rolling out. If there's no **Webhooks** tab, your project doesn't have them yet.

## Add a webhook

1. Turn on [engagement events](/docs/workflows-next/email/engagement-events) for your project. Webhooks are sent from them.
2. On the **Transactional** tab, open **Webhooks** and click **Add webhook**.
3. Enter an **Endpoint URL** that starts with `https://`.
4. Pick the **Transactional emails** to watch, or leave it empty for all of them, including ones you add later.
5. Pick the **Events**.
6. Copy the secret. You can't see it again.

Pause or delete a webhook from its menu.

## Events

| Event | `type` |
| --- | --- |
| Sent | `email.sent` |
| Delivered | `email.delivered` |
| Opened | `email.opened` |
| Link clicked | `email.clicked` |
| Bounced | `email.bounced` |
| Marked as spam | `email.complained` |
| Failed | `email.failed` |

The names and shape follow common email provider webhooks, so a handler you already have needs few changes.

## Payload

```json
{
  "type": "email.delivered",
  "created_at": "2026-11-26T09:15:02Z",
  "data": {
    "created_at": "2026-11-26T09:15:02Z",
    "email_id": "<message_id>",
    "template_id": "<template_id>",
    "template_key": null,
    "to": ["ada@example.com"],
    "subject": "Reset your password",
    "distinct_id": "user_123",
    "bounce": null,
    "click": null
  }
}
```

- `template_id` or `template_key` is set, matching what the send used. The other is `null`.
- `bounce` has `type` (`Permanent`, `Transient`, or `Undetermined`) and `subType` on a bounce.
- `click` has the `link` on a click.
- `subject` is left out for a [sensitive](/docs/workflows-next/transactional/sensitive-data) email.

Delivery webhooks cover transactional emails only, not broadcasts or automations.

## Verify the signature

Requests are signed with [Standard Webhooks](https://www.standardwebhooks.com), so any Standard Webhooks library can verify them. Each request has three headers:

- `webhook-id`: stays the same across retries, so use it to ignore duplicates.
- `webhook-timestamp`: Unix seconds.
- `webhook-signature`: `v1,` and a base64 HMAC-SHA256 of `{webhook-id}.{webhook-timestamp}.{body}`, keyed with your secret after you strip `whsec_` and base64-decode it.

```js
import { Webhook } from "standardwebhooks"

const wh = new Webhook(process.env.POSTHOG_WEBHOOK_SECRET)
const event = wh.verify(rawBody, request.headers) // throws if the signature is wrong
```

## Delivery

- Any response below `400` counts as received.
- PostHog retries `408`, `429`, and `5xx` responses, and network errors, a few times with backoff. Other `4xx` responses aren't retried.
- Respond fast, and do slow work after you respond. A slow endpoint times out after a few seconds.
- Events can arrive out of order. Use `created_at` to sort them.
