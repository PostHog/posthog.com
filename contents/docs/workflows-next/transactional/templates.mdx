Write a transactional email in PostHog, and your code sends it by its template ID with the values it needs. Anyone on your team can change the copy without a deploy.

To keep the content in your code instead, see [emails your code writes](/docs/workflows-next/transactional/from-code).

## Create a transactional email

1. Open [**Transactional**](https://app.posthog.com/transactional) and click **New transactional email**.
2. Name it. Turn on [**Protect sensitive data**](/docs/workflows-next/transactional/sensitive-data) if it carries sign-in codes or reset links.
3. Pick a verified sender. See [set up your domain](/docs/workflows-next/domain).
4. Write the subject and body in the [email editor](/docs/workflows-next/email-editor), with the variables your code sends, such as `{{ variables.reset_link }}`.
5. Copy the template ID and an example send from the **API** tab.

Transactional emails skip marketing opt-outs and the frequency cap, so use them only for emails a person needs. A transactional email can't go back to being a regular template.

## Use an existing template

Open the template on the **Templates** tab, go to its **API** tab, and click **Make transactional**. It needs a subject, a body, a verified sender, and no marketing category. If you still use it elsewhere, **Duplicate** it first and make the copy transactional.

With the API, call `POST /api/projects/:project_id/messaging_templates/:template_id/make_transactional/` with a [personal API key](/docs/api/personal-api-keys) that has the `transactional_email:write` scope.

## Variables

Everything the email shows comes from the send. The template can't read person properties, so pass all the data it needs in `message_data` (`templateData` or `template_data` in the SDKs):

```json
{
  "template_id": "<template_id>",
  "to": "ada@example.com",
  "distinct_id": "user_123",
  "message_data": { "first_name": "Ada", "reset_link": "https://example.com/reset?token=abc" }
}
```

Use the same names in the template:

```liquid
Hi {{ variables.first_name | default: 'there' }}, reset your password here: {{ variables.reset_link }}
```

Variables use [Liquid](https://shopify.github.io/liquid/). Add a default for anything that might be missing.

The send also needs a recipient, a distinct ID, and an idempotency key. See [send emails from code](/docs/workflows-next/transactional/send-from-code#what-a-send-needs).

## Edit, publish, and roll back

- **Drafts:** edits save as a draft. Sends use the live version until you click **Publish**, and **Discard draft** throws your edits away.
- **Versions:** each publish adds a version on the **Versions** tab.
- **Sender:** **Edit sender** changes the sender, display name, from address, or reply-to. The from address must be on the sender's verified domain.
- **Checks:** PostHog won't publish a change that would stop the email from sending, such as an empty subject.
