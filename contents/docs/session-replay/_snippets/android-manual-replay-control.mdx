> Requires PostHog Android SDK version >= [3.16.0](https://github.com/PostHog/posthog-android/releases/tag/3.16.0).

Setting `config.sessionReplay = false` in your PostHog configuration will prevent PostHog from automatically starting session recordings on SDK setup.

With `config.sessionReplay = true` (automatic mode), PostHog decides when to record: remote config, [trigger groups](/docs/session-replay/how-to-control-which-sessions-you-record#trigger-groups) (event triggers, a linked feature flag, sampling), and session rotation can all start a recording. In this mode, `stopSessionReplay()` only pauses the recording that's running right now. A later matched event trigger, a new session, or a remote config load can start recording again.

If you have your own logic for deciding who gets recorded (a feature flag you read yourself, consent state, a region check, an allow/deny list of screens), set `config.sessionReplay = false` instead. In this manual mode, PostHog doesn't start a recording on its own. Recording starts only when you call `startSessionReplay()` and carries on into new sessions. After `stopSessionReplay()`, it stays stopped through event triggers, new sessions, and remote config loads until you call `startSessionReplay()` again.

You can manually control when to start and stop session recordings using the following methods:

- `startSessionReplay(resumeCurrent: Boolean)`
  - Set **resumeCurrent** to `true` to resume a previous session recording (Default). 
  - Set **resumeCurrent** to `false` to start a new session recording. 
- `stopSessionReplay()` 
  - Stops/pauses the current session recording.

> **Note:** Calling these methods will have no effect if session recordings are disabled in your PostHog [Project Settings](https://app.posthog.com/project/settings).

#### Record or ignore specific screens

This example assumes `config.sessionReplay = false`, so your screen list decides what gets recorded, not PostHog's automatic triggers. You can combine these methods with your navigation to record only certain screens, or to pause recording on sensitive ones. For example, registering `ActivityLifecycleCallbacks`, stop recording when a sensitive activity resumes and resume otherwise:

```kotlin
val ignoredScreens = setOf("PaymentActivity", "SettingsActivity")

application.registerActivityLifecycleCallbacks(object : Application.ActivityLifecycleCallbacks {
    override fun onActivityResumed(activity: Activity) {
        if (activity::class.simpleName in ignoredScreens) {
            PostHog.stopSessionReplay()
        } else {
            PostHog.startSessionReplay()
        }
    }

    // Other lifecycle callbacks can be left empty
    override fun onActivityCreated(activity: Activity, savedInstanceState: Bundle?) {}
    override fun onActivityStarted(activity: Activity) {}
    override fun onActivityPaused(activity: Activity) {}
    override fun onActivityStopped(activity: Activity) {}
    override fun onActivitySaveInstanceState(activity: Activity, outState: Bundle) {}
    override fun onActivityDestroyed(activity: Activity) {}
})
```

Invert the check (`startSessionReplay` only for screens in an allowlist, `stopSessionReplay` otherwise) if you'd rather record just a specific set of screens.
