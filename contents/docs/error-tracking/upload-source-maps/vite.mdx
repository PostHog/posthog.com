## Manual setup

<Steps>

<Step title="Install the PostHog Rollup plugin" badge="required">

  Vite uses Rollup under the hood, so you can use the PostHog Rollup plugin to upload source maps:

  ```shell
  npm install @posthog/rollup-plugin
  ```

</Step>

<Step title="Add PostHog plugin to your Vite config" badge="required">

  Add the PostHog plugin to your `vite.config.js` file:

  ```js file=vite.config.js
  import { defineConfig, loadEnv } from 'vite'
  import posthog from '@posthog/rollup-plugin'

  export default defineConfig(({ mode }) => {
    // Vite loads .env only for your app's code. Load it for the config too.
    const env = loadEnv(mode, process.cwd(), '')
    return {
      plugins: [
        posthog({
          personalApiKey: env.POSTHOG_CLI_API_KEY ?? '', // Personal API Key
          projectId: env.POSTHOG_CLI_PROJECT_ID, // Project ID
          host: env.POSTHOG_CLI_HOST, // (optional) defaults to https://us.i.posthog.com
          sourcemaps: { // (optional)
            enabled: Boolean(env.POSTHOG_CLI_API_KEY && env.POSTHOG_CLI_PROJECT_ID), // Upload only when the credentials are set
            releaseName: 'my-application', // (optional) Release name
            releaseVersion: '1.0.0', // (optional) Release version
            deleteAfterUpload: true, // (optional) Delete sourcemaps after upload, defaults to true
          },
        }),
      ],
    }
  })
  ```

  Set the following environment variables:

  <div className="overflow-x-hidden">

  | Environment variable | Description |
  | --- | --- |
  | `POSTHOG_CLI_API_KEY` | [Personal API key](https://app.posthog.com/settings/user-api-keys#variables) with at least `write` access on `error tracking` |
  | `POSTHOG_CLI_PROJECT_ID` | Project ID you can find in your [project settings](https://app.posthog.com/settings/project#variables) |
  | `POSTHOG_CLI_HOST` | (optional) Your PostHog instance URL. Defaults to `https://us.i.posthog.com` |

  </div>

  The upload runs only when the key and project ID are set, so a build without them (a teammate's checkout, a pull request build) still passes. The `POSTHOG_CLI_*` names are the ones `posthog-cli` reads. Keep them apart from `POSTHOG_API_KEY` and `POSTHOG_HOST`, which PostHog's SDKs read at run time: posthog-laravel, for example, takes its project token from `POSTHOG_API_KEY`.

<CalloutBox icon="IconInfo" title="Using CI/CD?" type="action">

Add these environment variables to your CI/CD service's project settings to automatically upload source maps during production builds.

</CalloutBox>

</Step>

<Step checkpoint title="Verify source map upload and injection">

Confirm source maps were successfully uploaded:

1. Go to your [symbol sets in PostHog](https://app.posthog.com/error_tracking/configuration#selectedSetting=error-tracking-symbol-sets) and verify your latest upload appears.

2. Check your production JavaScript files in browser dev tools. They should include a source map reference comment:

```js
//# chunkId=0197e6db-9a73-7b91-9e80-4e1b7158db5c
```

</Step>

</Steps>
