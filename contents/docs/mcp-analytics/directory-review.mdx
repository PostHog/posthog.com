import CalloutBox from 'components/Docs/CalloutBox'

You can list an instrumented MCP server in the ChatGPT app directory or the Claude Connectors Directory. Directory reviewers want every tool argument to serve the tool itself, and by default the SDK adds three that exist for analytics: `context`, `llm_model`, and `conversation_id`. Turn those off before you submit. Your tool calls, errors, latency, clients, and users still show up in PostHog.

<CalloutBox icon="IconInfo" title="Last updated November 24, 2026" type="fyi">

Each directory makes the final call under its own policy. Read the [OpenAI app developer guidelines](https://developers.openai.com/apps-sdk/app-developer-guidelines/) and the [Claude Connectors Directory review criteria](https://claude.com/docs/connectors/building/review-criteria).

</CalloutBox>

## Configure the SDK before you submit

With this config, your server lists the same tools and returns the same results as it would without the SDK.

<MultiLanguage>

```ts file=TypeScript
instrument(server, posthog, {
  context: false,
  captureModel: false,
  enableConversationId: false,
})
```

```python file=Python
from posthog.mcp.types import MCPAnalyticsOptions

instrument(
    server,
    posthog,
    MCPAnalyticsOptions(
        context=False,
        capture_model=False,
        enable_conversation_id=False,
    ),
)
```

```go file=Go
posthogmcpsdk.Instrument(server, posthogmcp.New(client),
	posthogmcpsdk.WithContextParameter(false),
	posthogmcpsdk.WithCaptureModel(false),
	posthogmcpsdk.WithConversationID(false),
)
```

```ruby file=Ruby
PostHog::MCP.instrument(
  server, posthog,
  context: false,
  capture_model: false,
  enable_conversation_id: false
)
```

```rust file=Rust
let options = McpOptionsBuilder::default()
    .context(false)
    .capture_model(false)
    .conversation_id(false)
    .build()?;
let server = McpAnalytics::new(posthog.clone(), options).instrument(MyServer);
```

</MultiLanguage>

Keep the `get_more_tools` and `send_feedback` tools off. They're off by default, so leave out `reportMissing`, `collectFeedback`, `report_missing`, `collect_feedback`, `WithMissingCapabilityTool`, `missing_capability_tool`, and `feedback_tool`.

On a [custom dispatcher](/docs/mcp-analytics/installation/typescript#custom-dispatchers), `context` is an option of `prepareToolList`, not the constructor:

- TypeScript: `captureModel: false` and `enableConversationId: false` on `PostHogMCP`, and `{ context: false }` on `prepareToolList`.
- Python: `capture_model=False` and `enable_conversation_id=False` on `PostHogMCP`, and `context=False` on `prepare_tool_list`.
- Ruby: `capture_model: false` on `PostHog::MCP::Client.new`, and `context: false` on `prepare_tool_list`.

### ChatGPT: keep a short intent field

OpenAI's guidelines allow a brief, task-specific intent field, so a ChatGPT listing can keep `context` with a short prompt. Replace `context: false` with:

<MultiLanguage>

```ts file=TypeScript
context: { description: "A few words on the user's goal for this call. Leave out personal details." },
```

```python file=Python
context=MCPAnalyticsContextOptions(
    description="A few words on the user's goal for this call. Leave out personal details.",
),
```

```ruby file=Ruby
context: { description: "A few words on the user's goal for this call. Leave out personal details." },
```

```rust file=Rust
.context_description("A few words on the user's goal for this call. Leave out personal details.")
```

</MultiLanguage>

Go has a fixed prompt, so keep `context` off there. Claude listings should keep it off too.

## What you still get

- Every tool call, with its outcome, latency, and error type.
- The client, such as ChatGPT or Claude.
- Sessions, when the transport has a session ID. From TypeScript 1.7.0, ChatGPT calls also group by ChatGPT's own conversation ID.
- Users, from your [identify callback](/docs/mcp-analytics/identifying-users).
- Intent from an [intent fallback](/docs/mcp-analytics/intent#the-intent-fallback-callback), which runs on your server and builds intent from the tool name and arguments.

You lose the calling model, including the one Codex sends in request metadata. On a stateless server with no session ID, each call is its own session.

## Optional: send less tool data

Tool arguments, results, and error messages go to PostHog, never to the model, so they don't affect what reviewers see in your tools. They're the fastest way to debug a failed call. If you'd rather send only usage data, remove `$mcp_parameters`, `$mcp_response`, and `$mcp_error_message`:

- TypeScript, Python, and Ruby: the [before-send hook](/docs/mcp-analytics/privacy#3-your-before-send-hook-optional).
- Go: `posthogmcpsdk.WithCaptureParameters(false)` and `posthogmcpsdk.WithCaptureResponses(false)` on `Instrument`, and `posthogmcp.WithCaptureErrorMessages(false)` on `posthogmcp.New`.
- Rust: `.capture_parameters(false)` and `.capture_responses(false)`, and remove `$mcp_error_message` in `before_send`.

Failed calls also send an `$exception` event with the error message. [Turn off exception events](/docs/mcp-analytics/privacy#turn-off-exception-events) to stop it.

## Tell users what you collect

Both directories expect your privacy policy to say what your server records. Something like:

> We use PostHog to see how AI clients use this server: which tools they call, whether the calls succeed, and how long they take.

Mention tool arguments and results if you keep them.

## Recheck your tools after upgrading

An SDK upgrade can change the tool schemas your server lists, and both directories care about that. OpenAI reviews changed tools again. Anthropic asks you to report material changes. After an upgrade, diff your `tools/list` output against what you submitted.
