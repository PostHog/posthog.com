MCP Analytics captures how agents use your MCP server. Add the SDK for your server's language, and every tool call becomes a `$mcp_tool_call` event in PostHog.

## Install with the wizard

The wizard detects your server, installs the SDK, and adds the instrumentation. It supports TypeScript and Python servers, and [LLM coding agents](/blog/envoy-wizard-llm-agent) such as Cursor:

## What each SDK captures

Every SDK sends the same `$mcp_*` events with the same defaults, so your insights and dashboards work across languages. The SDKs differ in which optional features they implement:

| Feature | TypeScript | Python | Ruby |
| --- | --- | --- | --- |
| Tool calls and failures (`$mcp_tool_call`, `$exception`) | Yes | Yes | Yes |
| Tool listings, handshakes, and resource reads | Yes | Yes | Yes |
| [Agent intent](/docs/mcp-analytics/intent) (`context` argument) | Yes | Yes | Yes |
| Intent fallback callback | Yes | Yes | Yes |
| [Model capture](/docs/mcp-analytics/events#model-capture) | Yes | Yes | Yes |
| [Conversation IDs](/docs/mcp-analytics/conversation-id) | Yes | Yes | Yes |
| [Identifying users](/docs/mcp-analytics/identifying-users) | Yes | Yes | Yes |
| [Missing capabilities](/docs/mcp-analytics/missing-capability) (`get_more_tools`) | Yes | Yes | Yes |
| Agent feedback (`send_feedback`) | Yes | Yes | No |
| Stateless session token | Yes | Yes | Yes |
| Custom dispatchers | Yes | Yes | Yes |
| Wizard | Yes | Yes | No |
| Support | Beta | Beta | Experimental |

All SDKs remove credentials and binary content from captured payloads. See [Privacy](/docs/mcp-analytics/privacy).
