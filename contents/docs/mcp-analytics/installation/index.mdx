MCP Analytics captures how agents use your MCP server. Add the SDK for your server's language, and every tool call becomes a `$mcp_tool_call` event in PostHog.

## Capture WebMCP tool calls

If your web app registers tools through [WebMCP](https://webmachinelearning.github.io/webmcp/), `posthog-js` version 1.438.0 or later can capture each call for MCP Analytics.

Enable capture when you initialize PostHog:

```js-web
posthog.init("<ph_project_token>", {
    api_host: "https://us.i.posthog.com",
    capture_webmcp: true,
})
```

The SDK captures one `$mcp_tool_call` event when a tool call finishes or fails. The event includes the tool name, description, site hostname, duration, and error status. It also includes the current distinct ID and browser session. If Session Replay is active, the session ID connects the call to its replay.

The SDK does not capture your application's tool arguments, tool results, or detailed errors. Your normal consent, opt-out, `before_send`, batching, and delivery settings still apply.

By default, the SDK adds two required fields to compatible tool schemas:

- `context` contains the agent's reason for the call. Before capture, the SDK redacts credentials and sensitive URL values. It also redacts emails, IP addresses, payment cards, US Social Security numbers, and phone numbers.
- `llm_model` contains the model identifier that the agent reports.

The SDK limits `context` to 2,048 characters and `llm_model` to 256 characters. It omits blank values and an `unknown` model.

The SDK removes these fields before it calls your tool. It does not replace fields that your application defines. You can disable either field:

```js-web
posthog.init("<ph_project_token>", {
    capture_webmcp: {
        intent: true,
        model: false,
    },
})
```

Set `capture_webmcp` before your app registers its tools. The SDK only instruments tools that register after PostHog initializes. If you change the metadata settings, register the tools again.

## What each SDK captures

Every SDK sends the core events, `$mcp_tool_call` for each tool call and `$exception` for each failed call, so your insights and dashboards work across languages. The SDKs differ in which other events and features they implement:

| Feature | TypeScript | Python | Go | Ruby |
| --- | --- | --- | --- | --- |
| Tool calls and failures (`$mcp_tool_call`, `$exception`) | Yes | Yes | Yes | Yes |
| Tool listings, handshakes, and resource reads | Yes | Yes | No | Yes |
| Unknown-tool calls (`$mcp_unknown_tool`) | No | No | Yes | No |
| `input_required` rounds (`$mcp_input_required`) | No | No | Yes | No |
| [Agent intent](/docs/mcp-analytics/intent) (`context` argument) | Yes | Yes | Yes | Yes |
| Intent fallback callback | Yes | Yes | No | Yes |
| [Model capture](/docs/mcp-analytics/events#model-capture) | Yes | Yes | Yes | Yes |
| [Conversation IDs](/docs/mcp-analytics/conversation-id) | Yes | Yes | Yes | Yes |
| [Identifying users](/docs/mcp-analytics/identifying-users) | Yes | Yes | Yes | Yes |
| [Missing capabilities](/docs/mcp-analytics/missing-capability) (`get_more_tools`) | Yes | Yes | No | Yes |
| Stateless session token | Yes | Yes | No | Yes |
| Custom dispatchers | Yes | Yes | Yes | Yes |
| Wizard | Yes | Yes | No | No |
| Support | Beta | Beta | Beta | Experimental |

The Go SDK sends no `$identify` event.

All SDKs remove credentials and binary content from captured payloads. See [Privacy](/docs/mcp-analytics/privacy).
