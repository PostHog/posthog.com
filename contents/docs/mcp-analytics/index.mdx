MCP Analytics shows how AI agents use your MCP tools. It records tool calls, agent intent, reported models, failures, and requests for missing capabilities. It supports PostHog's hosted MCP server and servers that use the [MCP Analytics SDKs](/docs/mcp-analytics/installation).

Each tool invocation creates a `$mcp_tool_call` event in your standard events table. Use these events in MCP Analytics, [Product Analytics](/docs/product-analytics), or [SQL](/docs/data-warehouse/sql).

Want to see it at work? Our public [MCP leaderboard](/mcp/leaderboard) is MCP Analytics running on PostHog's own MCP server, built from its `$mcp_tool_call` events.

## Where its data comes from

MCP Analytics runs on the events your MCP server sends to PostHog. The [SDK](/docs/mcp-analytics/installation) emits them automatically, and PostHog's hosted MCP server is instrumented the same way.

<SurfaceCards columns={2}>

<SurfaceCard icon="IconBolt" color="orange" title="Tool calls" url="/docs/mcp-analytics/events" cta="Event reference">

The canonical <code>$mcp_tool_call</code> event: tool name, client, latency, errors, and session.

</SurfaceCard>

<SurfaceCard icon="IconList" color="blue" title="Lifecycle and discovery" url="/docs/mcp-analytics/events" cta="See all events">

Legacy initialize handshakes, <code>tools/list</code>, and per-request protocol versions power client and spec adoption breakdowns. The Go SDK sends neither <code>$mcp_initialize</code> nor <code>$mcp_tools_list</code>.

</SurfaceCard>

<SurfaceCard icon="IconAIText" color="purple" title="Agent intent" url="/docs/mcp-analytics/intent" cta="Capture intent">

What the agent said it was trying to do, clustered into themes across sessions.

</SurfaceCard>

Gaps agents report through the <code>get_more_tools</code> virtual tool when the right tool doesn't exist.
