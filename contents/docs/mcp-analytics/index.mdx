MCP Analytics shows how AI agents use your MCP tools. It records tool calls, agent intent, reported models, failures, and requests for missing capabilities. It supports PostHog's hosted MCP server and servers that use the [MCP Analytics SDKs](/docs/mcp-analytics/installation).

Each tool invocation creates a `$mcp_tool_call` event in your standard events table. Use these events in MCP Analytics, [Product Analytics](/docs/product-analytics), or [SQL](/docs/data-warehouse/sql). [Self-driving](/docs/self-driving) uses them to find problems and create reports. It can open a pull request for a server you own.

<CalloutBox icon="IconFlask" title="MCP Analytics is in beta" type="fyi">

The in-app MCP Analytics views are in beta. The `@posthog/mcp` SDK is published as a `0.x` release, so event names, properties, and tracing behavior may change before `1.0`. Pin a version and don't depend on it for production reporting yet.

</CalloutBox>

## How MCP Analytics works with Self-driving

[Self-driving](/docs/self-driving) uses your tool calls to find tools that need attention. A scout checks for high failure rates, repeated calls, slow responses, and large responses. It considers call volume and reach, then creates reports grouped by the team that owns the tools.

For your own server, the report includes a fix loop metric: the value that the proposed fix should improve. A coding agent then opens a pull request. For PostHog's hosted server, the report goes to a human without an attached repository. This path does not open a pull request.
