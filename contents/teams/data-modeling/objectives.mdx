## Q4 2026 objectives

### Objective 1: Semantic layer (owner: Sinan)

**Motivation:** The biggest bottleneck for the semantic layer is getting metrics and definitions into it. Users also can't see how much of their analysis it covers, so they don't know what to add or how far to trust it.

**What we'll ship:**
- A coverage mechanism that shows how often metrics are used, what they cover, and what's missing
- An open spec (OSI-like DSL) for defining the semantic layer
- A clear split between the semantic layer and the context layer, and what specialized agents on top of them look like
- Exploration: a standalone semantic layer, depending on demand
- Answer the question: how do we increase trust in data across all users?

### Objective 2: Self-driving warehouse (owner: Thiago)

**Motivation:** Most people don't know which views, materialized views, endpoints, or metrics they need. We can see what they query, so we should act as their data engineer and propose those changes to them.

**What we'll ship:**
- Recommendations on what to materialize, certify, and deprecate, and how to configure materializations
- Metric proposals based on what users actually query
- Query optimization and fixes for slow views and endpoints
- Integration with the Inbox
- Recommendations delivered through the version control workflow for data modeling

### Objective 3: Modeling on the managed warehouse (owner: Jovan)

**Motivation:** We need to move data modeling workloads off ClickHouse and onto the managed warehouse, so we can charge for modeling and give customers compute that scales with them.

**What we'll ship:**
- PostHog's own revenue dbt project running on data modeling
- All data models running on Trino
- Faster modeling jobs on Trino
- A defined transition from ClickHouse to Trino, including limits on ClickHouse and benchmarks against Snowflake and BigQuery
- Revenue tracking for modeling downstream of the managed warehouse

### Objective 4: Version control (owner: Jovan)

**Motivation:** dbt is ahead of us on trust. To compete, data teams need versioned models and tests they can review and roll back, the same way they work today.

**What we'll ship:**
- A git-backed, dbt-style data modeling workflow for agents and humans, including data quality checks
- A CLI to manage the project
- A way to take over your PostHog data modeling project and host it yourself
- Integration with Trino
- PostHog's own revenue dbt project managed this way

### Stretch: Python in the modeling lineage (owner: Sinan)

**What we'll ship:**
- Run a Python script as a step in a larger modeling lineage
