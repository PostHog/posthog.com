## Q4 2026 objectives

Last quarter we kept every product alive but moved none of them to a new level. This quarter we focus on fewer bets, pair on shared surfaces, and take what we have to GA – live, priced, and out of beta. We build MCP-first – if an agent can't use it, it isn't done – but keep the UI for users who still need it.

<details>
<summary>Take AEO, SEO, and agent experience to GA – <TeamMember name="Jordan Mryyan" photo /> and <TeamMember name="Lucas Ricoy" photo /></summary>

- Show the full crawled → cited → converted funnel per page and page group
- Detect agent sessions by default in `posthog-js`, so every customer sees how AI browsers (ChatGPT, Claude) use their site – agent vs. human traffic with zero config
- Get more agent data in: one-click log drains (Vercel, Cloudflare, Netlify) to capture non-JS AI crawlers
- Alert on crawl and citation spikes or cliffs, and on pages that agents read but that error or load slowly for them
- Close the loop from gap to content: emit signals that turn into concrete fixes (FAQ, `llms.txt`, structured data, robots rules)
- Price it and ship it to everyone

</details>

<details>
<summary>Make web analytics agent-native – <TeamMember name="Lucas Ricoy" photo /></summary>

If agents become the main way people use PostHog, web analytics has to work great without our UI:

- Let the wizard set up web analytics end to end, including a conversion goal
- Measure MCP answers to web, marketing, and AEO questions with evals, and fix what's weak
- Ship ready-made prompts: a web analytics dashboard as an artifact, and a scheduled agent task that watches your site and flags problems

</details>

<details>
<summary>Take ad performance to GA – <TeamMember name="Javier Bahamondes" photo /></summary>

Ad spend is business data, and PostHog should be the best place to correlate it with everything else customers send us:

- Attribute from start to finish: connect every source – paid ads, SEO, AEO, and agents – to revenue and new customers, using conversion goals and revenue events
- Give customers a clear view of their ad optimization data that they can use from their own agents through the MCP, including write tools to set up sources and conversion goals
- Self-driving: spot underperforming campaigns and suggest budget and setup changes that the customer's agent can apply
- Finish the pricing review and remove the beta label – customers and agencies are waiting on it before they commit

</details>

<details>
<summary>Cancel Vitally – <TeamMember name="Arthur Moreira de Deus" photo /></summary>

- Improve reliability and monitoring for Account creation, property syncs and data ingestion
- Built at least one self-driving loop: from signal triage to surfacing it for the user
