## Missions for 2026

<details>
<summary>We’ve established the AI Wizard as the fastest way to activate PostHog</summary>

This means agentic integration for multiple products across multiple frameworks. This also means support for additional “skills” like migrations and troubleshooting. Ultimately, the Wizard closes the gap between curiosity and real usage. It's an agent that delivers working PostHog solutions within a user’s codebase in minutes.

</details>

<details>
<summary>We’ve created a content-as-context platform that gives us a competitive edge</summary>

This means our content like docs, handbook, and blog posts play a central role in context engineering. By structuring our content into composable and reusable context, like skills, we can build agentic workflows that show how the entire product suite works together in practice. Success means developers see our content platform as both a well-organized knowledge base for readers and a context-rich ecosystem for agents. 

</details>

<details>
<summary>We’ve built systems that make product docs mostly self-serve</summary>

This means each product engineering team writes and maintains their own product docs at a strong baseline level of quality by using the templates, tools, and processes we’ve put in place. We partner with teams to review, improve, or overhaul their docs when needed. Success means keeping current product docs updated and launching several new products with docs, without slowing down.

</details>

<details>
<summary>Build an agent RAG system for updating and searching our docs</summary>

**Driver:** <TeamMember name="John Waters" photo /> <TeamMember name="Sarah Sanders" photo />

**Motivation:** The quality of our RAG search for docs is getting worse and so is the performance of our docs writer agent. AI agents now read our docs ~2:1 compared to carbon units (humans), so our docs need better tools and systems to stay correct and up to date for AI consumption.

**What we'll ship:** 
- An integration with our Business Knowledge product to index and search across our docs, repos, and other sources through a shared RAG system
- An agent writer system that creates docs PRs from multiple triggers: monorepo merges, support tickets, docs evals, scouts, Slack tags, feature flag rollouts, etc.
- Improve the agent writer's accuracy, consistency, and adherence to our style guide
- Replace the website AI chat with a new RAG-powered feature
- An approval / notification system for docs PRs generated by the agent writer

**We'll know we're successful when:** 
- Docs PRs merge at the highest velocity ever 
- Product teams and developer marketers trust that their product docs are up to date and accurate
- We can reuse the new agent writer to maintain the handbook, READMEs, changelog, and other technical content
- New RAG system provides useful answers from our docs in #at-posthog-anything and on the website
- We're providing great product feedback to the Conversations Teams

**Distribution ideas:**
- Write a blog post about how we used Business Knowledge to overhaul our docs search and maintenance 
systems
- Expose our docs RAG search through a public search-docs API endpoint for users and agents


**Synergy:** 
- <SmallTeam slug="conversations" /> is owning the headless CLI wizard that works with anyone's coding agent
- <SmallTeam slug="support" /> can update and fix the docs using our system

</details>

<details>
<summary>Measure and improve how well agents use PostHog docs </summary>

**Driver:** <TeamMember name="Edwin Lim" photo /> <TeamMember name="John Waters" photo /> <TeamMember name="Sarah Sanders" photo />

**Motivation:** We want to continually improve how people's agents use the PostHog platform according to our docs. To do that, we'll need a benchmark. We want to measure and evaluate how agents interpret, consume, and execute our product docs. 

**What we'll ship:** 
- An automated evals suite that tests models, efforts, tools, and prompts against our docs
- A qualitative or quantitative criteria for specific tasks like install and instrumentation
- Eval configs for each docs page 
- A trigger for the docs writer agent to make improvements based on eval results

**We'll know we're successful when:** 
- We can evaluate new model releases and understand how well each use PostHog with and without our docs
- Eval failures lead to docs improvements that increase agent success rates
- We have an official benchmark for the wizard and all PostHog installation / getting started tasks

**Distribution ideas:**
- Publish our eval results as a blog post or official benchmark for how well agents can use a product with only its public documentation as context.

**Synergy:**
- <SmallTeam slug="growth" /> is running broader evals of agents using PostHog through MCP, CLI, and SDKs. 

</details>

- We can effectively replace the context mill for the wizard
- We see more agent usage and traffic with our docs

**Distribution ideas:**
- We can use skills as an actionable CTA across blogs, newsletters, and landing pages
- Run a suite of AEO experiments on the docs with <TeamMember name="Natalia Amorim" photo />
