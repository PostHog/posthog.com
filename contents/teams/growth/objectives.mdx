## Q4 2026 objectives

These are the primary goals the team is prioritizing this quarter.

<details>
<summary>Solve onboarding and implementation for agents – <TeamMember name="Matt Brooker" photo /> <TeamMember name="Rafael Audibert" photo /></summary>

- **Rationale:** As an agent, it is hard to sign up, to implement PostHog correctly, and to know what to do with it.
- **Things we could do:** Make the wizard's headless mode production-ready, so it can be agent-driven. Expose our skills through a CLI and make agents aware of it. Simplify account provisioning for agents.
- **Note:** Rafael owns this goal while Matt is on parental leave.

</details>

<details>
<summary>Solve the PostHog experience for humans – <TeamMember name="Fernando Gomes" photo /></summary>

- **Rationale:** As a human, it is hard to know how to get set up and what you can do with PostHog.
- **Things we could do:** Make onboarding be user-centric and task-oriented, instead of setting up each PostHog tool one by one. Find out if the onboarding email flow is correct for the current stage of PostHog. Make it easier to offload onboarding and implementation to an agent. Use the wizard in the cloud for point implementations, such as adding a new product. Think through onboarding to a new product more carefully.

</details>

<details>
<summary>Solve inter-product growth for agents – <TeamMember name="Rafael Audibert" photo /></summary>

- **Rationale:** After a codebase uses one product, how do we make sure agents suggest and implement the other PostHog products that go with it?
- **Things we could do:** This goal is more abstract than the others, so we must try many things to see what sticks. Suggest new products and tools in tool call responses. Guide the user to new products with incremental skill surfacing. Write more docs.

</details>

### Side-quest

<details>
<summary>Solve intra-product growth for humans</summary>

- **Rationale:** After a user starts to use a product, how do we spread knowledge about that product so that the user uses it more?
- **Things we could do:** Each product team should own this for its own product, but not all of them do it well. Build a platform that makes it easy for them.

</details>
