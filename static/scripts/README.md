# PostHog bootstrap vendor

`posthog-bootstrap.js` is generated by the PostHog JavaScript SDK. Do not edit its runtime code here. The website serves it locally so the analytics host cannot delay Gatsby startup.

The bootstrap creates the early-call queue. The HTML template selects `data-sdk-version="1"`, so the full SDK loads asynchronously from `/static/1/array.js` and receives automatic same-major updates.

## Source and integrity

Source commit, artifact paths, SHA-256 values, and the vendor transformation are recorded in [`scripts/posthog-bootstrap.provenance.json`](../../scripts/posthog-bootstrap.provenance.json). Only the trailing source map reference was removed from the SDK output. The SDK license and notices are preserved in [`posthog-bootstrap.LICENSE.txt`](posthog-bootstrap.LICENSE.txt).

The test in `scripts/posthog-loader.test.cjs` checks the vendored artifact's hash. It also renders the real HTML template in Chromium and verifies application startup and early-call queuing while the analytics response is held. That test isolates browser parsing and queue creation; its inert SDK response does not test full SDK replay or production ingestion.

## Release dependency

This is a temporary vendor from [PostHog/posthog-js#5470](https://github.com/PostHog/posthog-js/pull/5470), not an artifact from a published SDK release. Do not merge the website integration before that SDK change is released.

After release, replace the vendor with the published `posthog-js/dist/loader-bootstrap.js`, apply the recorded transformation, and update the provenance. An SDK dependency and build-time copy can replace this manual vendor step. The bootstrap does not need to be recopied for each same-major SDK release; the major alias handles those runtime updates. Update the bootstrap if the website needs to queue a newly added SDK method.
